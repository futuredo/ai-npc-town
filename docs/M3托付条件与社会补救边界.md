# M3 托付条件与社会补救边界

## 052 补充：显式合作目标 v2

旧 v1 `KeepPrivate / Only(...)` 仍仅限制 confide，不保证必须求助，也不限制交付原件；不倒改 047 / 050 的成绩口径。v2 由调用方明确选择独行或指定梅伦 / 皮普：独行禁止 confide 与交出契约；梅伦只允许向梅伦托付 / 交件；皮普只允许向皮普托付，禁止交出原件。指定居民的当前 `ally` 与实际团聚共同决定完成，不能由模型自报或历史 Partial 代替。

UI 七项选择区分两协议，重新提出才冻结；重规划保持原契约，不自动换人 / 独行。确认对实际组合重新校验，执行前冻结步骤检查，已执行后果不回滚。这仍不是通用自由文本解析、所有社会副作用管控或全局保密。新增真实有限 22 次请求实际目标 7/9，皮普两失败保留；见[052 日志](开发日志/2026-11-10_052_合作意图正向目标与有限真实复验.md)与[逐局证据](合作意图v2有限验证.md)。

日期：2026-11-10。047 先补显式任务条件、保持 rules-6；后续 048 将社会规则明确升级为 `dragonsleep-rules-7`。不重写旧模型成绩，旧黄金原件保持不变，当前执行器不跨版本回放。

## 本轮实施：明确选择，不猜自然语言

计划面板新增“托付对象”：未限定、不向居民托付、只向梅伦托付、只向皮普托付。提出目标时冻结为 `DsPlanConstraints`；修改控件不影响已经提出的计划，必须重新提出目标才能换条件。

- 默认 `Unrestricted` 保留原行为与请求字节。文本中的“谁也别告诉”本身仍不是受证明的通用自然语言约束编译器；需要玩家同时作出明确选择。
- 条件版本为 `ds-plan-constraints-v1`。仅受限请求在冻结的计划上下文和本地运行记录中追加 `player_constraints`，后续每次修正、重规划都携带相同条件。
- 只限制本次计划中的 `act/confide`。它表示“不向未授权居民托付护送打算”，不代表保证秘密永不扩散，也不覆盖另行交谈、出示物品、居民传播已有消息等路径。
- “只向梅伦”是允许名单，不是必须邀请梅伦的承诺；没有合适条件时允许独行，绝不能默默换成皮普。必须获得某人帮助的正向目标仍待另行建模。
- 无效默认草稿不能确认；玩家改选的备选也独立检查。实际下一步在移动、跨夜、掷骰、耗时之前再次核对，冲突时停止剩余计划，无行动请求或提交。
- 执行前复制完整步骤及其集合，防止同步移动回调或异步居民回调把检查过的 `observe` 换成 `confide`。这不是宣称所有公开可变对象都已不可变。
- 离线规划器仅从玩家主动提交的条件生成允许的托付选项。真实提供方即使忽略它，确认和执行仍会拦截；本轮没有请求真实模型，不能报告模型遵守率提高。

旧的首案可执行率仍是规则指标，不因任务条件增加而改写。`DsPlanRun.MeetsObjective`、所选分支检查和受限运行记录分别表达任务是否允许、确认是否通过、实际执行了什么；不能拿 `PlanReport.Executable` 单独当“玩家全部条件已满足”。

## 低信任求助：rules-6 的历史缺口

旧 rules-6 要求“看过契约页且信任至少 0.5”，但任何缺口都说成“需要凭据”。同一契约反复 `show` 又可重复增加信任。低信任整局的主要阻塞发生在确认前，不是十局都真正走完了补救动作。

只读复核已有本机研究记录：

| 历史批次 | 事实 | 含义 |
| --- | --- | --- |
| `20261109-090749-162-recovery-live` | 10 个前置探针均已出示契约、信任约 0.35；9 次仍直接托付，唯一可执行回复重复出示 | 重复出示的成功不是有意义的社会协商 |
| `20261109-084724-487-plan-live` | 低信任 10 局，29 份草稿均未获确认，执行步骤 0 | 0/10 不能表述成执行后补救失败率 |
| `20261109-084445-399-plan-offline` | 对应 10 局离线基线同样未确认、执行步骤 0 | 不是仅换一个模型即可解决的问题 |

这些是旧实验的重新解释，不是本轮新增真实请求。原始结论继续见[闭环报告](归巢规划闭环复验_2026-11-09.md)。

### rules-7：交付原件核验

这是有意改变玩法语义，不是把失败降级为成功：

1. 区分“尚无凭据”和“看过凭据但不愿冒险”的公开拒绝；不给出 NPC 私有信任数值。
2. 复用 `give(pact_page, maren)` 转移原件控制权，记录公开保管核验状态，作为有代价的合作途径。玩家不再持有原件，不能同时向总管出示；所有提案仍要确认。
3. 同一契约对同一人的信任收益只给一次；不把重复 `show` 当刷数值补救，不降低原门槛冒充模型更可靠。
4. `give` 本身不泄露护送打算、不自动结盟；交付后还须实际 `confide`。资格同时核对精确原件、玩家交付记录和当前持有人，拿回原件撤销该保管资格和盟友标志。
5. 计划试运行不能读隐藏信任来预告居民的真实要求：有公开出示或交付记录时，只条件性假设合作，实际意愿由托付回执决定。实际 `Partial` 拒绝会写公开要求，再据此规划 `give → confide`；预测反馈不能冒充实际告知。
6. 这不是保证社会行动必定成功：交付仍沿用同地、持有与掷骰检查，消耗原行动时间；失败回执与剩余作废继续保留。

rules-6 三份黄金数据原路径、原字节保留；rules-7 黄金并列新增。当前运行时两种回放入口均拒绝 rules-6，不保留旧规则运行开关。逐项变化及覆盖迁移见[规则 7 证据对照](规则7黄金迁移与离线对照.md)。

## 047 条件保护的历史验收口径

离线负例证明显式条件能拦截，原黄金与研究统计证明默认兼容；Unity 验证控件、备选与修正链路，实际 Player 验证新布局没有破坏完整短局。它们不等于 M3 整体验收、真人可理解性或真实模型社会补救通过。

本轮实际为 211 项 .NET、32 项 PlayMode；新 macOS 包的默认短局、受限短局两分辨率与独立冒烟均通过。受限两次均经历 2 次真实失败与 2 次重规划后团聚、重开、第二次待确认提案，实际 `confide` 调用 0，详见 [047 日志](开发日志/2026-11-10_047_M3明确托付条件与执行复核.md)。无真实模型请求，旧社会补救成绩不变。

048 的规则升级验收另列批次，不能拿新规则的离线改善替换旧版真实模型成绩，也不能因此宣称自然语言通用否定条件、全局保密、必须求助某人或 M3 整体验收已经通过。

## 050 新增真实有限复验

用户明确授权后，新增 82 次真实规划请求，估算 USD 0.02112381。低信任三局确实从公开拒绝补交原件并再托付，最终团聚；但未传显式名单的自然语言“谁也别告诉”三局全实际托付了皮普。三个显式名单固定草稿的 confide 对象符合名单，OnlyPip 仍额外提出给梅伦原件；它不违反只约束 confide 的形式条件，却不能代表全部意图被满足。

这轮同时修复离线基线忽略 `people_here`，眼前观测优先于旧缺席码；另一常去处只是寻访候选，不是获知异地真值。详见[真实有限批报告](规则7真实模型有限批验证.md)，不把本节新结果倒写成 047 当时已经做过真实调用。
