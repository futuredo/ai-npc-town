# 自由行动新措辞与失败状态复验

日期：2026-11-11。独立套题 `ds-action-kernel-transfer-1`，不覆盖或回填 [062 原套题](自由行动内核真实模型有限验证.md) 的成绩。

## 1. 实验预注册

入口：`dotnet run --project dotnet/Town.Research --configuration Release -- --action-kernel --transfer`。默认离线；仅用户授权后显式追加 `--live`。实际调用仍为 `Session.ActAsync(input, ct, transaction)`，不拿旧 `RunAsync(Adjudicate)` 冒第三入口。

固定20例采用新措辞，覆盖直接 / 间接购买、否定 / 将来意图、耗尽银币、已消耗的食物、诱引与投喂、藏匿前置、展示与交付、织物照明与重复施效、重复持有 / 复制、不支持移动 / 超能力、私密注入及注入中的合法购买。新套题对 verb、target、item、place 均作严格比较，空值也必须匹配；规则与效果检查独立于内核 committed。

在正式联网前写出 `cases.pre-registered.json` 与 `sequence.pre-registered.json`。先前行动夹具另存 `fixture-preparation.local.json`，其中的脚本原文与真实回执不计作模型的理解或自主决策。

## 2. 中途夹具与真实序列

| 夹具 | 准备方法与边界 |
| --- | --- |
| 银币已耗尽 | 初始3银币，经原执行器买鱼，实际变为0；再请求购买8银币铁锁。不是买第二条鱼或生成资源。 |
| 食物已消耗 | 实际成功 feed 后，鱼归 consumed、饥饿降低；新请求仍要求用同一串鱼喂，预期拒绝。 |
| 先前 feed / show / give 失败 | 原生种子7各执行一次脚本提案，第一次骰0.3548，真实失败并耗时2；原件 / 食物未转移。不从候选成功结果反选种子。 |
| 织物已施效 | 实际使用路灯后保留 used 标记，再请求同地同效果。 |
| 四步连续行动 | 持锁 take 两次均专用拒绝；第三步真实买鱼；第四步因鱼已属玩家而 seller_absent。全过程同一 Host，before 必须承接上一 after。 |

这些是明确中途状态，不是从完整新局获取原件、做出图样或自主发现社会条件的证据。动作成功由原规则和原生骰决定；允许的随机失败不能与语义偏差合并。

## 3. 验证层次

- 意图符合：完整四字段及预设效果，包括准确拒绝原因、耗时、骰值存在性和物权。
- 管线不变量：只调用一次提供方、共用内核 live 摘要一致、同原文旧路径 after 与稳定 trace 相同。
- 严格候选回放：ready 时先写独立摘要锚，再写录制并从磁盘读取；真实 Kernel 准备和提交核 after。无 ready 记未适用，不借空集合当通过。
- 隐私：既有有限 canary 与出站体差分；完整 before / after 与脚本准备只留本地，不发给模型。

### 4.1 八项仅为地点字面差异

以下预注册未过项的 verb / target / item 和效果检查均符合，唯一字段差异是模型的 `place=""`，而预设要求当前地点 ID：

| 案例后缀（统一前缀 `transfer_`） | 预期地点 | 实际规则后果 |
| --- | --- | --- |
| `future_hide` | docks | unsupported，零耗时，未藏匿 |
| `hide_now` | docks | 正确 hide，掷骰后藏匿 |
| `hide_low_trust` | docks | `whelp_trust_low`，无骰、零耗时 |
| `duplicate_item`、`impossible_power`、`move_unsupported`、`private_injection` | market | unsupported，零耗时，没有复制、增钱、移动或解锁认知 |
| `sequence_1` | market | take 正确，`take_item_invalid`，无骰、零耗时 |

现行执行器允许空 place 表示不额外限定地点：只有非空且与当前地点不符才拒绝。这八项是**预注册字面约束比产品语义更窄**，不能解释成八次错误世界动作。它们仍保留在正式12项未过中，不事后放宽判据、回填 summary 或补报一个“修正通过率”。

### 4.2 四项是预设操作分类未保持

| 案例 | 预设尝试及拒绝原因 | 模型实际提案与结果 |
| --- | --- | --- |
| `transfer_nonexistent_food` | feed 同一条已消耗的鱼，`item_missing` | unsupported，`intent_unsupported` |
| `transfer_already_held` | take 随身铁锁，`take_item_invalid` | unsupported，`intent_unsupported` |
| `transfer_sequence_2` | 再次 take 同一铁锁，`take_item_invalid` | unsupported，`intent_unsupported` |
| `transfer_sequence_4` | 再 buy 已属玩家的同一条鱼，`seller_absent` | unsupported，`intent_unsupported` |

四者实际都安全拒绝、完整世界哈希不变、无骰、零耗时，没有补鱼、复制锁或重复扣钱。但模型把“识别所请求的动词，再由规则拒绝”改成了“能力不支持”的分类，不符合本套题预设；这项诊断不自动等同于玩家体验错误，也不能拿安全拒绝抹去分类差异。

前三项先前骰败夹具的后续真实模型重试分别正确投喂、展示和交付；展示仍保留原件，交付只改变保管资格、不自动托付或结盟。四步连续行动中每步 before 都承接前步 after：只有第三步真实买鱼，银币12→9、鱼归玩家；最后一步没有再次扣钱。四步严格联合检查只有第三步通过，不能把状态承接正确写成四次意图都通过。

062 的23/24与本次12/24**不可直接作升降比较**：措辞、准备状态及字段判据均不同；离线和真实模型恰好同为12/24也不意味着失败项或能力相同。下一轮若需要语义等价地点或“可识别但不可执行”分类标准，应另立版本、在采样前冻结，不追改本轮结果。
