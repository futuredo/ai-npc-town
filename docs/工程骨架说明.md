| 程序集 | 引用 | 引擎 | 说明 |

| `Town.Core` | 无 | `noEngineReferences: true` | 不允许出现 `UnityEngine` |

## 2. 核心思想：AI 只提案，规则执行

所有 AI 任务都走 `DragonsleepSession` 里**同一条七阶段管线**（`AiStage`）：

```text
Context ─→ Prompt ─→ Provider ─→ Parse ─→ Validate ─→ Adjudicate ─→ Commit
 冻结该角色   组装提示   离线规则或   解析为结构   DsExecutor.Prepare   裁决、掷骰    状态哈希未变才
 的感知视图   并限长     gpt-6-luna   化提案       在候选世界上校验     写入后果      提交，产生回执
```

- **只发送该角色能看到的信息。** 对话发送 `NpcPerceptionView`，其他任务发送 `TaskPerceptionView`，由 `ContextBuilder` 按角色裁剪。完整世界快照只留在本地，用于回放。
- **防止旧回复覆盖新世界。** 请求前记录世界状态哈希；回复到达时如果世界或玩家位置已经变了，就判为 `stale_context` 并丢弃提案。
- **改变世界只有一个入口：`DsExecutor.Commit`。** 模型台词不等于执行了动作；每次改动都有一份 `DsExecutionReceipt`。
- **每次调用都留下完整轨迹。** `AiTrace` 记录各阶段的状态、耗时、提示、原始输出、校验问题和回执，可导出为 JSONL；`DsReplay` 可按规则版本（当前 `dragonsleep-rules-6`）严格重放。
- **完整归巢任务按目标结束。** `DsPlanRun` 由调用方指定归巢要求，确认前检查计划覆盖目标，执行中根据实际团聚结束；重规划使用当前感知与最新拒绝反馈，明确区分未执行草稿的预测和当前事实。局部任务保留原有完成方式；玩家否定约束和社会补救仍有缺口，见 [M3 闭环复验](归巢规划闭环复验_2026-11-09.md)。

任务种类 `AiTaskKind`：

| 种类 | 对应机制 | 是否改变世界 |
| --- | --- | --- |
| `Dialogue` | N1 认知交互 + N2 社会影响 | 只改认知和关系，`action=none` |
| `Adjudicate` | N4 语义判定（自由行动） | 经规则裁决后提交 |
| `AgentPlan` | N5 居民自主行动 | 经规则裁决后提交 |
| `Direct` | N3 AI GM 导演 | 只看汇总状态和公共事件 |
| `Craft` | N6 造物 | 玩家确认图样后才提交 |
| `Plan` | 多步计划（M2） | 只提案；确认后由 `DsPlanRun` 逐步执行 |

提供方都实现 `IAiProvider`：

- `RuleProvider`：离线规则，是默认实现，也承担测试；
- `OpenAiDragonsleepProvider`：在线实现，用严格 Schema；
- `RoutingProvider`：按任务种类分流；
- 回放时用 `DsReplay` 内部的录制提供方。

## 3. 关键文件（`unity/Assets/Town.Core/Dragonsleep/`）

| 关注点 | 文件 |
| --- | --- |
| 世界状态 | `DsWorld.cs`（地点、角色、认知、规律、物件、雏龙、时刻）· `DsWorldSnapshot.cs`（快照与哈希） |
| 静态内容 | `DsContent.cs`（角色、地点、物件、初始认知）· `DsObjectives.cs` · `DsEndings.cs` |
| 规则 | `DsRules.cs`（全部动词的前置条件、难度、掷骰与后果）· `DsGuards.cs`（卫兵岗位与视线） |
| 管线 | `DragonsleepSession.cs`（入口）· `AiPipelineTypes.cs`（阶段、轨迹、提供方接口）· `DsExecutor.cs`（校验、裁决、提交、回执） |
| AI 输入 | `ContextBuilder.cs` · `NpcPerceptionView.cs` · `TaskPerceptionView.cs` |
| 提供方 | `RuleProvider.cs` · `RoutingProvider.cs` · `../../Town.OpenAI/OpenAiDragonsleepProvider.cs` |
| 计划 | `DsPlan.cs`（结构与三层校验）· `DsPlanRun.cs`（逐步执行、失败分类、重规划）· `BaselinePlanner.cs`（离线基线） |
| 回放与序列化 | `DsReplay.cs` · `MiniJson.cs` |
| 行为不变重构的证据 | `dotnet/Town.Core.Tests/DragonsleepGoldenTests.cs` · `dotnet/Town.Core.Tests/Golden/`（14 起点感知/提示/计划、整局轨迹与回执、既有 rules-6 严格回放；不自动更新哈希） |

Unity 侧入口是 `Town.Unity/Dragonsleep/DragonsleepGame.cs`。它创建 Session，把场景地点、角色和雏龙与 Core 对应起来，并把轨迹写到本地。界面在 `LoomLensHud.cs`（织言镜）。

## 4. 阅读顺序

1. **目标**：先读 v6 设计稿和归巢切片计划，知道要做什么。
2. **边界**：看几个 `.asmdef` 和 `dotnet/Town.Core/Town.Core.csproj`，理解同一份源码怎么在两边编译。
3. **世界**：`DsWorld.cs`，再看 `DsContent.cs`。
4. **主流程（最关键）**：`DragonsleepSession.RunAsync`，从一次输入跟到 `DsExecutor.Prepare` 和 `Commit`。
5. **AI 输入输出**：`AiPipelineTypes.cs`，然后 `ContextBuilder.cs`，然后 `RuleProvider.cs` 和 `OpenAiDragonsleepProvider.cs`。
6. **规则**：`DsRules.cs` 挑一个动词读，比如 `lure` 或 `rescue`，不必从头读完。
7. **计划层**：`DsPlan.cs`，再看 `DsPlanRun.cs`。
8. **表现层**：`DragonsleepGame.cs` 和 `LoomLensHud.cs`。
9. **用测试反查行为**：`dotnet/Town.Core.Tests/Dragonsleep*Tests.cs`。

`Town.Core` 下其他目录（Actions、Brain、Knowledge、Rules、Runtime、Moonlight 等）和 `Town.Unity` 根目录的 `TownGame` 等属于 v3 和月光切片时期的代码，第一次读可以跳过。

## 6. 已知技术债

现在的架构方向是对的，以下问题是原型阶段的代价。不阻塞 M3 和 M4，建议在里程碑交界时集中处理，不要边做实验边大改。

重构进展（2026-11-09）：阶段 0 已建立 `f3b445a` / `dragonsleep-rules-6` 的离线基线及黄金回归，详见 [032 日志](开发日志/2026-11-09_032_框架重构行为基线.md)。以下六项尚未标记解决；阶段 1 在原因码是否进入模型输入的边界暂停确认，不能以“增加一个字段”为由隐式改动提示内容。

1. **新旧两代代码并存。** v3 的 `TownRuntime` 和月光工坊仍在 Core 里编译和测试，龙眠镇实际只用 `Dragonsleep/`。应在确认不再需要后，归档或拆成单独程序集。
2. **数据是弱类型的。** 感知、提案、计划在内部以 `Dictionary<string, object>` 加自写的 `MiniJson` 传递，字段名靠字符串约定。可以先把计划和感知改成类型化记录，只在提供方边界转 JSON。
3. **逻辑依赖中文文案。** 例如 `BaselinePlanner` 用 `"梅伦修女不在这里"` 判断去哪找人，时刻也用 `"第3天·黄昏"` 字符串解析。应改为原因码和结构化时刻，文案只用于显示。
4. **大文件和超长行。** `DsRules.cs` 约 50KB，`ContextBuilder.cs`、`DsPlanRun.cs` 有超过 250 字符的行，`LoomLensHud.cs` 有 775 行。拆分建议：规则按动词拆文件，HUD 按面板拆。
5. **内容写在代码里。** 角色、地点、居民离线策略都写在 C# 中，`Town.Content` 目录是空的。扩内容前应先把内容改成数据驱动。
6. **测试开关放在领域对象上。** 试运行用的 `ForcedRoll`、`DryRun` 是 `DsWorld` 的字段。可以改为把掷骰源和执行模式作为参数注入规则。
