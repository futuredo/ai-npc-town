| 程序集 | 引用 | 引擎 | 说明 |

## 2. 核心思想：AI 只提案，规则执行

所有 AI 任务都走 `DragonsleepSession` 里**同一条七阶段管线**（`AiStage`）：

```text
Context ─→ Prompt ─→ Provider ─→ Parse ─→ Validate ─→ Adjudicate ─→ Commit
 冻结该角色   组装提示   离线规则或   解析为结构   DsExecutor.Prepare   裁决、掷骰    状态哈希未变才
 的感知视图   并限长     gpt-6-luna   化提案       在候选世界上校验     写入后果      提交，产生回执
```

- **只发送该角色能看到的信息。** 对话发送 `NpcPerceptionView`，其他任务发送 `TaskPerceptionView`，由 `ContextBuilder` 按角色裁剪。完整世界快照只留在本地，用于回放。
- **防止旧回复覆盖新世界。** 请求前记录世界状态哈希；回复到达时如果世界或玩家位置已经变了，就判为 `stale_context` 并丢弃提案。
- **AI 提案与移动等规则事务经 `DsExecutor.Commit` 提交。** 模型台词不等于执行动作，提交产生 `DsExecutionReceipt`。这是现行执行边界，不是世界对象的编译期绝对隔离：换时段仍由会话推进，`DsWorld` 仍有公开可变状态。
- **每次调用都留下完整轨迹。** `AiTrace` 记录各阶段的状态、耗时、提示、原始输出、校验问题和回执，可导出为 JSONL；`DsReplay` 可按规则版本（当前 `dragonsleep-rules-6`）严格重放。
- **完整归巢任务按目标结束。** `DsPlanRun` 由调用方指定归巢要求，确认前检查计划覆盖目标，执行中根据实际团聚结束；重规划使用当前感知与最新拒绝反馈，明确区分未执行草稿的预测和当前事实。局部任务保留原有完成方式；玩家否定约束和社会补救仍有缺口，见 [M3 闭环复验](归巢规划闭环复验_2026-11-09.md)。

任务种类 `AiTaskKind`：

| 种类 | 对应机制 | 是否改变世界 |
| --- | --- | --- |
| `Dialogue` | N1 认知交互 + N2 社会影响 | 只改认知和关系，`action=none` |
| `Adjudicate` | N4 语义判定（自由行动） | 经规则裁决后提交 |
| `AgentPlan` | N5 居民自主行动 | 经规则裁决后提交 |
| `Direct` | N3 AI GM 导演 | 只看汇总状态和公共事件 |
| `Craft` | N6 造物 | 玩家确认图样后才提交 |
| `Plan` | 多步计划（M2） | 只提案；确认后由 `DsPlanRun` 逐步执行 |

提供方都实现 `IAiProvider`：

- `RuleProvider`：离线规则，是默认实现，也承担测试；
- `OpenAiDragonsleepProvider`：在线实现，用严格 Schema；
- `RoutingProvider`：按任务种类分流；
- 回放时用 `DsReplay` 内部的录制提供方。

Unity 侧入口是 `Town.Unity/Dragonsleep/DragonsleepGame.cs`。它创建 Session，把场景地点、角色和雏龙与 Core 对应起来，并把轨迹写到本地。`DragonsleepGame.Plan.cs` 负责 `DsPlanRun` 的 UI 操作生命周期、取消迟到隔离、异常后终止及实际地点同步，不修改 Core 锁或规则。`LoomLensHud.cs` 保留脚本身份，partial 按 Dialogue、Lens、Journal、Style、ArtDirection、Plan 拆分；Plan 展示目标、取舍、步骤、回执和历史，禁止自动确认 / 执行。

`DragonsleepStageView.cs` 在主线程空闲时接收复制的只读表现帧，将实际护送、隐藏、抓捕、救援和团聚映射到实体；动画不持有世界引用，不写规则。卫兵岗位、铁笼和斗篷包裹是明确登记的灰盒，不是正式资产。终局地图传送被拒绝，失败结局不能通过移动实体伪装成已团聚。

本机包由 `Town.Editor/DragonsleepPlayerBuild.cs` 只构建既有主场景，输出严格 BuildReport 摘要；`DragonsleepPlayerSmoke.cs` 仅在显式参数下检查实际 Player 启动，不在普通运行中自动执行。Player 轨迹位于 `persistentDataPath/dragonsleep/traces/`，不是 `.app` 附近。命令与证据边界见 [本机试玩与验证](本机试玩与验证.md)。

`DragonsleepJourneyProbe.cs` 仅在显式 Player 参数或测试主动创建时运行，以实际 UI 导航按钮验证固定种子的完整离线短局、失败补救、结局及重开。它不替换提供方，不直接提交规则动作；正常启动不创建验证器。`ClearLens()` 重开时终止旧阶段揭示并重置常驻提示，避免旧局协程写回新局界面。

共享主题已从旧 Moonlight 目录保 GUID 移到 `Town.Unity/Shared/UiTheme/`；生成器引用新路径。Build Settings 唯一场景为 `Assets/LocalThirdParty/Dragonsleep/Dragonsleep_Town.unity`。该场景依赖本机商业资源，不随源码检出恢复。[SDK 抽离建议](AI框架SDK抽离建议.md) 是前期设计，后续收敛为上方单一 PieGame 内核验证，不是已发布 SDK，也未迁移现行玩法。

## 4. 阅读顺序

1. **目标**：先读 v6 设计稿和归巢切片计划，知道要做什么。
2. **边界**：看几个 `.asmdef` 和 `dotnet/Town.Core/Town.Core.csproj`，理解同一份源码怎么在两边编译。
3. **世界**：`DsWorld.cs`，再看 `DsContent.cs`。
4. **主流程（最关键）**：`DragonsleepSession.RunAsync`，从一次输入跟到 `DsExecutor.Prepare` 和 `Commit`。
5. **AI 输入输出**：`AiPipelineTypes.cs`，然后 `ContextBuilder.cs`，然后 `RuleProvider.cs` 和 `OpenAiDragonsleepProvider.cs`。
6. **规则**：从 `DsRules.Core.cs` 的公共前置进入，再在 `DsRules.Effects.cs` 挑一个动词读，比如 `lure` 或 `rescue`。
7. **计划层**：`DsPlan.cs`，再看 `DsPlanRun.cs`。
8. **表现层**：`DragonsleepGame.cs` 和 `LoomLensHud.cs`。
9. **用测试反查行为**：`dotnet/Town.Core.Tests/Dragonsleep*Tests.cs`。

`Town.Core` 现行领域实现集中在 `Dragonsleep/`；旧 Actions、Brain、Knowledge、Rules、Runtime、Moonlight 等目录及旧 `TownGame` 已删除，不应再按历史路径寻找当前入口。M4 计划交互证据见 [044 日志](开发日志/2026-11-09_044_M4归巢计划界面与异步收尾.md) 与 `DragonsleepPlanPresentationTests.cs`；实体规则映射证据见 [045 日志](开发日志/2026-11-09_045_M4实体投影与本机试玩构建.md) 与 `DragonsleepStagePresentationTests.cs`，灰盒和真人观感另验。

## 6. 已知技术债

现在的架构方向是对的，以下问题是原型阶段的代价。不阻塞 M3 和 M4，建议在里程碑交界时集中处理，不要边做实验边大改。

重构阶段 0–4 的历史行为基线与当时验证见 [037 收尾日志](开发日志/2026-11-09_037_旧代码盘点与框架重构收尾.md) 和 [032 日志](开发日志/2026-11-09_032_框架重构行为基线.md)。用户随后授权直接删除旧原型与专属验证，本轮不再要求恢复旧玩法或创建归档 tag。当前清理的实际验证单列 [043 日志](开发日志/2026-11-09_043_旧原型退役与工程整理.md)，不改写旧数字。

1. **旧代已退役，现行与实验仍需区分。** v3 / 月光不再编译；龙眠镇与独立 PieGame 验证不是一条已经接通的运行管线。旧存档仍留玩家目录，不跨格式读取，也不因删除代码而清除用户数据。
2. **数据是弱类型的（计划层已解决，其余保留）。** 计划构造 / 校验 / 执行统一 `DsPlan/Step/Choice/Option`，只在提供方和记录边界转 JSON；246 项 .NET、4 项 PlayMode、两组统计与黄金字节不变，见 [036 日志](开发日志/2026-11-09_036_计划内部类型化与字节兼容.md)。感知与其它机制暂不迁移，详见[感知视图类型化迁移建议](感知视图类型化迁移建议.md)。
3. **逻辑依赖中文文案（部分解决）。** `BaselinePlanner` 的人物缺席判断、预测隐私遮蔽已改本地原因码；时刻统一到 `DsMoment`，`until` 只在边界解析。旧公开新闻的搜城筛选及感知库存 / 状态描述仍依赖文本，需另行设计事件 / 感知迁移，不在本轮改模型输入协议。
4. **大文件和超长行（本轮范围已解决）。** 规则按主题 partial，HUD 按面板/样式 partial；当前 Core/Dragonsleep 与 Unity/Dragonsleep 的 C# 超过 160 字符行数为 0。旧代与其他目录未全仓格式化。236 项 .NET、4 项 PlayMode、两组统计与黄金不变，见 [034 日志](开发日志/2026-11-09_034_规则与界面机械拆分.md)。
5. **内容写在代码里（设计完成，未实施）。** 角色、地点、居民离线策略仍在 C# 中，`Town.Content` 目录为空。本轮只提交 [内容数据驱动建议](内容数据驱动建议.md)：稳定 ID / 排序 / 版本 / 指纹、合法视角、原子加载与新旧行为对照，不改变现有内容或提示。
6. **测试开关放在领域对象上（已解决）。** 世界已移除 `ForcedRoll`、`DryRun`，改为注入 `IDsRoll` 与执行模式。默认种子序列、候选计数和静态预览保持原样；243 项 .NET、4 项 PlayMode、两组统计与黄金不变，见 [035 日志](开发日志/2026-11-09_035_掷骰源与执行模式注入.md)。
