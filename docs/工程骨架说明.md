## 2. 核心思想：AI 只提案，规则执行

所有 AI 任务都走 `DragonsleepSession` 里**同一条七阶段管线**（`AiStage`）：

```text
Context ─→ Prompt ─→ Provider ─→ Parse ─→ Validate ─→ Adjudicate ─→ Commit
 冻结该角色   组装提示   离线规则或   解析为结构   DsExecutor.Prepare   裁决、掷骰    状态哈希未变才
 的感知视图   并限长     gpt-6-luna   化提案       在候选世界上校验     写入后果      提交，产生回执
```

- **只发送该角色能看到的信息。** 对话发送 `NpcPerceptionView`，其他任务发送 `TaskPerceptionView`，由 `ContextBuilder` 按角色裁剪。完整世界快照只留在本地，用于回放。
- **防止旧回复覆盖新世界。** 原路径保留Session的世界 / 代际 / `stale_context` 预检；061显式自由行动只由Kernel判定整状态、代际、去重和取消，不再重复宿主预检，原码另记 `kernel_code`。
- **候选裁决与提交权威分开。** 两条路径均复用 `DsExecutor.Prepare` 的隔离裁决；默认路径继续 `DsExecutor.Commit`，显式自由行动只经 Kernel.Commit → 受控单次写能力，同时写世界与spent，不再进执行器的去重表 / 比较。`DsWorld` 仍有公开可变状态，不构成编译期绝对隔离或所有写入统一迁移。
- **每次调用都留下完整轨迹。** `AiTrace` 记录各阶段的状态、耗时、提示、原始输出、校验问题和回执，可导出为 JSONL；`DsReplay` 仅在规则版本一致时严格重放（当前 `dragonsleep-rules-8`）。旧 rules-6/7 原件保留，但当前两种回放入口均拒绝跨版执行。
- **完整归巢任务按目标结束。** `DsPlanRun` 由调用方指定归巢要求，确认前检查计划覆盖目标，执行中根据实际团聚结束；重规划使用当前感知与最新拒绝反馈，明确区分未执行草稿的预测和当前事实。局部任务保留原有完成方式；显式 `DsPlanConstraints` 在确认、执行和重规划持续限制 `confide`，不声称解决通用自然语言否定条件或社会补救，见 [M3 条件边界](M3托付条件与社会补救边界.md)及[历史复验](归巢规划闭环复验_2026-11-09.md)。

任务种类 `AiTaskKind`：

| 种类 | 对应机制 | 是否改变世界 |
| --- | --- | --- |
| `Dialogue` | N1 认知交互 + N2 社会影响 | 只改认知和关系，`action=none` |
| `Adjudicate` | N4 语义判定（自由行动） | 经规则裁决后提交 |
| `AgentPlan` | N5 居民自主行动 | 经规则裁决后提交 |
| `Direct` | N3 AI GM 导演 | 只看汇总状态和公共事件 |
| `Craft` | N6 造物 | 玩家确认图样后才提交 |
| `Plan` | 多步计划（M2） | 只提案；确认后由 `DsPlanRun` 逐步执行 |

提供方都实现 `IAiProvider`：

- `RuleProvider`：离线规则，是默认实现，也承担测试；
- `OpenAiDragonsleepProvider`：在线实现，用严格 Schema；
- `RoutingProvider`：按任务种类分流；
- 回放时用 `DsReplay` 内部的录制提供方。

Unity 侧入口是 `Town.Unity/Dragonsleep/DragonsleepGame.cs`。它创建 Session，把场景地点、角色和雏龙与 Core 对应起来，并把轨迹写到本地。`DragonsleepGame.Plan.cs` 负责 `DsPlanRun` 的 UI 操作生命周期、取消迟到隔离、异常后终止及实际地点同步，不修改 Core 锁或规则。`LoomLensHud.cs` 保留脚本身份，partial 按 Dialogue、Lens、Journal、Style、ArtDirection、Plan 拆分；Plan 展示目标、取舍、步骤、回执和历史，禁止自动确认 / 执行。

Game 实际安装 `UnityOwnerThreadDispatcher`，通过只持纯托管接口的 `DsOwnerThreadDispatcher` 注入 Session；默认 CLI / .NET 不注入，保持同步宿主模式。Plan 异步编排使用同一个 owner，Session 实际冻结 / 提交边界复核 run 身份，防止排队旧操作作用新局；不回滚已提交后果。同步 Accept / Abandon / ToRecord 和 ConfirmCraft 仍需调用者在 owner 上执行，不能宣称任意线程安全或全游戏都已 Kernel 事务化。

Game 开启严格图样确认：HUD 使用与本次 trace 匹配的 `DsCraftProposal` 冻结描述和引用能力，旧按钮 / 句柄不能决定或关闭新案。已有 pending 拒绝后续 Craft，不调用提供方覆盖；有效领取决定时检查原请求 token，准备前取消不入槽、准备后取消惰性终结且零扣料耗时。正常 bool headless / 绑定路径的回执仍相同；新 cancelled 决定因 replay-v1 未记录 token 操作而拒绝严格回放，不伪装为 declined。

计划的托付下拉框只在重新提出目标时冻结。受限请求追加带版本的 `player_constraints`，默认未限定的请求 / 本地记录字节保持原样。执行当前步先复制完整步骤及集合，跨夜复核沿用同一快照，避免回调改写公开草稿替换已检查动作；不是整个世界或所有提案类型都已不可变。

v1 仍只管 confide 名单。新增 v2 显式独行 / 必须梅伦 / 必须皮普，同时管契约原件交付和实际合作完成：确认时冻结整份计划、对实际所选组合独立重验，结束以当前公开 ally 与实际团聚为准。模型摘要、预测合作和曾经结盟均不替代当前事实。`PlanIntentResearch.cs` 另立非新局夹具、逐动作 / 草稿审计、源码与加载程序集清单，不改原冻结集；见[合作意图有限验证](合作意图v2有限验证.md)。

rules-7 梅伦合作支持实际交付原件保管核验，`give` 转移持有但不自动结盟，仍须 `confide`；契约出示收益只给一次。计划试运行仅依据公开出示 / 保管记录条件性假设合作，不拿私有信任或远处持有人预测公开要求；真正拒绝后才记录公开要求并重规划。此升级有意改变规则与提示，不再沿用“rules-6 字节不变”的结论。

`BaselinePlanner` 现优先使用 `people_here` 这一当前合法观察，再用本地实际失败码与常去处模板。眼前缺席时另一常去处仅是寻访候选，不是异地位置事实；缺少观察字段仍保留旧回退。14 冻结提案与全部黄金字节保持原样，低信任离线组归巢 9/10→10/10。真实有限批与离线策略分开说明，见[050 日志](开发日志/2026-11-10_050_当前观察优先与真实规划有限复验.md)。

`DragonsleepStageView.cs` 在主线程空闲时接收复制的只读表现帧，将实际护送、隐藏、抓捕、救援和团聚映射到实体；动画不持有世界引用，不写规则。卫兵岗位、铁笼和斗篷包裹是明确登记的灰盒，不是正式资产。终局地图传送被拒绝，失败结局不能通过移动实体伪装成已团聚。

`DragonsleepJourneyProbe.cs` 仅在显式 Player 参数或测试主动创建时运行，以实际 UI 导航按钮验证固定种子的完整离线短局、失败补救、结局及重开。它不替换提供方，不直接提交规则动作；正常启动不创建验证器。`ClearLens()` 重开时终止旧阶段揭示并重置常驻提示，避免旧局协程写回新局界面。

`DragonsleepJourneyProbe.Social.cs` 是显式低信任夹具的社会补救前缀验证，不冒充完整新局获取原件或完整归巢；它仍通过默认离线提供方和实际确认 / 执行按钮验证代价、公开拒绝、再确认、交付与托付分别提交。

`DragonsleepJourneyProbe.Scene.cs` 只在显式 `--dragonsleep-journey-scene` 验证模式中点击地图去工坊再回集市，核 SDK 与宿主两次 committed 摘要相同、零耗时、零模型调用；普通运行不自动跑验证。它不替代完整计划的验收，也不声称计划内部移动已经进入 SDK。

`DragonsleepJourneyProbe.Cooperation.cs` 用明确非新局的合作夹具验证三种 v2 实际目标，不写盟友冒成功；`DragonsleepJourneyProbe.Day.cs` 从新局真实输入观察后点击两次日间按钮，验证非零 spent 与世界同次提交。所有验证模式仍须显式启动，普通 Player 不自动调用或退出。

`DragonsleepJourneyProbe.LateRescue.cs` 仅在显式末段验证中建立最后黄昏被捕 / 皮普已结盟夹具，使用正常种子与实际按钮救援到终局；不是从新局获得这些状态，也不保证其他随机种子成功。

`DragonsleepJourneyProbe.Craft.cs` 仅在显式造物验证中走实际图样准备 / 放弃 / 新案确认按钮，并直接调用授权 API 验证旧 handle / 裸 bool 被拒；直接负例不冒称 OS 鼠标触发旧闭包。普通运行不自动执行该验证。

`DragonsleepJourneyProbe.Action.cs` 从标准预算的新局实际发送12次观察，包含旧夜间流程，以内核 / 宿主摘要与提交计数核唯一写，并记录累积before UTF-8量；只有显式 `--dragonsleep-journey-action` 运行。私有ReplayFrame不放到公开trace或模型；本轮典型量测88596字节不是总内存。游戏等待自由行动时可实际点击重开，由同桥Reset拒绝旧ready，不能用取消替代代际；其它任务忙时重启限制保持。

共享主题已从旧 Moonlight 目录保 GUID 移到 `Town.Unity/Shared/UiTheme/`；生成器引用新路径。Build Settings 唯一场景为 `Assets/LocalThirdParty/Dragonsleep/Dragonsleep_Town.unity`。该场景依赖本机商业资源，不随源码检出恢复。[SDK 抽离建议](AI框架SDK抽离建议.md) 是前期设计，后续收敛为单一内核与桥，再限域接入场景移动；不是已发布 SDK 或全玩法迁移。
