## 阶段主目标

**把已验证的六种机制，组合成一段有因果、可失败、能补救的 AI 原生玩法。**

载体是“雏龙归巢”：玩家提出“把小烬安全送回母亲身边，避开卫兵”，AI 根据已知信息拆成可执行的步骤，玩家决定关键取舍，每一步都由规则执行并给出回执；失败后由 AI 重新规划，或由玩家改选方案。

本阶段完成原排期中的第 1、2 项，并把第 3 项的一部分（找谁帮忙）内嵌为关键取舍。第 4 项（GM 生成任务）、第 5 项（10–15 分钟完整试玩）在本切片之后进行。

## 阶段 A：Core 补齐护送与卫兵（离线）

1. **雏龙跟随与位置**：信任与恐惧满足条件时可“带上”雏龙；玩家移动时跟随移动，写入 `whelp.place`，出现在回执中。被发现、受惊或信任不足时可能逃回原处或原地躲藏。
2. **卫兵可查询状态**：按时段的岗位表（城门、集市、王城、码头等），黄昏换岗空档由现有 `law_guards_dusk` 驱动；`guard_sweep` 改为真实改变岗位。规则提供“某地某时是否被看见”的判定，被看见会触发上报与抓捕风险。
3. **团聚事实**：雏龙随玩家到达龙骨岗且母龙已降临时，写入 `WithMother`。`homecoming`/`new_pact` 改为依赖这个事实，信物和契约决定母龙态度和结局分支，不再单独决定归巢。
4. **铁笼补救路线**：雏龙被奥斯里克抓走后，应能潜入王城、出示契约或谈判救回，而不是直接失败。
5. 离线测试覆盖：跟随、走失、被看见、换岗空档、到达、团聚、铁笼救回；回放版本升到 `dragonsleep-rules-4`，rules-3 录制按版本拒绝，不越版本冒报。

## 阶段 B：多步计划与重新规划

1. **计划结构 `DsPlan`**：有序步骤，每步绑定一个现有动词与参数，写明前置条件（引用玩家已知事实）和预期效果；另有关键取舍点（例如走码头还是走城门、找梅伦还是找皮普帮忙）。模型只看玩家的 `TaskPerceptionView`，不得引用玩家不知道的卫兵位置。
2. **校验**：计划整体先在候选世界里做静态检查（动词、引用、前置条件是否可满足），不可行时返回原因而不是执行。
3. **逐步执行**：玩家确认取舍后，每一步单独经过现有执行器提交并产生回执；计划不能一次提交多步。
4. **失败分类与重规划**：
   - 前置条件不满足（执行前发现）→ 解释原因，提出替代步骤；
   - 掷骰失败（执行中）→ 写入后果，从新状态重新规划；
   - 世界已变（两步之间状态哈希过期，例如卫兵换岗、GM 搜城）→ 作废剩余步骤，重新规划。
   每次重规划都记录原因、旧计划、新计划，玩家可以接受、修改或放弃。
5. **离线基线规划器**：固定模板加前置条件搜索，与模型对照，证明 AI 带来的增量。
6. **社会取舍内嵌**：求助对象的选择进入居民认知；皮普可能透露给奥斯里克，梅伦需要契约才会冒险。同一起点下比较“告诉梅伦 / 告诉皮普 / 谁都不说”的后续差异。

## 验收标准（事先冻结）

| 指标 | 门槛（初定，可经评审调整） |
| --- | --- |
| 计划可执行率：首个计划通过静态校验 | 模型 ≥ 80%，并高于离线基线 |
| 失败后补救：三类失败各自触发重规划并能继续 | 每类至少 10 例，补救后计划可执行 ≥ 70% |
| 无效引用：计划引用玩家未知事实 | 0 次被提交；被拦截次数如实记录 |
| 回执一致：每步 UI 状态与执行回执一致 | 100%，叙述不先于回执 |
| 社会取舍：三种求助选择产生可解释的不同后续 | 每种至少 3 个种子，差异写明来源 |
| 结局可达：离线脚本在不同种子下走到归巢、新约、铁笼救回、未竟 | 每种至少一次 |
| 等待：每次规划端到端延迟 | 记录中位数与 P95，超过 5 秒必须有可取消的进度提示 |
| 真人小测 | 切片可玩后 1–2 人各 5 分钟，记录困惑、等待和重复操作 |

真实模型测试集在开工前写好并冻结（含新措辞），调参后的复验与冻结集结果分开报告，不合成一个总准确率。

## 不做与风险

- 不做任意代码、任意 3D 生成；计划步骤仍由现有动词组成，新增动词须同时补规则与测试。
- 多步计划会增加请求数和等待；如果延迟拖垮体验，先考虑一次规划多步、本地基线预填，再考虑更换模型（换模型需另行授权）。
- 卫兵加入视线后难度可能失衡，需要用多种子离线跑平衡，像第一天那样记录完成率与存活率。
- 结局条件改变后，旧录制会因规则版本不同而拒绝回放，这是预期行为。
