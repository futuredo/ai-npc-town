# 感知视图类型化迁移建议（仅设计，未实施）

## 本轮边界

计划内部已使用 `DsPlan/Step/Choice/Option`；离线规划器直接构造类型，提供方 / 记录边界才调用原 `ToRecord`，模型返回在执行器入口严格解析一次。`until` 的 JSON 值仍是原字符串。

**本轮不类型化感知，也不改提示词、Schema、感知字段、顺序或字符串值。** `NpcPerceptionView`、`TaskPerceptionView` 继续冻结 JSON。中文库存 / 状态描述及旧公开新闻筛选仍是遗留项，不伪称已消除。

## 不能直接换自动序列化的原因

- 键插入顺序、数组排序、空字符串 / 空数组和数字表示已经构成模型输入协议。
- 居民对话、居民计划、玩家行动、造物、GM、多步计划的可见范围不同，不能先取完整世界再靠属性过滤。
- “未知”“未观察”“当前不可见”不能被 nullable 默认值自行合并。
- 本地失败码不属于模型协议，不能顺便加入感知，尤其不能把静态试运行的异地真值送入重规划。

## A. 兼容现协议的内部类型化

1. 按任务分别定义类型，不创建包揽角色真值的万能 DTO；宿主先从合法视角构造，冻结后不持有世界引用。
2. 字段严格表达当前内容。库存等显示字符串暂留原串，结构化物品 / 状态属于下一次协议变更。
3. 写显式有序投影器，继续调用 `MiniJson.Write`；不依赖反射顺序、自动忽略 null / 默认值。
4. 保留公开捕获接口，逐任务替换内部构造；历史读取兼容必须有具体样本，不加猜测性兜底。

进入条件：另行授权、完成任务覆盖清单、隐私矩阵和固定字节样本。

验收：完整 JSON 与完整提示指纹逐字节相同；未知 / 异地 / 私有信念负例不泄漏；严格回放、离线统计、整局轨迹及 Unity 测试不变。当前 14 起点黄金主要覆盖计划、对话和居民计划，迁移前须补足行动、造物、GM 及重规划分支样本，不能说现有黄金已经证明全部协议。

## B. 单独升级感知协议

若要消除“库存含 food”“公开新闻含搜城”等逻辑，先定义结构化可见事实 / 公开事件及显示投影；旧世界数据只在导入边界适配。

这会改变模型收到的内容，必须另行批准、升感知 / 提示协议版本并建立新旧对照，不能只换黄金哈希后称行为不变。旧回放保留旧协议识别，不能严格兼容时明确报告，不悄悄重建为新提示。

## 未来 SDK 边界

SDK 可拥有冻结感知包、协议版本、提示指纹及引用验证契约；“谁知道什么、材料能否用、事件意味着什么”由宿主负责。`DsWorld`、人物 ID、中文显示模板和规则留在龙眠镇适配层。先用第二个规则不同的宿主验证，再决定稳定 SDK API。
