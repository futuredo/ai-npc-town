## 2. 本次到底验证了什么

研究套件为 `ds-plan-intent-v2`，约束为 `ds-plan-constraints-v2`，规则为 `dragonsleep-rules-7`。两批均采用 `PlanCases.Scenarios["pact_escort"]` 固定夹具，`is_fresh_game=false`：起于第 1 天正午、码头；小烬已经跟随且被斗篷遮盖，信任 0.6，玩家已持契约页并掌握相关线索。不是从寻找小烬、建立信任、取得契约开始的全新局。

每模式三个种子，Session 种子按 `(seed + 30) * 7919 + 13` 得到 `245502 / 253421 / 261340`。每 episode 至多 6 次 Plan、100 次循环；live 实际最大循环数 12。Plan 才可联网，行动步骤是结构化提案，夜间居民与 GM 使用离线规则提供方。

三种模式都要求实际归巢，但合作条件由研究调用方**显式传入** `DsPlanConstraints`，不是靠模型从任意自然语言猜出约束：

提供方仅接收冻结的玩家任务视角及必要输入、系统生成的重规划反馈；ID 白名单来自该视角。计划只是提案，确认本身不改世界，执行后逐步取实际回执。自动研究协议为：默认方案确认一次；确认拒绝则放弃，不另选对象；首案语义修正单独计次；提供方错误停止整个批次，无 HTTP 自动重试、无换模型兜底；失败或放弃后不额外推进终局。

`objective_achieved` 的报告口径是：运行状态 `completed`、实际 `Whelp.WithMother=true`、指定合作条件成立，且无实际禁用托付/原件交付行动。`required_ally=true` 在 solo 是“无指定帮手，条件自然满足”，**不等于真的结盟**。`actual_with_mother`、`final_dawn` 与结局标题分别报告，不用摘要声称、预演成功或“走完一段”替代实际团聚。

## 6. 失败、恢复与未恢复

### 梅伦：发生失败后仍然达成，不抹去中间失败

- `maren-seed-1`：live 首次 `show` 在 `S1-2` 掷骰失败，显示 0.15 < 难度 0.19；剩余旧步骤作废。第二次计划 `S1-3` 重新确认，实际出示与托付成功，最终完成。离线同种子用了三次计划，不能用离线的三次覆盖 live 的两次。
- `maren-seed-3`：live 的首次出示、第二次允许交付分别失败（显示 0.12 < 0.29、0.11 < 0.19）；第三份计划成功。最后仍保留 `last_reason_code=roll_failed` 是历史失败记录，最终状态与实际团聚依然成立，不能只看 last_reason 判整局失败。

### 皮普种子 1、3：结盟真实，归巢失败也真实

两局共同链路有逐条证据：

1. 实际托付回执写入 `ally:pip`（种子1 `S1-2`，种子3 `S1-3`）。
2. 夜间离线居民行动先让皮普到集市，再向总管转述 `b_plan_pip`：种子1 `S1-12`、种子3 `S1-13`，实际形成总管的计划认知。该流言不是玩家向未授权对象 `confide`，也不在本次玩家约束防护范围；三局皮普最后均 `osric_knew_plan=true`，连成功的种子2也如此。
3. 第3天黄昏移动到龙骨岗，`rule-events.jsonl` 的 `S1-R11` 记录加派卫兵与巡逻；望风使暴露概率从 0.25 降为 0.15，**不是免疫**。种子1注记掷骰显示 0.15、种子3显示 0.12，实际回执均写入 `whelp.captured_by=osric`、`following=false`、地点变王城。种子1注记保留两位小数，不能据此宣称原始浮点值恰等于阈值或发生比较错误。种子2显示 0.79，未被发现并完成。
4. 两失败样本都停留第3天黄昏，`actual_with_mother=false`、`final_dawn=false`；没有事后跨夜替它们补成成功。最后的 `plan_call_limit` 是研究有界停止原因，触发它之前的实际失败是巡逻捕获。
