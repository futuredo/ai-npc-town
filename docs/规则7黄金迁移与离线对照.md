### 2.2 两个回放入口都不能跨规则版本

`DsReplayFrame.VerifyAsync()` 是严格回归：重建提示必须匹配原指纹，执行后世界哈希、展示文本、失败码和裁决类型也必须匹配。`VerifyExecutionAsync()` 允许提示迭代、复用原始回复，但不是跨版本迁移器。

二者都先进入 `VerifyInternal` 的 `RulesVersion != DsExecutor.RulesVersion → false`。因此旧 14 帧保持 `dragonsleep-rules-6` 时，对当前 `dragonsleep-rules-7` 都应在版本门禁拒绝，不能篡改旧版本、快照或提示来制造成功。旧帧改错提示后仍为 false，也**不能单独隔离证明提示门禁**，因为版本已先拒绝；新 rules-7 录制的同版本负例才专门承担这项责任。

新录制的 14 帧均为 `dragonsleep-replay-v1` / rules-7 / 模拟响应。逐项解析看到：与对应旧首案的 `before` JSON 内容相同；每个新帧 `before == after`；响应 raw 字符串与旧首案相同，其 SHA-256 与新 `perceptions.json` 的 `proposal` 一致；提示指纹与新 `prompt` 一致。这是新旧内容关联，不是旧帧在新规则成功回放的证据。

## 5. 低信任 `perturb_precondition` 的逐局证据

### 5.1 先证明真的拒绝，再看是否真的补救

研究起点为 `pact_escort`、`option=maren`；`PlanResearch.cs` 把梅伦初始 Trust 设为 0.05，13 局首个计划调用的本地 `before.actors` 也都记录 0.05。这个私有数值用于本地审计，不是发送给规划者的条件。记录里的 `perturbed=false` 只表示没有运行中回调扰动，不代表低信任起点没有设置。

13 局均有实际 `confide maren` 步骤：`status=failed`、`failure=Precondition`，展示文本一致为：

> 按计划：请梅伦同行 梅伦摇头：“我认得这页纸，但看过不代表能冒险。把契约原件交我保管核验，我才肯以教会名义同行。”

这 13 个结果都有 `committed / applied=true` 回执，而不是仅有静态拒绝或没执行的草稿。步骤失败表示“未得到同行合作”，不表示这次公开提出条件的事务没有发生。源码 `DsRules.Social.Confide` 对此产生 Partial，并写公开请求；`DsPlanRun` 把实际 confide 的 Partial 归为 Precondition。

进一步逐局核对随后那次重规划调用：本地 `before.flags` 都已有 `requested:pact_custody:maren`、尚无 `ally:maren`，契约页 Holder 仍为 player；实际提示的 `public_cooperation_requests` 非空、`pact_custody=""`，没有 `trust_in_player` 字段。重规划的新计划都把梅伦分支从 `show` 换成 `give maren pact_page` 后再 `confide`；该 Precondition 重规划均 `new_plan_executable=true`、`decision=accepted`，对应请求 ID 也确实进入 `accepted_request_ids`。

这证明已记录的公开条件进入离线恢复链路，但**静态可执行和获确认不保证掷骰后交付成功**。

### 5.4 当前落盘格式无法单独证明什么

- `episodes.jsonl` 保存步骤 `failure/reason/presented` 和回执摘要，却没有实际 Action trace 的完整 `verdict`、`roll/difficulty`、稳定 `ReasonCode`、逐项 effect 路径与前后值。因此可直接核对“公开拒绝文本 + Precondition 步骤失败 + applied 回执”；**不能从这些行单独证明其序列化裁决就是 Partial 或稳定拒绝码就是 `confide_custody_required`**。这两项对应关系来自当前源码，不是假装在 episode 中发现了缺失字段。
- 成功 give 的步骤及回执证明该实际动作成功，展示也说明失去原件；但 episode 没有每步完整世界快照。若要求对每个成功局独立重验交付后的 `items.pact_page.holder=maren` 和 `flags.pact_custody:maren`，仅这份 episode 不足以证明，不能用 effect 数量替代逐项效果。当前 `DsRules.Effects` 明确先 Move 原件、再写保管标志，且不走普通礼物加信任分支；对应单元测试存在，但本次未运行。
- 原始 `Whelp.WithMother` 没有作为终局世界快照存入 episode；直接可见的是 `runs[].homecoming_achieved`。当前 `DsPlanRun.ToRecord()` 将该字段写为 `Session.World.Whelp.WithMother`，所以表中按这个已序列化的状态报告团聚，不仅凭结局文案猜测。独立重建最终世界、核对最终世界哈希仍缺 episode 级原件，本文不声称已经做到。
- `ally_maren` 顶层字段由研究脚本在计划循环结束、补跑世界到终局之前采样；不是完整终局快照。表中严格按这个采样点报告，不扩写成“所有终局时刻的盟友状态均核验”。
