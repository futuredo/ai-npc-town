# 分支与协作规范

> 2026-11-05 起改为**单人直接在 `main` 开发**。原先的 `develop` + 功能分支 + PR 流程已停用（`develop` 和旧功能分支暂时保留在远端，不再使用）。以后有协作者时再恢复分支和 PR 流程。

## 日常流程

```bash
git switch main
git pull --ff-only
# 完成修改后：检查 diff，运行与改动相关的验证
dotnet test dotnet/Town.sln --configuration Release
git add <本次修改的文件>
git commit -m "实现居民对话请求与执行反馈"
git push
```

- 提交信息使用中文，描述具体行为变化。
- 提交前必须本地跑通核心测试；涉及 Unity 场景或表现时，在开发日志里写明编辑器或 PlayMode 验证结果。
- 不对 `main` 强制推送，不重写已推送的提交。
- 需要试验性改动、可能整体放弃时，可以临时开一个本地分支，验证后合回 `main` 再推送；不需要开 PR。

## 验证与保护

- GitHub Actions 的 `core-tests` 在每次推送 `main` 时运行，也支持手动触发。失败时在 GitHub 上标红，**不会阻止推送**，看到失败要立即修。
- 检查复用 Unity 内的 `Town.Core` 源码，使用 .NET 8 运行 NUnit 测试；不覆盖 Unity 完整构建、场景渲染、寻路体验或模型服务。
- `main` 的远端保护只保留：禁止强推、禁止删除。不要求 PR，不要求状态检查。

## Unity 与本地数据

- 提交 `Assets` 及对应 `.meta`、`Packages` 和 `ProjectSettings`。
- 不提交 `Library`、`Temp`、`Logs`、构建产物和 .NET `bin/obj`。
- API Key 使用本地环境变量或被忽略的 `.env.local`，示例仅提供无密钥的 `.env.example`。
- 阶段验收后在 `main` 上打版本标签。
