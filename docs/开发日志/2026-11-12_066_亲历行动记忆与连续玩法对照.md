# 066 · 亲历行动记忆与连续玩法对照

## 目的

承接065的已消耗食物ID缺口及用户“多调用AI，验证AI集成核心玩法”的要求。本轮不再只测一次提案，而是让真实行动改变物权、资源和合作条件，再由模型在同一世界继续决策。使用无记忆 / 亲历记忆两臂，保留真实失败和状态分叉；不改规则8、Schema、模型、Kernel或黄金，不扩第四SDK入口。

## 修改范围与决定

- 新增 `DsActionPerception`：感知v1原字节保留，v2在冻结快照中加入 `recent_player_actions` 和作用域说明。仅Game自由行动显式选择v2，要求同时使用行动提示v2与内核事务；默认headless、计划和其它机制不继承历史。
- Session在真实Kernel committed、受控写能力核验后、完成通知前，生成私有不可变白名单记录。记录包括最近四次动作、当时可见的对象ID / 名称、裁决类别和有限物权后果；不扫描可变Trace列表、模型叙述、玩家陈述、完整Effects或居民私有信任。零变化拒绝、骰败如实记录，不当作成功。
- 物件名称与对象只来自该次冻结视角；历史物权不代表当前库存、地点或可用性。记忆不递归补记旧ID，不补资源；Restart / Restore清空并更换本地epoch，同JSON的ABA与晚回复不能回灌。
- 版本由不可变TaskSnapshot贯穿FreezeCopy、在线安全重建、Kernel binding / 指纹及同版候选回放。新字段仅v2序列化，旧v1提示 / 感知组合及历史黄金不更新。
- 干预是“亲历记录＋配套历史解释指令”，不是只增加数据字段的纯因果试验；仍以当前合法视角为边界，不发送完整世界。

## 有限真实实验及门禁停止

`--action-memory` 默认离线，仅显式 `--live` 联网。预注册四类玩法链（投喂 / 契约交付合作 / 照明搜索 / 购买）、三个固定种子、两个感知方案、每臂四步，最多96次。每臂保持同一Session；不重置链中资源、骰序或世界，不用模型台词补写后果。最终玩法目标、第二步重复挑战、原始意图及管线不变量分别记录。

1. 首批在第32次按门禁停止，正式记录为 **31/32不变量通过、27/32意图检查通过、31个ready帧严格回放**。第32次模型把 `whelp` 填入item，规则安全拒绝；错误回复保留为意图失败。研究器误要求内核 `host_rejected` 的公开文案 / 回执状态与旧路径逐字相同，导致对照失败；真实前后世界、时间和效果相同。
2. 只修研究器的已声明拒绝映射：要求原Failure一致、旧执行器评估 / 校验问题 / 裁决 / 骰值一致，世界与其余回执字段逐字一致，仅归一 `unknown_entity → host_rejected` 等明确状态映射。不修改产品逻辑，不回填首批summary。
3. 离线非法物件反例通过后，另行预注册 `--memory-start-fixture=4`，只请求尚未采样的64项，**64/64不变量、45/64意图检查、62个ready帧严格回放**；两个失败准备不记回放通过。首批32项没有重跑。

两批合计 **96次真实gpt-6-luna请求**，输入121335 / 输出5724 tokens，usage未知0，费用合计**估算USD 0.00878730**。单并发、输出最多768 tokens、请求体最多12KiB、无自动重试或模型兜底。费用不是服务端账单或余额证据；两个manifest和比较器版本分开保留，不称96项在同一冻结研究器下全部通过。

具体玩法现象、逐臂分母、有效重复挑战与状态分叉见[有限验证报告](../亲历行动记忆与连续玩法有限验证.md)。记忆方案三个投喂重复挑战均正确引用已消耗的同串鱼并由规则拒绝，无记忆方案三个均丢失物件ID；但两个方案最终都能完成这三条跟随目标，不能把重复动作识别改善说成跟随只靠记忆才成功。其它措辞和合作失败仍保留，不宣布M3或普遍自主玩法通过。
