# 048 · 规则七原件保管与低信任补救

日期：2026-11-10。起点：`5d083d0`。本轮是用户要求继续主线后的**显式规则升级**，不是不改变行为的重构。

## 目的与范围

旧版低信任组卡在确认前：已看过凭据与尚无凭据被混为一谈，有效捷径却是重复出示刷信任。此次不降低合作门槛、不让失败托付冒充成功，而是给梅伦增加有真实代价的原件保管核验途径。

- 当前版本升为 `dragonsleep-rules-7`；不添加旧规则运行开关。
- `give(pact_page,maren)` 真正转移原件，记录玩家交付；不加普通礼物信任、不自动透露计划或建立盟友，仍要再次 `confide`。
- 合作资格为真实保管记录且梅伦仍持原件，或原有出示与信任路线；取回原件撤销保管和盟友资格。
- 契约向梅伦 / 总管仅首次成功出示增加对应信任；失败不抢占收益，重复出示不刷新首次记录。总管开笼仍独立核对，不因出示过一次就永久禁止。
- 缺凭据和看过但仍不愿合作分别公开反馈；实际拒绝记录公开要求，再驱动 `give → confide` 重规划。

没有改变预算、模型、JSON 计划 Schema、冻结案例、商业源素材或 PieGame 内核。本轮真实 API 请求 **0 次**；不读取密钥或预算。

## 关键决定：预测不冒充 NPC 已说出口

试运行不能读隐藏信任或远处原件持有人，把尚未执行的拒绝变成玩家知识。有公开出示 / 保管记录时，只条件性假设梅伦合作；实际托付可能 `Partial`，已经告知计划和公开提出条件的事务仍有回执、耗时，随后计划停止并作废剩余步骤。

离线规划器只用实际公开要求或实际失败的本地原因码选择交付，不用预测拒绝码。交付后的已知物件说明以玩家亲历记录为准，不提示墓穴还有另一份原件，也不追踪未观测的远处持有人。

UI 在重新确认前显示失去原件、不能再向总管出示的代价，说明试运行不是合作保证。独立社会夹具通过默认离线提供方与真实按钮验证前缀，不冒充从新局取得原件或完整归巢。
