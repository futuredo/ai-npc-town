## 限制、风险与下一步

- **阶段 0 完成后，在阶段 1 的输入协议边界暂停确认。** `DsPlanRun.ReplanAsync` 的上下文原样合并进 `ContextBuilder.PlanPerception`；`RuleProvider` 则直接解析提示词中的感知 JSON。若向现有感知添加 `reason_code`，会改变真正发送模型的内容与提示指纹，违反本轮字节不变要求。因此尚未添加原因码，也未删改中文判断。
- 推荐原因码只存在于本地类型化元数据，经会话传给离线规划器，不写入感知 JSON / 提示词 / 旧回放记录；中文仅展示。该方案需要明确本地元数据的来源与旧回放兼容边界，不应悄悄增加“只有离线提供方能看见的世界事实”。在用户确认前，不推进阶段 1–4。
- 阶段 2（partial 拆分）、3（随机源与执行模式）、4（计划类型化）、5（旧代码与内容数据驱动方案）尚未执行。没有删除任何旧代码或资源。
- 长期 SDK 抽离只记录方向，不在本轮扩展实现：共享契约、提案管线、事务回执、规划与回放基础设施；`DsWorld`、动词规则、剧情与内容保留为宿主适配层。应以第二个不同规则项目验证复用，而非仅把龙眠镇类改名为 SDK。
- 自动化证据仅覆盖既有离线行为与主场景四项表现测试，不代表真人玩法、视觉或在线模型效果验收。
