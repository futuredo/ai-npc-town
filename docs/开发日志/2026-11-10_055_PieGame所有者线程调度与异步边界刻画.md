# 055：PieGame 所有者线程调度与异步边界刻画

日期：2026-11-10。与主线晚救援分别提交，交付可复用调度基础，不虚报第三条玩法迁移。

## 目的与决定

只将 Executor.Commit 调回主线程会遗漏 Session 请求前后世界读取、trace、造物待槽以及计划续体。当前串行 gate 跨 await 的语义也不能随便释放。本轮不改生产 Session / Plan 的线程所有权，先实现独立 `IOwnerThreadDispatcher.InvokeAsync<T>(Func<T>)`。

新增纯托管 FIFO 队列及 Unity Update 宿主，共 152 行运行时源码，锁只保护队列登记 / 领取，实际同步块在 owner 且不持队列锁。默认每帧最多 16 项、禁止重入，单项异常隔离；OnDestroy 取消尚未执行工作，不覆盖正在提交的结果。原 token 仍交给真实桥裁决，不伪造取消回执。

## 验证

- 独立 8 项调度 PlayMode 配合真实 UnityKernelBridge，而非假提交器。TCS 与队列计数区分提供方等待、结果入队、实际派发；派发前无端口写入，实际端口及 Completed 在主线程。
- 覆盖同步 / 异步提供方、错误线程 Drain / Close、重复 / stale、原始 token 提交前与提交后取消、禁用后已入队再销毁即时取消、块内关闭、异常后续项、限额 16 与 continuation 不 inline。
- 新增 2 项真实 Session .NET 边界刻画：专用线程发起请求、worker 释放 TCS 后完成不回原线程；等待时移动被拒，协作取消世界不变且 gate 释放。**这些断言证明生产缺口仍在，不代表修好了它。**
- 联合候选 .NET **302/302**（Town 241、Kernel 61）、Unity **73/73**（游戏 54、桥 11、调度器 8），证据 `.local/late-rescue/final-verified/*.trx`、`.local/late-rescue/playmode.xml`。六组黄金不变；本 SDK 增量未修改规则、提示、Kernel 或既有桥。
- SDK 独立提交前再次完整执行 .NET **302/302**、Unity **73/73**，证据 `.local/owner-dispatch/dotnet/*.trx`、`.local/owner-dispatch/playmode.xml`；实际 XML 为 Passed、失败 0。没有把仅静态检查写成通过。
- 产品运行时代码未再变更，复用 054 同一候选实际包的 14 次运行证据，不重建同样的大包或冒称新跑 Player。最新包 `120116-f047938c.app` 及历史日志保留；原 57 条构建警告、真人观感和性能未验结论不变。
- 本 SDK 验证全部离线，无新增真实 API；主线同轮 22 次真实 Plan 的费用和未过项单列 054，不写成全轮零费用。

生产真实接缝仍只有场景移动与日间推进。模型、造物、夜间、计划异步链路及 Unity 严格回放没有迁移；不声称两个完整真实宿主已经统一 runtime。后续先按主线需要设计请求冻结 / 终结的完整所有权和造物确认记录，再接调度器，而不是跨 await 保持短提交 scope。契约见[所有者线程调度](../PieGame所有者线程调度契约.md)。
