# 改为直接在 main 开发

日期：2026-11-05　分支：main　关联 PR / 提交：#3（已合并，0dc1389）

## 目的与范围

用户认为单人开发不需要 feature → develop → main 三层流程，要求改为直接在主分支开发。本次只调整协作流程、仓库保护和 CI 触发条件，不改玩法代码。

## 修改与关键决定

- 收尾三个叠加 PR：
  - #3 已包含 #1、#2 的全部提交，把目标分支从 `develop` 改为 `main`，用 merge commit 合并（0dc1389）。
  - #1、#2 关闭，并注明已随 #3 合入。
  - `develop` 和旧功能分支暂时保留在远端，不再使用。
- `main` 远端保护改为只禁止强推和删除，取消「必须走 PR」和「必须通过状态检查」，否则无法直接推送。
- `core-tests` 改为只在推送 `main` 和手动触发时运行。CI 失败不会阻止推送，要靠看到后立即修。
- `AGENTS.md`、README、[分支与协作规范](../分支与协作规范.md) 同步改为单人直接在 `main` 开发；提交前本地跑测试、不强推的要求保留。

## 限制、风险与下一步

- 失去了 PR 带来的 Codex 自动审查和合并前拦截。需要审查时，可以临时开分支提 PR，或在 PR 外手动请求审查。
- 有协作者后应恢复分支保护和 PR 流程。
- `develop` 分支确认不再需要后可删除，它的保护规则也要一并移除。
