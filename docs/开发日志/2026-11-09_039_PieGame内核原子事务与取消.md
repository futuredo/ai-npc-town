# 039 PieGame 内核原子事务与取消

日期：2026-11-09

## 目的与修改范围

提交 2：新增纯 C# `PieGame.AI.Kernel` 及独立 ToyHost 测试工程，并加入 `Town.sln`。Unity 源码、目录、asmdef 均有新的 `.meta`，`noEngineReferences: true`、空程序集引用、关闭自动引用；现有程序集和 GUID 不改。实施中按用户补充统一采用 PieGame 命名，新资产改名时保留其 GUID。

内核仅管不透明状态、字符串任务注册、冻结字节包、提供方编排、候选、事务回执与取消。维修宿主只在 `.NET` 测试工程：分钟时间、数量资源、缺料/工位占用、支出阈值、私有库管信息。阈值候选此时只能返回 `confirmation_required`，下一提交才加入确认能力。

## 关键契约与证据路径

- 提供方等待、宿主隔离解析/候选执行在提交锁外；读快照、正式候选和外部事务经过同一把短锁。
- 原子性覆盖经过该内核实例的写入。宿主端口 `Write` 必须完整替换成功，或抛异常且无副作用；端口不得重入内核。直接改宿主状态、多个内核实例包同一可变端口不在保障范围。
- 锁内先检查取消，再判断已提交身份/会话/摘要并写入、登记去重。相同请求不同候选不是重复成功；外部事务也比较提案身份。
- 提交前取消为 `cancelled`；提供方忽略取消后返回为 `late_after_cancel`，不使用输出；提交线性化边界开始写入后取消不能回滚为“未写入”。回执保持 `committed` 并可观察 `CancellationAfterCommit`，包括回执返回后才取消。
- 竞争测试在端口写入前设置屏障：候选已比较但尚未写入时，外部事务阻塞在同一把锁外；候选成功后，旧摘要外部事务被拒。反向顺序用提供方等待屏障验证外部成功、候选过期。
- 公开回执/事件只含机器码、请求 ID 和摘要，不含原始输出、感知、世界快照或宿主异常文本。摘要是本次事务的证据，不是公开世界视图。
- 独立子智能体复核后补 3 个负例：同态换局的外部事件必须依靠 `StateStamp` 代际拒绝；重复回执保留原提交的取消观察关系；非法 Unicode 使用严格 UTF-8 在写入前拒绝，避免默认替换编码令不同状态摘要相同。外部摘要由不可构造的 stamp 提供，也消除了伪造摘要拼接身份的歧义。
