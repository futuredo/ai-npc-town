# M3：规划闭环修复与状态迁移复验

日期：2026-11-09　分支：main　关联：[切片计划](../雏龙归巢切片计划.md)、[完整报告](../归巢规划闭环复验_2026-11-09.md)、[指标 JSON](../归巢规划闭环指标_2026-11-09.json)

## 目的与范围

用户要求先解释完整护送为什么远差离线基线，修复规划与失败补救，再做真实模型复验；暂不推进 M4。

上一轮模型完整护送仅 3/40，基线 34/40。逐局发现动作/库存语义错误、长期暴露于巡逻、旧状态压过当前状态、最新拒绝原因没有传回，以及步骤结束被误判为目标完成。另有 `confide` 静态允许 Partial、实际执行却中止的不一致。

## 修改范围与关键决定

- `DsPlanRun` 增加调用方指定的归巢目标；完整任务确认前必须覆盖团聚，运行中也依据真实目标结束。保留局部任务原行为。
- 显式修正被拒提案，传递最新拒绝原因；标清草稿预测范围及其前序步骤，避免“预测已跟随”被当成当前事实。确认前、两步之间的静态失败反馈不暴露异地隐藏原因。
- 当前感知增加玩家已知的帮手与出示记录；当前前置条件从裁剪后的感知推导。旧计划和历史成功步骤只留本地审计，避免旧成功覆盖新抓捕或新恐惧。
- 在线 Schema 枚举来自冻结视角；Core 引用校验仍独立执行。提示补足消耗、跟随、安抚、时序与风险，并给出工坊暂避的领域策略示例，报告明确其贡献边界。
- 统一静态与运行的 `confide` 判定；低信任藏匿在掷骰前拒绝。规则升到 `dragonsleep-rules-6`。
- 研究器最多三份连续无效草稿，完全相同的无效动作序列提前结束；每局最多十次规划调用。首案修正不改写首案分母，提供方故障不重试。
- 保持原冻结案例与离线基线源码不变；新增六个独立状态迁移案例，在首次真实测试前冻结。最终各组独立统计，不把试跑、控制组、中断批合成总准确率。

## 结论、未完成项与下一步

**主要差距已收敛，但 M3 整体验收仍未通过。** 原首案达到 80%，却没有严格高于 100% 的基线；不能偷换原门槛。

1. 低信任梅伦整局 0/10；固定前置条件探针 1/10。重复出示契约可累加信任的原型规则与泛化拒绝文案会误导补救，应改成玩家可理解的条件与有意义的协商路径。
2. “谁也别告诉”主组有 3/10 仍托付皮普，新措辞为 2/3；当前执行器检查归巢和合法引用，没有把玩家否定约束编成硬条件。成功归巢不能掩盖这一问题。
3. 新状态样本有限，中间控制组没有多轮随机重复，不能宣称普遍优于基线或给单项修复确定归因。
4. 下一步仍聚焦 M3 的意图约束保持与社会补救，再以独立案例复验。M4 计划面板、取消等待与 M5 真人小测均未开始。
