# 061 · 玩家行动模型请求接入 PieGame 内核

日期：2026-11-11。基线：`3dde617`。目的：让一个真实游戏模型入口使用 `Begin → PrepareAsync → Commit`，移除此入口自己的摘要 / 去重 / 代际提交裁决，而不是再套一层 Transact。

## 范围与关键决定

- 仅 Game 输入框自由行动注入 `IDsActionTransaction`；headless 默认 Act、计划 FixedProvider、研究扰动、对话、造物、居民、GM、Plan 和夜间提交继续旧路径。同一 Adjudicate 的分流由明确入口及注入决定。
- Core 不引用 Kernel / Unity；新无引擎 `Town.PieGame` 与 `.NET Town.PieGame` 共源，负责冻结编码、纯 handler、提供方旁路、错误映射和共享 StatePort。Unity 只包装真实桥及生命周期。
- 冻结私有 packet 的确定字节与任务 / 协议 / 规则 binding；provider 核指纹后只消费同一个 packet，不重新读取世界。handler 从 before 恢复独立候选，在 worker 调用 Prepare。
- `FinishActionTransaction` 不调用旧 `DsExecutor.Commit`，不再核宿主 stale_context / World 引用 / SessionGen；仅保留 superseded 宿主策略。Kernel 是此入口提交权威，受控能力一次写 world＋spent，跨时段换岗在同一候选生效，无 fallback。
- Restart / 空闲 Restore 统一通知同桥 Reset；允许自由行动等待中重开但保留 Busy 到迟到任务收尾，不取消代替 Reset。有效旧 candidate 实际 Kernel 回执 stale_session；等待中移动 / 日间 / Restore 仍被 gate 拒绝。
- 每 ready 留私有 ReplayFrame，不入公开记录；旧 DsReplay 与新 Kernel replay 各覆盖自己的路径。保留原 Provider 错误 / usage，缺完整 usage 的费用副本归未知；仅内核 trace 多 kernel_code。

逐条设计、入口表、回执映射及代码位置见[玩家行动接入契约](../PieGame玩家行动接入.md)。Kernel / UnityKernelBridge 源码、协议、规则、提示组装及黄金工件均未修改；没有新增收费请求，也未读取 `.env.local` 或预算文件。
