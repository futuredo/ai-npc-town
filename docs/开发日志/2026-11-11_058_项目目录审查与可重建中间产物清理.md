# 058：项目目录审查与可重建中间产物清理

日期：2026-11-11。起点 `main@a9e9531`，工作区干净。用户要求审查项目文件夹架构和内容，先清理无用内容；本轮不推进玩法、规则、模型输入或 SDK 迁移。

## 目的与审查结论

目录膨胀主要来自本机素材筛选时的完整解包暂存、派生筛选包，以及验证提交时导出的重复工程，不是现行源码里存在几套可直接删除的游戏实现。`dotnet/` 编译 Unity 下同一份核心代码，不是重复源码。独立只读审查也未发现足够依据直接删除的现行 C#；旧代只剩 15 个空目录元数据。

完整目录职责、精确清理范围、恢复依据及保留项见[目录审查](../项目目录与清理边界.md)。主场景依赖未入 Git 的商业资源、内容加载器未实现、Plan 所有权 / 造物授权未完、CI 覆盖分散仍是已知边界，清理不掩盖这些问题。

## 修改范围与关键决定

- 对 5 个外置盘原包重新核 SHA256，与既有来源审计完全一致；对四组素材暂存和 Arashi 增量暂存逐文件核原包字节，再核派生包与清单 / 暂存一致。只删除可重建中间产物，原包、导入工作资源、清单、种子、脚本、许可台账不变。
- FantasyHorde 暂存有 15 个文件无法与当前原包逐字证明一致。未将它或其样本包当垃圾，保留并列出不确定项；初次只读审计因该断言中止，当时尚未删除，随后改为保留不确定项、仅对通过者执行。
- 三份 staged-main 的 443 个非 bin/obj 文件都能在 Git 对象库找到原 blob，没有独有源码；只删这些导出副本及生成输出，保留相邻 TRX 和结果。临时 capture / PayloadAudit 工具只删 bin/obj，保留其源码。
- 旧 `dotnet/Pie.AI.Kernel*` 两目录只有被忽略的 bin/obj，删除；当前 `PieGame.AI.*` 工程不变。另删旧自动 `unity/Pie.AI.Kernel.csproj` 与三处 Finder 元数据。
- 删除 14 个退役 Core 空目录、空 Scenes 目录及各自 `.meta`；删除前查实际 Assets（含主场景）、设置和编译工程，无这 15 个目录 GUID 引用。目录与元数据同步清理，避免留目录后重生新 GUID；现行脚本 GUID 不变。
- 修正 `Town.Content/Config/README.md` 的过期初始化路径及骨架“目录为空”的说明，新增目录清理边界文档和入口链接。

本地实际删除 **25 个精确对象、16,385 个文件、11,278,015,934 bytes 逻辑大小**；另删除受控目录 `.meta` 15 个、2,565 bytes。约 11.28 GB / 10.50 GiB，不声称 APFS 实际物理空间必然等量释放。执行清单及逐文件来源核对位于 `.local/cleanup-20261111/`；删除前后另核 7,480 个保留本地文件的大小和 mtime 不变。
