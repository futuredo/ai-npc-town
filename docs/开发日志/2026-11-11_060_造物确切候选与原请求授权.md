## 目的与关键决定

旧 UI 只捕获 bool，会领取 Session 最新图样；完整世界哈希无法阻止旧按钮批准同世界里的新候选。准备后取消原请求，旧实现也仍可能确认消耗材料。本轮引入只读冻结描述的本机 opaque `DsCraftProposal`，由确切 trace 引用取得，确认只接受当前同一能力。

- Session 共用前置检查拒绝覆盖 pending，三类 Craft 调用入口都在 provider 前拦截。
- Game 开启严格绑定模式，裸 bool 不消费待槽；headless 默认保留受信任兼容适配。
- HUD 描述、按钮闭包和 Escape / 收起均绑定所显示的 handle。旧句柄不消费新案、旧卡不关闭新卡；busy 拒绝保留本地绑定。
- 领取有效决定时先清槽一次，原 token 取消生成 cancelled、零效果 / 材料 / 时间；实际提交后取消不回滚。取消不在后台自动修改待槽。
- 正常图样仍由原执行器检查完整世界摘要，保留准备一次与决定一次的同 trace 两次 owner 通知。
- 正常回放三态保持；v1 没有记录取消操作，cancelled 明确拒绝严格重放，不伪装为玩家 declined。
