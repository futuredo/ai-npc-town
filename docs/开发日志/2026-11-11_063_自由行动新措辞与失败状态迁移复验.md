# 063 自由行动新措辞与失败状态迁移复验

## 目的与范围

承接 `c1be04c` 的有限行动验证，新增独立 `ds-action-kernel-transfer-1` 套题，验证未用过的措辞及失败 / 消耗后的状态承接。不修改产品规则、提示、模型、内核、Unity 运行时、黄金或原冻结计划集；不通过修改规则或反复采样将失败刷成通过。

## 关键决定

- 沿用真实 `Session.ActAsync(input, ct, transaction)` 第三入口，复用既有 runner 的冻结出站、同原文旧路径对照、私有录制与真实 Kernel 严格回放。原 suite 判据不改，新套题由显式 `--action-kernel --transfer` 选择；默认离线，仅添加 `--live` 后联网。
- 固定 20 个独立案例与同一世界 4 步连续行动。20 份输入、预期字段和 before 摘要、四步序列的预期均在联网提供方创建前保存；不是 24 个独立随机样本。
- 新套题严格匹配 verb / target / item / place，预期空字符串不作通配；具体拒绝原因与有无骰、耗时分别检查，错误对象导致安全拒绝也不能记作理解正确。
- 部分独立夹具由先前脚本提案经真实规则准备：买鱼花光银币、鱼被实际吃掉、灯已在此处施效，以及投喂 / 展示 / 交付实际掷骰失败。脚本准备不计模型能力；失败使用预设原生种子7，不遍历挑种子、不强制成功骰、不在模型回复后补资源。
- 四步连续行动为：重复拿随身铁锁 → 再次拿同一铁锁 → 买鱼 → 再买同一串鱼。每次 before 承接上一 after，没有中途重置；范围只到这些局部行动，不冒充归巢、多日社会或真人试玩。
- 本轮最多24次真实请求，`gpt-6-luna`、768输出tokens、12KiB体积、单并发、无自动重试、不切模型；服务或不变量错误即停，按原研究账本记录。不打印密钥、不读取或重置账本原文。

## 实际验证

- 首次完整离线 .NET 426/426；补充“照明错目标被拒不得假绿”的研究器反例后，预 live 全量 **427/427**（Town366 / Kernel61），证据 `.local/action-transfer/pre-live/*.trx`。原黄金保持通过。
- 本地夹具反例：三项先前失败均实际 `roll=0.3548`、Rejected 且 Applied，随机计数1、spent2、原物件仍归玩家；食物消耗与银币花费均由原执行器真实提交，不是只手改 consumed / Coins 冒执行证据。
- 正式真实批24次请求已完成，严格四字段及效果联合检查 **12/24**；不变量、同原文旧路径、ready候选实际严格回放及有限安全检查各 **24/24**。输入21,142 / 输出1,459 tokens，费用合计 **估算 USD 0.0028437**，未知费用0、提供方错误0。证据目录为 `.local/dragonsleep/experiments/20261111-120246-0276540-8a36646677e14a02bbc66449dcaeb96d-action-transfer-live/`。
- 正式离线组也为12/24，但未过项不同，不能因此称两种提供方能力相同。两批清单51项源码与3个加载程序集分别一致，收尾核对源码仍51/51一致；未在live后改题、改源码或补样本。
- 12项未过中，8项仅是合法空 place 与预设地点ID的字面差异，效果检查符合；另4项将明确重复操作分类为 unsupported，未保持预设 feed / take / buy。四项都安全拒绝、零耗时、世界不变；保留正式12/24，不事后改分，也不将地点字面差异写成错误世界动作。逐项见[有限报告](../自由行动新措辞与失败状态复验.md)。
- 四步序列全程哈希承接、仅第三步买鱼扣三银币，最后未重复扣钱；严格检查只有第三步通过。不把正确状态承接或内核 committed 冒充完整意图通过。
- 本轮独占 Unity 全量 **89/89**，失败0、跳过0，实际XML `.local/action-transfer/playmode.xml`，耗时99.4714488秒；本轮未更改Unity运行时或测试。
- 默认90局 / 27局离线研究核心与062基线逐项相同，证据 `.local/action-transfer/default-offline/{frozen,holdout}-comparison.json`，两者 `equal=true`；排除的仅为UTC、实测耗时及超5秒数量，不排除玩法指标。黄金、冻结用例及生产规则源码无改动。
