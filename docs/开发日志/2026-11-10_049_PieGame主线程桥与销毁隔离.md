# 049 · PieGame 主线程桥与销毁隔离

日期：2026-11-10。主线起点：`e117e9d`。SDK 与游戏并行推进，单独提交，不迁移龙眠镇、不改变其规则和模型输入。

## 目的与范围

把已验证的纯 C# 内核带到 Unity 生命周期边界：后台等待和准备不阻塞主线程，所有真实状态读取和写入回到 Unity 主线程；对象销毁时，不让不配合取消的提供方留下悬挂的公开任务。

- 新增 `PieGame.AI.Unity`，只依赖内核和 Unity，关闭自动引用；新增独立 PlayMode 测试程序集，不引用 Town。
- `UnityKernelBridge.Awake` 锚定实际主线程。同步事务入口、事件订阅和准备启动均先检查线程；端口回调不得重入。
- `PrepareAsync` 强制在 worker 运行提供方和隔离 handler，纯托管 mailbox 交付结果；Update 只完成准备任务，不自动提交或确认。
- Commit／Confirm／Transact 均显式调用真实内核；没有复制内核的去重、代际、原子性或确认逻辑。
- OnDestroy 关闭队列并立即取消所有待完成公开任务，包括已排队但尚未 Update 的任务；随后取消提供方生命周期，迟到结果只丢弃。
- 原始用户 token 保留在内核 Preparation／Receipt；提供方仅在调用期间使用用户与生命周期的组合 token，准备后或提交后取消的观察不丢失。

没有修改 `PieGame.AI.Kernel`、Town 代码、场景、模型、预算或 .NET 工程。本轮真实模型 API **0 次**，没有读取密钥或预算。

## 决定与修正

并行初稿加入了句柄、自动提交、回放入口和会话容量策略，偏离本轮最小边界。该初稿未提交；主会话停止其继续扩展，收回为原定的 Request／Preparation 与显式提交接口。不是在自动提交路径旁叠兼容层。

Unity 严格回放本轮不暴露：内核该入口会读取 live port，不能直接套进普通 worker 准备。现有内核严格回放能力和 61 项 .NET 测试完全保留；不把录制原文塞普通 provider 冒充严格回放。

初轮桥测试仍要求提供方收到 `CancellationToken.None`，且销毁后继续解析，与实际生命周期保护冲突。保留生产保护，修正测试；以内部只读计数建立“后台迟到处理已结束”的确定屏障，不以等一帧猜测。另补已入队取消和端口回调重入断言。
