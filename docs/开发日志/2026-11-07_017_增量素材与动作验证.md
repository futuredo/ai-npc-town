## 修改范围与取舍

本轮外盘已从最初六组扩展至 **17 个顶层组/项**，快照含 **6 个 `.downloading` 文件**。筛选期间 Medieval Kingdom、Frozen Fortress 陆续完成，动作库和 Metahuman 包出现；收尾保留已取得快照，不反复追逐下一下载。

- 新增选择 Fantasy Horde 四人物、一根法杖、十动作及依赖；Arashi 只取一个配色及依赖。
- 旧 Medieval NPC、KINGDOM、Fantasy Worlds、龙和 Alcazar 样板不重复导入。旧商人参与新动作采样，不改原 Prefab。
- Medieval Kingdom 全流静态检查 1423 条目，主体 HDRP；URP 目录只有外链取包说明，不等于当前已取得 URP 内容，暂不导入或自动下载外链。
- Frozen Fortress 完整包静态检查 535 条目，雪堡主题非必需；URP/材质尚未验，暂缓。
- TL NPC01/05 与旧 NPC02 同属来源/许可风险，PSA/MAX 另需转换，继续排除。BIP/RAR 动作库未逐段验证，不当作现成 Unity 动作。
- AFS、Modular Medieval NPC、Stronghold、两包 HEROIC FANTASY CREATURES 和一份 BIP 格斗库在快照中未完成，不改名、不解压导入。

### 2. 最小依赖闭包与管线处理

通过本机离线脚本检查包结构与引用，筛选后生成只含 `Assets/LocalThirdParty/` 路径的临时 Unity 包。原始 Prefab/材质部分是二进制序列化，只匹配文本 `guid:` 会漏依赖；补充对应二进制 GUID 匹配后，才检查所有 incoming GUID 无碰撞并在当前 live Editor 中导入。没有把最初不完整的依赖列表当作成功结果。

| 新包 | 选择入口与依赖 | 结果 |
| --- | --- | --- |
| Fantasy Horde Villagers v2.2 | 15 入口，54 文件，转换前 187096365 bytes | 16 FBX、十日常片段、四人物加共享 rig 共五有效 Humanoid Avatar |
| Arashi Character 1.0 | 一个配色入口，14 文件，转换前 299759316 bytes | 7 FBX、主模型有效 Humanoid、读取 46 片段；偏战斗，作为备选 |

Fantasy Horde 先应用包内 URP Shader 子包的同 GUID 版本，再追依赖；没有导入子包里的工程管线配置。四个原生兼容材质保留，四个 Built-in Cutout 与一个 Standard 转为 URP；Arashi 一个 Standard 转换，共 **6 材质转换**。最终十个新主材质均为 URP、supported 且无 Shader 错误标记。

本轮发现 `shader.isSupported=true` 的旧 Cutout 仍无 URP Pass，因此不能只看支持布尔值；按管线标签/材质引用检查，保留其实际使用的主贴图、UV、裁剪、法线与相关参数后转换。未使用的旧 Shader 文件不等于主材质仍在使用它，审计分母明确为十个新主材质。

Arashi 的 `Player.cs / ChanceWeapon.cs` 排除，源 Prefab 两个缺失脚本引用保持原样；只在新 `_Review.prefab` 中清理。没有为了消除警告执行下载包脚本。

### 3. 新预览和动作验证工具

新增 `Town.Editor/IncrementalAssetReview.cs` 与 meta，显式菜单创建独立五对象场景和五个干净适配 Prefab，共享 Horde 待机控制器。已有目标场景时拒绝覆盖；临时打开、保存、截图后恢复原激活场景。新样板在 `Assets/LocalThirdParty/Review/Incremental/`，没有替换旧场景/角色或烘焙 NavMesh。

`VerifyAnimationRetargeting()` 使用独立 PreviewScene 和手动 PlayableGraph，十片段对四 Horde 人物、旧商人和 Arashi，分别在 10%/37%/71% 三时刻采样骨骼旋转并检查有限值与变化。首次旧商人实例没有绑定 Avatar，检查真实失败；随后只在临时实例上从依赖中取得唯一有效 Humanoid 并绑定，原 Prefab 不改，再完成最终 60 组测量。

预览角色为并排审阅统一了显示高度，不把该缩放作为成人/儿童最终比例。源文件和新适配件都留在本机被忽略的商业目录；不会随代码仓库分发。
