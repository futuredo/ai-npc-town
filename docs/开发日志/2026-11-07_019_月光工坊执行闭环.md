## 目的与范围

用户明确要验证 AI 对游戏内核/玩法的改变，允许按设计继续搭建；GitHub 可参考，但框架实际进度优先。因此不再扩故事或泛化 Agent 平台，先推进 **N4 方法候选 + N2 角色条件的执行下游**：答应、确认、实际完成必须分开，能取消、失败、录制与重放。

本轮不调用模型、不读取密钥、不更改 `action=none`、信息视图或费用政策。不把人工样本包装成自然语言理解，不把旧 100 项测试作为新机制证据。保留其他任务的 URP、素材、Blender 工具链与全部未提交修改，不关闭用户已有 Editor、不启动第二实例。

## 修改与关键决定

### 独立 Core 与新场景

- 新增 `Town.Core.Moonlight`：`MoonRequest`、`MoonCandidate`、`IMoonCandidateSource`、`MoonWorkshop`、`MoonReplay`。不改旧 TownRuntime 存档协议，不把旧 ID 重命名冒充新玩法。
- 输入文本保留；候选当前由 **显式人工样本**给出：引路、分光、澄清、拒绝。没有关键词暗匹配，也没有真实模型适配。
- 引用只允许本次离线请求中的芬恩观察；检查代际、请求实例归属、版本、有限能力、角色同意、持续供光条件与两份月焰。候选同意后等玩家确认，才占用资源。
- 新 `MoonWorkshopGame` 在 Unity 里实际验光/检测遮光、等待分光稳定两秒、驱动 NavMesh 与连续位置采样。上下路是实质不同的空间结果；模型/样本不能直接宣布完成。
- 新 `Moonlight_Workshop.unity`、独立导航和四个 URP 材质，均通过现有 Editor 的 CLI 生成。使用内置几何作技术代理，不引用商业素材、不覆盖旧灰盒或素材预览。
- 书签为内存录制/回放：新代际、恢复后暂停、继续重新验现场光路；不是磁盘多槽存档。Core 录制上限 10000 指令/2 MiB，SHA 只检测损坏。
- 记录请求前先写有界命令，防记录已满后留下半个 pending；候选与历史输出为副本。

完整职责、运行方法与下一最小任务见[执行切片说明](../月光工坊首个执行切片.md)。

### 两项真失败与修复

首次全 PlayMode 为 **7/9**，旧六项全通过，新场景出现下路引路超时与重开后高度偏差 **1.2278 米**。增加位置/路径/路点诊断后查出：Unity 圆柱默认是胶囊碰撞体；压扁外观时胶囊半径仍撑高，烘出了悬空导航面。角色虽到导航目标，却进不了 Core 的约定路点范围。

只对本轮四个平台换贴合模型的静态 MeshCollider，并重烘自己的导航数据，保留其资产 GUID；旧场景/NavMesh 不动。起点导航面由约 1.2278 米降为 **0.0167 米**，导航三角形 34。没有放宽到达半径或重开位置断言。修后原九项全过，再补途中书签恢复与继续测试；另保留书签处不足一次姿态采样的时间，避免恢复后误判超速。最后重新编译并运行，十项全过。

## 限制、风险与下一步

1. **没有证明 AI 原生机制增量**：当前一角色、固定两方法、固定离线观察/同意样本；尚无开放语义理解、协商反提、自主多角色、受限 GM 或功能造物。N2/N4 的完整模型职责仍待接入验证。
2. 光路检查目前只覆盖指定遮光层和这张固定地图；连续采样不是全几何安全/防作弊。引路代理自动跟随，不是玩家自由设计的造物。还没有任务阻塞有界超时/恢复、完整场景编辑回放或长会话压力验收。
3. 技术几何和 IMGUI 不代表正式奇幻品质；未做人类试玩、正式动画/声音、无完整漂流灯队伍、准备/迁移/收束短局。
4. 下一步不是再搭通用框架：在现有执行接缝扩展参数/顺序/条件不同的小计划与单角色异步候选协议，保留输入反例；明确获准在线视图/动作范围后，再申请至多三次真实窄探测，不自动扩大调用。
5. 旧方案历史归档尚未执行；未完成下载继续留作下一轮增量筛选。隔离辅助件可按清单精确恢复，不运行整仓回退。
