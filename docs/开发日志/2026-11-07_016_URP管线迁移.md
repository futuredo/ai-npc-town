# 将当前工程从 Built-in 迁移到 URP

日期：2026-11-07　分支：main　提交：未提交、未推送

## 目的与范围

用户要求“先把目前我的这个工程转成 urp 的项目”。本轮交付真正生效的 URP 工程、材质转换、可持续使用的生成/截图工具，以及既有玩法底座回归；不是只向 manifest 加包。

这是一项独立工程任务，不表示 v5 详细设计已经确认，不提前移动 history，不接入新 AI 能力或改变在线权限。保留之前未提交的代码、方案、素材台账和用户已打开的 Editor；没有重新生成灰盒、NavMesh，也没有将商业人物替换进玩法场景。

## 修改与关键决定

### 1. 管线与质量档

- 在现有 Unity `6000.3.23f1` Editor 中通过 Unity CLI 安装兼容的 `com.unity.render-pipelines.universal@17.3.0`，依赖由 UPM 解析，不手写 lock。
- 创建 `Assets/Settings/Rendering/Town_URP.asset` 与 `Town_URP_Renderer.asset`；Graphics 默认和全部 6 个质量档都绑定前者，防止切换质量后退回 Built-in。
- 当前采用同一 Forward Renderer：HDR、4× MSAA、render scale 1、主光阴影分辨率 2048、阴影距离 60、SRP Batcher；不默认打开额外深度/不透明颜色纹理。Renderer 配齐默认 PostProcessData；Unity 自动生成 Global Settings 与默认 Volume Profile。
- 新增显式 `Town/Rendering/Configure URP` 菜单，不在打开工程或 Play 时改配置。已存在的管线资产复用，不重建用户场景。URP 自动注册的调试输入保留，既有 WASD 等输入未删除。

### 2. 材质：兼容优先，不“一键全换 Lit”

转换前备份本机材质、场景和配置到 `.local/urp-migration-20261107/before/`。注意备份发生在安装 URP 包后，不能把其中的 Packages 文件称为安装前快照；安装前包差异仍需结合 Git 和本轮依赖记录核对。

| 处理 | 数量 | 说明 |
| --- | --- | --- |
| Standard → URP | 257 | 使用官方 MaterialUpgrader，包含灰盒与本地工作副本 |
| Autodesk Interactive → URP | 4 | 使用对应官方转换器，保留其贴图工作流 |
| 自定义 `2Side` → 双面 URP Lit | 32 | 保留双面、透明裁剪、贴图/UV；另做粗糙度通道转换 |
| Polyart Shader Graph | 31 | 已是原生 URP，保留图与材质，不替换掉混合等效果 |
| TriForge 自定义 Shader | 3 | 已声明 UniversalPipeline，保留树皮、树枝和分层混合 |

`2Side` 原 Shader 的 `_Glossiness` 实际代表 roughness，贴图来自 `_SpecGlossMap.r`；不能当作 Standard 的 smoothness 直接搬过去。本轮对照源 Shader 与 Unity CGIncludes，改为 `smoothness = 1 - roughness`，金属度保留独立来源，生成 **21 张线性 MetallicSmoothness 派生贴图**，不改源贴图导入设置。它们只在被忽略的商业样板目录中，不随仓库分发。

初次编译曾因调用 URP 内部 `LitShader` 类失败，已改用公开 `BaseShaderGUI` / `LitGUI` API。初次双面转换也曾仅保留标量，需要专项修正；随后依据备份恢复原关键字和粗糙度语义，32 个均完成修复，未来转换入口已包含该逻辑。首轮 `material-conversion.tsv` 是过程记录，最终状态应结合 `roughness-repair-result.json` 和 `final-audit.json`，不把早期记录当成最终验收。

最终审计 **336 个主材质**：URP Lit 298、URP Autodesk Masked 4、Polyart 31、TriForge 3；缺失/不支持/错误 Shader 0，残留 Standard/2Side/Autodesk 旧 Shader 0，Shader 编译错误标记 0。首轮素材任务的 83 项是抽样范围，本轮 336 项是全 Assets 主材质范围，不能比较成同一分母。

### 3. 预览与后续工具

- 本地素材审阅场景保留原有 15 对象、位置和尺寸，不重新 Build；将有对应 Prefab 源的 **485 个 Renderer** 恢复为源材质，替代先前为 Built-in 临时覆盖的材质。先检查场景已保存，再记录覆盖并保存；原场景已备份。
- `GrayboxSceneBuilder` 新建材质改用 URP Lit；`LocalAssetReview` 优先保留已兼容的源材质，必要兜底也用 URP。
- 新增共用 `EditorCameraCapture`，在 URP 下通过 `SingleCameraRequest` 输出截图；恢复相机、RenderTexture 状态并释放临时资源。`SceneSnapshot` 与素材审阅工具共用，不继续依赖 Built-in 的直接 `Camera.Render` 路径。
- Town.Editor 程序集显式引用所需 Core/URP Runtime/Editor 程序集。新增 PlayMode 测试检查实际管线类型、全质量档绑定与灰盒材质支持，而非仅判断包已安装。
- `.gitattributes` 仅对 Unity `.asset` / `.mat` 放宽编辑器生成的空字符串行尾空格检查；不手工重写 live Editor 的 YAML，C#、JSON、Markdown 保留默认检查。

### 4. 台账与授权

更新 `art/asset-manifest.json` 的当前管线和 `render_migration`，记录包版本、转换数量、派生贴图、审计与证据位置。原 `technical_verification` 标为首轮导入历史；不覆盖来源、许可或当时发现的问题。所有商业样板仍为 `license=null`、未核实授权、未批准发布；`import_verified` / `in_game_approved` 没有因管线转换擅自变为 true。

## 限制、风险与下一步

- 当前工具不能直接读取图片进行视觉评审。这里只能确认截图实际产出、基本像素非异常以及 Shader 技术检查，不宣称每件素材的贴图、头发/叶片透明排序、树风、双面观感或风格统一已经通过。
- Alcazar 等自动生成材质仍可能缺少正确贴图连接。下一步应由实际画面逐项验收，而不是再统一换一遍 Lit；动画重定向、逐段播放、玩法接入和商业授权仍独立待办。
- 尚未执行独立 Player 构建、目标设备 GPU/显存/帧率测试或包内 Shader 变体检查。现在 6 个质量档共用一套配置，不代表低端设备已优化。
- 本轮只迁渲染底座，AI 原生六机制、短局和正式 UI 不因此变成已实现，也不把测试通过等同于好玩或成品验收。
- 如发现转换回归，先定位具体材质/配置，再通过 Unity 恢复该项本地备份并重新验证；不要整仓重置或覆盖其他任务未提交改动。不要直接从备份 Packages 回滚声称恢复安装前状态。
