# 051：PieGame 首条真实场景事务接入

## 目的

按用户要求让 SDK 与游戏主线同步前进，不再只停留于独立 ToyHost / 桥验证。本轮选择最小真实入口：玩家实体进入地点的同步、零耗时规则事务。不同时迁移模型、计划、跨夜、造物或全部世界写入。

## 修改范围与决定

- `Town.Core` 新增无 Unity / PieGame 依赖的 `IDsSceneRuleTransaction` 与受控 `DsSceneRuleWrite`。原执行器先做旧去重、stale、失败和 no-change 判断，只有有变化的 `enter:`、同 spent / budget、零耗时候选才可传给 backend。
- `Town.Unity/DsSceneRuleTransaction` 在 Session gate 内同步建立短 scope，桥捕获真实会话 JSON 与 before 精确比较，Kernel 锁内只调用一次预先准备的宿主复制能力。没有影子权威世界、没有任意外部 Action、没有成功后的第二次复制或失败 fallback。
- `Game.UpdatePlace` 显式传 adapter；重开在 Game / Session 均空闲后重建会话，再用独立 reset scope 真正更新桥代际。普通 Core / CLI / 回放不传 adapter，旧路径与回执格式保持。
- `Town.Unity` 与主场景测试显式引用 PieGame Kernel / Unity 桥；反向依赖没有加入 Core。独立 Kernel 和桥源码未修改。
- 地图按钮补 `travel_<place>` 命名。新增显式 Player scene 验证模式，真正点击工坊和集市，核两套回执摘要、零耗时、零模型。默认完整计划没有混入这些额外移动，原终局 hash 继续单独核对。
- 最后检查补上 `TravelTo` 的 Session.Busy 拦截：不只是避免等待期间提交世界，还防止先移动实体、等解锁后无新输入却补交移动。对应测试同时断言 Transform 没变。

## 验证设计与实际结果

### Core 与桥的边界

5 个新 Core 接缝测试：旧 / 新路径完整 JSON 与规则事件逐字一致、世界对象身份保持、一次能力写入、能力返回即撤销、stale 无 fallback 可重新尝试、no-change / duplicate 不调用 backend、假报成功抛契约错误、非移动事务不得借用接缝。

7 个真实主场景 PlayMode：真实旅行经 SDK；抓捕 / 受惊 / 黄昏无岗 / 普通移动逐字对照；旧前置拒绝和去重；真实能力的错误线程 / scope 内 stale；重开后旧 ID 合法复用但不复活旧世界；明确计划 Core 移动仍未迁移；仅 Session 持锁时重开与旅行被拒。

- 最终全量离线 .NET：**248/248**（Town 187、Kernel 61），证据 `.local/scene-kernel/dotnet/`。含并行主线 8 个观察测试和本次 5 个 Core 接缝测试，黄金 6 组保持。
- Unity 6000.3.23f1 编译与最终 PlayMode：**55/55**（游戏 44、独立桥 11），`.local/scene-kernel/playmode-final.xml`，0 failed。游戏 44 = 原 36 + 接缝 7 + 地图 Player 同源验证器 1。
- 最终错线程 / Busy 检查修正后再次全跑，不复用修正前的通过声明；未改变规则、提示、冻结案例、黄金预期或独立 Kernel / 桥。
- 主线两份 90 / 27 局离线复验见 050；低信任组改善来自 Baseline 当前观察修复，不归因于 SDK。实际线上 82 请求也归 050，SDK 验收保持离线。

## 保障边界与下一步

可以说：**龙眠镇第一条真实场景移动事务已复用 PieGame Kernel 的比较 / 单次写入 / 去重边界。** 不可以说全游戏已经迁移、所有世界写入都统一、模型提交都在主线程或 Unity 严格回放完成。ToyHost 与此真实入口共同证明了一小段复用，但不是两个完整真实游戏宿主的迁移验收。

`DsWorld` 仍有公开可变字段，夜间仍在旧会话推进，Core 计划内部移动仍走旧执行器。绕写、恶意宿主、多个内核共享端口、内存耗尽时复制的强异常安全不在这条接缝保障内；未来把 RestoreState 用在同一 adapter 上时也须显式 reset。

下一步优先根据真实主线需求决定第二条入口，不机械逐个替换。详见[首入口契约](../PieGame首条场景事务接入.md)与[通用桥边界](../PieGameUnity桥契约.md)。
