# 046 · Player 完整短局与重开隔离

## 目的

用户暂时没有时间试玩，继续主线而不等待人工排期。上一轮只证明实际 `.app` 能启动；本轮补充实际 Player 中的有界按钮短局，并修复在自动化复核中发现的新局 UI 隔离问题。自动化不代替真人的理解、手感、视觉或好玩程度判断。

## 修改范围与决定

- 新增 `DragonsleepJourneyProbe`：仅在显式 `--dragonsleep-journey` 参数下创建 Player 验证器；正常启动不自动操作、不自动退出。Editor 测试显式创建同一验证器，不维护另一套短局实现。
- 使用实际主场景和默认离线 `RuleProvider`，唯一初态设置是随机种子 `7932`；不补物品、认知、信任、时间或雏龙状态，不注入成功计划。
- 所有玩法输入通过真实 UI Toolkit 按钮的导航提交事件：启程、目标、取舍、确认、逐步执行、重规划、结局、查看现场、重新打开结局、重开，以及新局第二次提案。不是操作系统鼠标坐标命中或 WASD 路径测试。
- 断言提案、重规划和确认不写世界；新草稿保持待确认，失败步骤及作废历史保留；明确检查实际执行失败而不是把首案语义修正算作失败补救。
- 取舍会先触发另一选项再明确选回独行分支，检查 Core 最终 `Selection`。控件树重建后等待新布局，再发下一次导航输入。
- `ClearLens()` 在重开时停止上一局的阶段揭示协程。否则普通最终跨夜后立即重开，旧协程可能重新填回新局织言镜详情。补充非计划链路的晚局夹具回归；该夹具不冒充完整新局证据。
- 重开同时清除常驻织言条的旧步骤通知，显示明确的“新的一局，尚无调用”；检查第二次提案前的可见提示，不让后续操作覆盖残留后再假称已复位。
- 新增少量 UI 名称用于可观察性，不改场景序列化引用、Core、提示词、黄金或 PieGame 内核。
