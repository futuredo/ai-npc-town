# M4：归巢计划界面与异步收尾

日期：2026-11-09　分支：main

## 目的与范围

把已有 `DsPlanRun` 接到主场景，让玩家通过界面提出目标、选择取舍、确认、逐步执行和失败后重新规划，不必从调试日志操作。主线玩法优先，本轮不迁移 PieGame 内核，不改 Core、规则、提示词、冻结集或预算。

与工程整理会话明确分工：对方完成 [043 整理](2026-11-09_043_旧原型退役与工程整理.md)，提交 `8334a4b` 后释放暂存、提交和主文档窗口；本会话独占 Game / HUD 计划 partial 与新测试。Unity 验证错峰，不用 restore、stash 或全仓暂存处理对方改动。整理提交推送未确认，本轮正常推送会一并包含它，不强推。

## 修改与关键决定

- 增加底栏“P 归巢计划”和快捷键；目标文字保留，步骤滚动展示，取舍分支必须通过归巢检查才能确认。确认本身不执行、不耗时间；每次点击只推进一个计划步骤。
- 使用已有归巢目标约束。局部动作完成、确认前状态失效、实际前置失败或世界变化，都不能显示成归巢成功。新草稿与重规划一律重新确认，不自动执行。
- 展示实际回执、提交数量、失败原因和作废步骤；重规划超时或坏 JSON 后仍保留历史，不把旧计划冒充新草稿。传输失败不走语义修正按钮，没有自动重试；可显式重新提出目标。
- 等待规划可以取消请求，但 Busy 保持到提供方真正收尾。忽略取消的迟到回复、已销毁场景的 continuation 不得恢复确认或执行。忙时拒绝重启、移动及其它输入。
- 一个 step 可能包含移动、时间推进和多名居民事务，不等于一笔可撤销事务。只提供“取消规划请求”，不承诺 step 原子回滚。跨夜部分提交后异常时终止剩余计划、保留实际后果与回执，禁止重跑该步骤。
- 结束前把玩家实体同步到实际 Core 地点，异常也走此收尾，避免下一帧按旧 Transform 改回地点。忙时 HUD 不枚举后台正在修改的世界、计划和轨迹集合；这不是通用主线程桥，未修改 Core 会话锁。
- 原 Game / HUD 的类名、文件名、序列化字段和 `.meta` 保持；新增 partial 与测试配新 GUID。场景、Prefab 和素材未改，沿用深青 / 金色界面。

## 限制与下一步

- 完成的是 **M4 的计划交互子项**，不是整个 M4 或 M3。低信任求助、否定约束和部分前置补救缺口仍保留。
- 离线主场景脚本走到团聚结局，不是本轮真实模型、真人手感、设备性能或发行包验收；未构建玩家安装包。
- 截图已导出，但当前主模型不支持图像输入，视觉子智能体又被组织模型策略拒绝，不能声称完成了人工视觉审核。几何检查不代表文字对比和实际观感已通过；仍需真人检查长文本与窗口可读性。
- 跟随 / 受惊 / 卫兵换岗抓捕 / 母龙相会的完整实体演出、关键造物外观与照明尚待补齐；规则事实不等于这些画面已完成。
- SDK 本轮无新增进度，仍是独立内核可行性通过、尚未接入龙眠镇。下一步优先补主线演出和可运行试玩包，再按真实需求推进最小适配，不让整体 SDK 迁移阻塞玩法。
