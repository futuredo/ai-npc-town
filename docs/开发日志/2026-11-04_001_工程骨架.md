# 离线工程骨架与素材准备

日期：2026-11-04　分支：`feature/town-runtime-skeleton`

## 目的与范围

在现有灰盒、世界 / 认知核心和 OpenAI 小样本验证基础上，建立能继续开发的工程入口，给后续素材准备一个简单清单，并开始记录每次较大修改。

修改前工作区干净。功能分支基于现有 OpenAI 分支继续开发，该部分尚在 PR #1 中；本轮保留这项依赖，不提前合并 main / develop。

## 修改与关键决定

- 新增纯 C# `TownRuntime`，组合会话、规则对话、近期记忆、事件日志和维修任务；Unity 与命令行使用同一源码。
- 添加雨棚查看、拾取、出示证据、归还锤子的显式命令；交互检查地点与持有权，重复拾取被拒绝，重复证据不重复学习。
- 首条任务链为「归还锤子 → 阿木修长凳 → 60 分钟完成」；18:00 未完成则到期，用面板显示临时座位结局。
- 默认规则对话只读取当前 NPC 的快照；模型台词不调用动作。增加并发、等待暂停、版本校验、销毁取消与重开隔离。
- `TownGame` 自动附加离线 IMGUI 面板；玩家实际位置回报交互区域，重开时恢复玩家站位。点击面板不会触发点地移动。原灰盒场景、导航资产和材质未重新生成。
- 新增离线 Sandbox、12 项回归测试、正式素材分类目录、11 组素材条目、工程结构说明与准备清单。
- AGENTS.md 写入较大修改必须记日志的约定，并提供索引和模板。

## 限制与下一步

这是开发骨架，不是完整 15–20 分钟 Demo。正式 UI、NPC 日程 / 搬运、传播、关系与承诺、单槽存档 / 回放、B/C 记忆实验及正式模型游戏内接入仍待做。修好长凳目前改变规则和面板状态，未改变模型或播放维修动画。

下一步先在 Unity Play 验收现有导航和操作面板，再接角色卡配置与正式对话 UI；美术从一个角色 + 一件道具样板开始。阶段验收继续区分核心测试、Unity 导入、实际交互和真实模型调用。
