# 实施与轻量素材 v5

日期：2026-11-07。状态：**待确认的制作与验收方案，不是新增功能或采购授权。** 配套[玩法详细设计](未竟之镇_Demo详细设计_v5.md)、[AI 接入与实验规格](AI接入与实验规格_v5.md)。

## 1. 制作策略：小而完整，不是粗糙地堆系统

首版只做一个月光工坊—断鳞步道—安全月台的连续场景。一套光学组件、一套基础角色形体、三块重复地台即可覆盖主要研究。资源用于**可读的轮廓、空间、光路、操作反馈与状态一致性**，不先投入大量角色/怪物/建筑/复杂镜头。

低素材不意味着全部胶囊体加名字，也不等于模型资产必须实时生成。首版有意采用**纸偶小剧场/微缩魔法工坊**：角色用简洁纸偶，龙用远景剪影，魔法用实际可测的光学状态与少量表现。六类中的“生成式构造”生成组件/行为结构，不新增运行时图像、3D 或视频模型服务。

### 硬性制作上限（设计目标）

| 项目 | 首版上限 / 策略 |
| --- | --- |
| 地图 | 1 张连续小地图，约 24×18 米的起始假设，三主地台、两路线、一检修边道 |
| 场景 | 新 Demo 场景 1 个；旧 `Town_Graybox` 保留回归，不覆盖 |
| 自主角色 | 3 位；基础阶段只 1 位，漂流灯不是语言模型代理 |
| 独立美术件 | 目标 ≤12 类可复用网格/平面剪影，详见下一节；重复实例不另算新资产 |
| 角色动作 | 无面部、口型、复杂手部交接；程序位移/朝向/浮动/摆动，后续必要时补一组通用走路 |
| 特效 | 4 组可复用效果：月焰、光路线、符文状态、退墨边缘 |
| UI | 一个玩家 HUD、一组可复用卡片、一页因果结果；实验面板独立 |
| 音频 | 约 5 个短音效，可选 1 段低干扰环境循环；无配音、TTS 或音频生成接入 |
| 采购 | 首闭环 0 必购。确认后若确有瓶颈，再选一个小型基础包，不按旧候选表一次买齐 |

上限不是实际已经制作的数量。若首闭环确需增加物件，先说明它解决哪条验收缺口；不因“奇幻”二字扩成整只龙和全套生物骨骼。

## 2. 最小素材清单与复用方法

### 2.1 十二类以内的视觉基础件

| 编号 | 基础件 | 实例与改造 | 最小交付 / 不做什么 |
| --- | --- | --- | --- |
| A01 | 一块鳞片地台 | S/J/E、步道、边缘重排；稳定/退墨换状态 | 简单弧边低模或程序网格；不做蒙皮龙背 |
| A02 | 台架/锚座 | 工作台、光学台、路标座、安全灯架 | 同一支架缩放组合；不做整间精细工坊 |
| A03 | 龙角/远景剪影 | 背景平面或少量轮廓网格，配雾层 | 不可交互；不买整只战斗龙来放大 |
| A04 | 纸灯罩 | 月灯远景、三只漂流灯、造物外罩 | 同一模型/不同尺度；漂流用浮动/朝向 |
| A05 | 月焰芯 | 初始便携灯与当前造物的唯一光源 | 体积小、状态清楚；移动同一实体或显式转接，不复制光源资源 |
| A06 | 纸骨架 | 两个库存骨架与生成实例载体 | 简单环架；造物形状由部件摆布体现 |
| A07 | 棱镜 | 一件借物、分光实体 | 单一低模半透明体；用光路线表现功能，不追求真实折射着色 |
| A08 | 反光片 | 一件借物、反射实体 | 平面/薄片；不要依赖昂贵实时镜面反射 |
| A09 | 接线件 | 四件库存，按端口连线显示 | 少量网格加线段，不做软体绳索模拟 |
| A10 | 基础纸偶形体 | 玩家与三角色复用形体/比例/材质 | 保留名字与剪影，不需要四套独立骨架 |
| A11 | 角色饰片组 | 芬恩半影、梅芙披肩/蛾片、瑟恩枝角/甲片 | 同一小图集/平面拼片，最多一个打包饰片资源组 |
| A12 | 符文标识组 | A/B/L1/L2、边道、岗位、状态图形 | 一张小图集或程序线条，字体与图形分工 |

“类”是复用/制作预算，不将数百件独立资产压在一个目录下假称一类。实际导入按真实来源、许可证与文件登记，不能因为组合计数就省略授权。

### 2.2 色彩、光与层级

- 地台象牙白、背景灰紫，月焰银蓝、漂流灯暖金；警示不只用红色，要有形状与文字。
- 引擎光学判定独立于渲染：光束用线段/带状网格和有限发光材质即可；不需要大量实时灯、体积云或物理光线追踪。
- 此设计稿编写时工程为 Built-in；同日用户另行要求后，已独立完成 **URP 17.3.0 迁移**，见[日志 016](开发日志/2026-11-07_016_URP管线迁移.md)。Core 与渲染继续解耦，不同时引入多个复杂渲染包。该工程迁移不等于 v5 设计已确认，也不等于新月光/法术视觉已经实现。
- 功能与美术碰撞分开；呼吸晃动只作用装饰层。光学接收器/路径/NavMesh 不随全景镜头晃动偷偷变化。
- 关键反馈至少两通道：符文亮灭 + 图形、角色意图 + 方向/岗位、失败短句 + 指向对应对象。

### 2.3 必需音效与字体

最小五项：光源拿放/转接、试亮、符文有效/失效、队伍到达、潮息提示。环境循环可后补；无声开发可测规则，但正式体验验收不能宣称音效完成。

中文字体一套，覆盖角色名、材料与错误提示；检查许可与缺字。图标尽量自制线形，共约 10—12 个：材料、眼见/听说/假设、同意/等待/失败等。无需头像插画或卡牌美术套装。

### 2.4 台账与旧商品候选

现有 `art/asset-manifest.json` 与候选 CSV 保留事实，不批量改成已批准/已导入。v5 确认后再逐条标“复用/暂停/需新增”，有实物导入才填验收。生成或自制资产也登记作者/工具与许可条件，不因是占位就混进正式目录。

旧[商品页筛选](素材筛选_白龙月灯_v4.md)仅为可追溯参考，不作为本版采购清单。原先候选中的完整龙、精细女巫/鹿骨骨架与大型环境包不是前置条件；不删除此前用户工作的台账和 CSV。

| 类型化命令/Runtime | 保留统一入口、代际与异步拒旧包 | 增加有限能力命令/资源事务/条件状态，不允许模型任意写 WorldState |
| 单槽存档/回放 | 复用完整性、原子写、备份、离线重建思路 | 新协议覆盖对象图/同意/任务/回执；旧版本明确拒绝或显式迁移 |

新增只围绕当前闭环：光学与物料账、有限配方/功能图、条件约定、有界任务、机制候选适配、事件与回放。先具体实现，再抽公共接口。不预造通用知识图谱、全功能任务编辑器、可插拔模型市场、多代理编排平台或无限魔法系统。

建议以新的内容 ID/场景与规则版本隔离旧基线；实际目录/类名在实现时按仓库模式确定，不在文档里假称这些类已经存在。共用代码变更必须跑旧 100 项回归，结果以实际执行为准。

## 4. 分阶段实施与闸门

里程碑用 M 编号，六机制用 N 编号，避免混淆。不估未经验证的固定工期；按交付证据推进。

| 阶段 | 交付 | 必须看到的通过证据 | 明确停止 / 不进入下一阶段 |
| --- | --- | --- | --- |
| M0 确认与冻结 | 三份 v5、地图/材料/参数版本、六实验卡、权限清单；确认后归档旧稿 | 文档入口无冲突，模型/程序职责明确，地图可解性检查规格齐全 | 未确认先不归档/采购/改新在线权限；数值不自洽先修 |
| M1 无模型可操作样板 | 新单场景、搬灯/试亮、上下路、队伍、安全点、材料/组件预览 | 玩家亲手让光学/路线变化；预制样本完成分光和分批两种策略 | 只有标签/旗标变化，实际到达/光路不一致 |
| M2 第一 AI 闭环 | 单角色 N1/N2/N4、候选/澄清/条件、一次真实任务、最小记录/回放/预算 | 人工候选正反例、旧包/重复/同意冲突都拦；获准后 ≤3 请求小探测 | 只会解释到旧按钮、承诺不执行、权限/384-token 载荷不成立 |
| M3 六类窄切片 | N6 受限结构实体、N5 三角色局部后续、N3 一个公开事件目标；各自开关复位 | 每类有独立正反例与状态差别；逐类离线后申请小探测，不等全做完 | 生成只有换皮、GM 无可玩后续、自主只有固定日程 |
| M4 组合短局与品质 | 有证据的 2—3 类主机制、完整 HUD/结算、取消恢复/新存档、轻美术音效 | 一条跨机制因果链；新玩家看懂操作和结果，等待可取消 | 六机制强制串课、持续等待、同核心卡点不修 |
| M5 研究报告与去留 | 机制对照、实际模型失败/费用/等待、3—5 位诊断目标、取舍与下一问题 | 报告分技术/模型/体验，含负面结论，配置与记录可回放 | 只展示最好片段、全写成功或用旧测试证明新能力 |

M1 做预制结构仅为验证引擎，不把它记作模型造物。M2 就开始最小记录与用户反馈，不等 M4 才补可观测性。真实模型探测在每类可离线执行后尽早进行，但没有额外授权就停在线闸门前，继续离线不会伪报模型能力。

## 5. 逐层验收清单与责任

实施者负责自动/场景证据；研究评审负责合法多解与原生贡献判断；未读方案的玩家负责体验诊断。初期同一人可兼任前两项，但报告披露，争议样本尽量另请复核。用户负责设计/新增权限/费用批次确认，不默认把每个游戏判断都交给用户。

### 5.1 Core 与协议（离线，必做）

- 地图策略：普通灯不能从合法站位照齐 A/B；有效分光可照齐；上下路均有可解配置。
- 物料守恒：只有一芯、借物所有权、预留竞争、拆装不复制、无效拓扑/循环供能拒绝。
- 条件与任务：各自同意、三步上限、安全撤回、角色只在合法岗位支援，预检失败不扣窗口。
- 观察与来源：实到/实见才亲历，复制证词仍同源，私下消息不自动公开。
- 六卡至少 18 人工候选与公共工程反例，不能计为模型成功样本。
- 异步/存档：旧包/取消/重复零落地，回放 0 网络，新状态一致，旧存档明确版本边界。
- 预算：全局串行、跨进程账本、失败计次、无自动重试，密钥不会进入数据。

必须执行 `dotnet test dotnet/Town.sln --configuration Release`。新测试数量由行为覆盖决定，不以凑某个漂亮总数代替证据。

### 5.2 Unity 空间与操作（不调用模型）

| 场景证据 | 必须观察 |
| --- | --- |
| 光学样板 | 物体朝向改变光路；遮挡、分光、符文输入与实际反馈一致 |
| 两条通路 | 真走到才完成；光丢失到安全点停止，不假到达、不从检修边道偷运对象 |
| 队伍 | 两/四名容量、岗位真实到位、两批接续；三只漂流灯不互相卡死 |
| 构造 | 至少两种候选图产生不同实际功能；无效预览不扣材，失败不残留半功能对象 |
| 交互焦点 | 输入框/配方卡不穿透移动；Esc 取消；等待/暂停/读档不漂移 |
| 新存档 | 位置、灯图、材料、借物、约定、任务与窗口恢复；不重复调用模型 |
| 轻美术 | 1280×720/1920×1080 可读，三角色剪影/关键状态不只靠名字或颜色 |

同场景配置由 Unity CLI/测试控制，截图/录像说明固定初态与结果。瞬移只作准备，不算完成一条真实路径；编译不等于这一层通过。

### 5.3 模型与真人

模型按[实验规格 §8](AI接入与实验规格_v5.md#8-六张机制实验卡)分批；真实请求由本轮具体授权决定，不沿用设计批准自动调用。真人按[实验规格 §9](AI接入与实验规格_v5.md#9-三种比较必须分开)诊断；旧离线/回放体验不可冒充实时模型体验。

首个可分享短局不是必须证明六类全部可靠；必须诚实说明每项的完成状态、运行模式与限制。某机制探索失败也可形成研究产物，但不能把失败切片藏掉后报告全覆盖。

## 6. 风险与应对优先级

| 风险 | 早期观察 | 优先做什么 |
| --- | --- | --- |
| AI 只是灯光谜题的聊天附属 | 固定路线和 AI 路线只差台词 | 测保留方法/条件/构型；若无实质差别，限制原生宣称或重设计 |
| 玩法像搬运作业 | 玩家只走两趟，不试光、不协商、不改构型 | 缩短距离，突出试验/路线差异；不靠加搬运对象延长时长 |
| 规则多到背不动 | 先读材料表才敢操作 | 先即时小试验，渐进显示相关条件，非相关世界法则不强塞 |
| 三角色调用过多 | 一个简单同意链占满预算 | 一位先跑、各次职责缩短、常用操作无模型；依据轨迹申请预算，不偷跑 |
| 384 tokens 装不下构型 | 高频截断/坏结构 | 缩字段/图上限/单次职责；仍不足提出显式调整，不自动加额 |
| 护送执行与 Core 脱节 | 宣布完成但角色还在路上 | 先打通到达/失败回执和安全点，后做复杂自主 |
| 低素材变廉价 | 角色/部件难分、魔法只靠文字 | 优先剪影、光路、图形状态、音效与焦点；不是买大包遮盖 |
| GM 偷偷全知 | 私约/未发生内容进旁白 | 专用公开投影、事件引用/对象验证；未批准不在线 |
| 不断换方案拖延 | 再写新故事却没有一个可操作闭环 | v5 确认后先 M1/M2，变更记录理由/影响，不再平行多套“最新” |

## 7. 确认与变更机制

### 7.1 本版待确认的设计决定

1. 采用一张轻量龙背地图与“送芬恩和三只漂流灯过断鳞”的短局，不先完整献灯首章。
2. 首版核心魔法聚焦光路/灯具结构，暂不做动态影桥、任意造景或动作战斗。
3. 六类都有独立研究入口，游玩只选有价值的组合；基线可通关，原生贡献另行检验。
4. 十二类以内复用视觉件、纸偶角色与远景剪影，0 必购起步，不等复杂美术再验证。
5. 按 M0—M5 和逐层证据推进；确认后旧稿归入 `docs/history/`，不改现行安全与成本规范。

这五项是设计确认，不是价格/新模型视图/动作权限审批。普通设计参数可在可解性/试玩后调整，但冻结场景版本用于实验；新增能力、费用上限或信息权限要独立记录并获准。
