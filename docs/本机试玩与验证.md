# 龙眠镇本机试玩与验证

本页针对 Unity 6000.3.23f1 / macOS 的离线试玩，不代表对外发行版本。主场景依赖本机已导入的商业环境、人物、龙和 UI；这些素材及 `.app` 不上传到仓库，不在许可尚未核实前再分发。

## 构建

先退出占用本工程的 Unity Editor；不要同时运行 PlayMode 测试或另一个构建。以下入口只读取既有主场景，不自动重建场景、不安装 Unity 模块，也不主动写 PlayerSettings / Build Settings。Unity / URP 本身可能生成缓存和序列化设置，构建后须检查 Git 状态，只恢复确认属于本次构建的生成差异，不覆盖别人的改动：

```bash
ROOT="/Users/sanwuwei/ai native项目-小镇"
UNITY="/Applications/Unity/Hub/Editor/6000.3.23f1/Unity.app/Contents/MacOS/Unity"
mkdir -p "$ROOT/.local/builds"

"$UNITY" -batchmode -projectPath "$ROOT/unity" -buildTarget StandaloneOSX \
  -executeMethod Town.Editor.DragonsleepPlayerBuild.BuildMacOs -quit \
  -logFile "$ROOT/.local/builds/Dragonsleep-build.log"
```

`.local/builds/` 保存带时间和随机后缀的新 `.app` 与同名 `.build.json`，不会覆盖旧包。以摘要中的 `result`、`buildResult`、错误数以及进程退出码共同判断结果；没有成功摘要不能称为构建成功。主场景缺失时先按 [README](../README.md) 准备本机素材与场景，不用空场景冒充成功。

按用户要求，新包实际验证通过后及时清理被替代的旧 `.app`，保留最新已验证包；构建摘要、测试日志与回放证据继续保留，不把清包扩成删除 `.local/`、商业源素材或玩家存档。下文历史包名是证据标识，不保证旧二进制仍留在本机。

2026-11-09 本机已实际构建并启动验证：`Dragonsleep-macOS-local-20261109-132840-229b05fb.app`，约 3.12 GB，构建 0 错误 / 57 警告，显式 Player 冒烟通过。该包不是对外发行版本；具体证据见 045 日志。

## 启动与操作

打开成功构建的 `.app`；点击开场“启程”后进入游戏。默认使用离线 `RuleProvider`，启动不请求 OpenAI，不需要密钥，不会自动规划或执行。

- WASD 移动，Shift 疾行；右键拖动、Q/E 和滚轮控制镜头。
- Enter 聚焦输入；“言 / 行 / 造”分别对应交谈、行动和造物。
- P 打开归巢计划：提出目标、选择取舍、确认后**逐步执行**；重规划仍需重新确认。它不是自动通关按钮。
- “合作条件”默认未限定；旧三项允许名单仍只限制计划 `confide`，只向某人不等于必须求助。新增 v2“独行 / 必须梅伦 / 必须皮普”同时约束原件交付和实际合作目标；改下拉草稿需重新提出，条件随本次目标和重规划冻结。两版都不拦截另行输入或居民流言，不代表全局保密。
- 当前规则 7：梅伦可以接受契约原件保管核验作为另一条合作资格；交付后玩家不再持有原件，不能继续向总管出示，仍须另一步托付才会结盟。重复出示契约不再刷信任；计划只是条件性试运行，真正是否合作以实际回执为准。
- M 打开地图与结束时段，J 查看手记，Tab 查看规则回执。计划请求在途时可请求取消，但须等原请求真正结束才能继续；执行步骤已有的后果不会回滚。
- 结局卡可“查看现场”，底栏“结局”可重新打开卡片再来一局。终局不再允许地图传送；现场镜头不改变玩家、雏龙或结局的规则状态。
- 雏龙、母龙复用现有模型；卫兵岗位、铁笼、斗篷包裹是明确登记的灰盒占位，不是正式资产验收。

Player 的轨迹写入 `Application.persistentDataPath/dragonsleep/traces/`，不尝试写入 `.app` 或把构建包附近当作仓库。该目录与历史 `unfinished-town/` 存档无关，不删除历史玩家数据。

## 显式启动冒烟

下面仅证明实际构建能够加载主场景、离线会话、角色和必要 UI，**不证明完整玩法、真人手感、性能或视觉质量**。正常启动不传这些参数，就不会运行冒烟或自动退出。

```bash
APP="成功构建摘要中 outputPath 的绝对路径"
BIN="$(/usr/libexec/PlistBuddy -c 'Print :CFBundleExecutable' "$APP/Contents/Info.plist")"

"$APP/Contents/MacOS/$BIN" \
  --dragonsleep-smoke --dragonsleep-smoke-output "$ROOT/.local/builds/player-smoke-new.json" \
  -screen-fullscreen 0 -screen-width 1600 -screen-height 900 \
  -logFile "$ROOT/.local/builds/Dragonsleep-player-smoke.log"
```

输出必须是尚不存在的绝对本地 JSON 路径，父目录先存在；不要加 `-nographics`，否则无法证明 UI 布局。退出码 0 且摘要 `passed: true` 才是通过；1 表示验证失败，2 表示参数或摘要写入失败。

## 证据边界

- 规则正确性：离线 .NET、黄金快照与两组研究统计。

```bash
"$APP/Contents/MacOS/$BIN" \
  --dragonsleep-journey --dragonsleep-journey-output "$ROOT/.local/builds/player-journey-new.json" \
  -screen-fullscreen 0 -screen-width 1600 -screen-height 1000 \
  -logFile "$ROOT/.local/builds/Dragonsleep-player-journey.log"
```

- 输出须是父目录已存在、尚不存在的绝对本地 JSON 文件；成功退出 0 且摘要 `passed: true`，检查失败退出 1，参数或摘要输出失败退出 2。
- 使用实际默认 `RuleProvider`；只固定起点种子 `7932`，其余资源、信任、认知、时间和雏龙状态不修改。最多 120 次计划状态推进、10 次规划、180 秒，不能无限重试。
- 验证启程、目标、显式取舍、确认、一次执行一步、真实执行失败后作废 / 重规划 / 再确认、团聚结局、查看现场、重开和第二次提案。规划与确认不能改变世界；已经执行的历史不能在重规划时消失。

## 规则 7 的显式社会夹具

在完整短局命令中增加 `--dragonsleep-journey-social`，使用新输出文件；不能同时加 `--dragonsleep-journey-private`。单独传 social 参数不启动验证器。

它会明确设置大教堂、持有原件、梅伦信任 0.05、已遮盖跟随及相应玩家知识，固定安全骰序种子 109；**不是从新局取得原件或完整归巢验证**。其余全程使用实际默认离线提供方和 UI 按钮：出示 → 实际托付拒绝 → 重规划 → 再确认 → 交付原件 → 再托付。确认前原件不转移，交付本身不自动结盟。

规则 7 当前回放仅接受同版本录制；旧规则 6 原始工件保留但不会跨版执行。实际版本升级、自动测试、社会夹具两分辨率、默认 / 受限完整短局与启动冒烟见 [048 日志](开发日志/2026-11-10_048_规则七原件保管与低信任补救.md)，黄金与离线 90 / 27 局逐项差异见[迁移对照](规则7黄金迁移与离线对照.md)。不把离线改善写成真实模型成绩。

## SDK 地图接缝的显式验证

在上方 `--dragonsleep-journey` 命令后增加 `--dragonsleep-journey-scene`，使用新的 JSON / 日志路径；不能与 private / social 模式混用，单独 scene 参数不会自动启动。该模式从默认离线新局启程，实际点地图去工坊、回集市，要求两次 SDK committed 与宿主回执前后摘要相同、只增长两个世界版本、不消耗时间、模型调用 0。

它只验玩家场景移动，不执行计划、夜间或团聚；不能拿它的世界 hash 与完整短局终局相比较。正常运行只有玩家实际走入 / 地图前往新地点才触发这条接缝，不会自动行走。契约见[首条场景事务](PieGame首条场景事务接入.md)，最终包与运行证据见[051 日志](开发日志/2026-11-10_051_PieGame首条真实场景事务接入.md)。

## v2 合作夹具与 SDK 日间验证

在 `--dragonsleep-journey` 后分别增加以下一种模式，输出使用尚不存在的新文件；不能与 private / social / scene 或其他验证模式混用，单独附加模式参数不会启动验证器。

- `--dragonsleep-journey-cooperation=solo`：明确独行，禁止计划 confide 与契约原件 give。
- `--dragonsleep-journey-cooperation=maren`：必须实际 `ally:maren` 且团聚；允许但不强制交原件给梅伦。
- `--dragonsleep-journey-cooperation=pip`：必须实际 `ally:pip` 且团聚，不授权交出原件。
- `--dragonsleep-journey-day`：真实行动输入“观察”先消耗 2 点，再点击地图结束时段两次，核日间 SDK 同次提交世界和 spent。只验证清晨→正午→黄昏，不冒充夜间或计划已迁移。

合作模式明确设置 `pact_escort` 对应的码头跟随 / 遮盖、原件持有和玩家知识，固定种子 `253421`，不设置盟友；**不是从全新局获得这些资源的证明**。三种模式经真实 UI 提出、确认、逐步执行到实际合作与团聚，不能用摘要或预测代替实际状态。日间模式从默认新局开始，零规划调用；场景和日间契约分别见[首入口](PieGame首条场景事务接入.md)、[日间入口](PieGame日间原子事务接入.md)。

最新保留的已验证本机包为 `Dragonsleep-macOS-local-20261110-092244-9bda2775.app`：默认完整局、受限完整局、社会前缀两分辨率、地图两分辨率、冒烟、三种合作夹具和日间两分辨率共 **12 次实际运行通过**；构建 0 错误 / 57 警告。完整记录见 [052](开发日志/2026-11-10_052_合作意图正向目标与有限真实复验.md)、[053](开发日志/2026-11-10_053_PieGame日间世界与时间原子提交.md)。旧包替换后只清理 `.app`，不清理历史证据。
