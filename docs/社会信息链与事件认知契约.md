# rules-9 社会信息链与事件认知契约

版本：`dragonsleep-rules-9`　日期：2026-11-16

本文定义 rules-9 中“规则实际发生的事件”如何进入居民本人认知，以及居民如何在有限范围内转述认知。它不把模型台词、玩家自述或世界真值当作已发生事件。

## 1. 版本、回滚与证据边界

- 当前规则版本为 `dragonsleep-rules-9`。rules-6、rules-7、rules-8 的黄金文件和原始字节不改写；旧版本回放不能通过当前规则版本门禁。
- 事件认知在候选世界中由规则成功路径生成，只有候选世界通过 Commit 后才进入正式世界、快照、差分和回放。Prepare 失败、拒绝或 stale commit 不留下事件认知。
- 普通自由对话没有“玩家说过的结构化事实”字段，因此普通 `say` 不新增居民事件记忆。现有结构化 `confide` 仍按原规则产生护送计划认知；本契约不把自然语言对话文本提升为事实。
- 居民感知只发送当前居民自己的 beliefs；`RootOwner`、`True` 等内部校验字段不发送给其他居民，也不通过玩家裁剪视图泄露。

## 2. 事件到认知

事件只来自成功提交的规则效果。当前同一地点的居民均按“在场目击者”处理；不在该地点的居民不获得该事件认知。该范围沿用当前同地点可见规则，不扫描异地居民状态。

| 规则事件 | 触发条件 | 认知主题与内容边界 |
| --- | --- | --- |
| 交付 `give` | 物品实际从玩家移动到目标并提交成功 | `event:give`。包含实际交付；契约原件交给梅伦时明确记录“保管核验、不是护送托付、不会自动结盟”。 |
| 取回 `take` | 物品实际从居民处取回并提交成功 | `event:take`。原件取回时记录保管关系/同行盟友的实际撤销；失败不生成。 |
| 出示 `show` | 出示动作实际提交成功 | `event:show`。首次和重复出示都可留下实际出示记录；重复出示不重复增加信任或重复设置首次出示标记。 |
| 本地岗哨观察 | 居民在本人所在地点、当前时刻发生本地岗位观察 | `event:guard`。只描述“此时此地看见/未看见岗位”，不描述异地岗位、未来安全性或隐藏裁决原因。 |

岗位观察在玩家实际进入地点、阶段开始以及居民移动/守卫规则路径中生成，但不扩大 rules-8 的玩家 `guards_here` 范围，也不把一次观察传播为异地知识。

事件认知的 `Owner` 必须是目击居民；`RootId` 为该事件认知自身，`RootOwner` 为目击居民，`Hops=0`，`True=true`，`RevealTrust=0`，来源为 `seen:event:<topic>`。事件文本带当前时刻，避免把历史保管或岗位状态表达成永恒当前状态。

## 3. 认知字段与保留

每条 `DsBelief` 除原有字段外，包含：

- `RootId`：最初事实的认知 ID；
- `RootOwner`：最初事实的居民所有者，用于防止信息回传；
- `Hops`：从根认知经过居民转述的跳数；
- `Source`：`seen:event:*`、`seen` 或 `told:<speaker>` 等来源摘要。

每个居民、每个事件主题最多保留最近 **2** 条观察/传播认知；亲历事件与该事件的传播认知共用上限，超出时删除最旧条目。根条目被淘汰后仍保留 `RootOwner`，因此淘汰不会解除防回传约束。当前实测模型请求体最大 **3,642 bytes**，低于 `12,288 bytes` 上限。

旧快照若缺少新字段，恢复时按兼容规则补全：无 `@` 的 ID 为 `Hops=0`，带一个 `@` 的旧传播 ID 为 `Hops=1`；根 ID 和根所有者从可用根记录或零跳所有者推导。新快照写出完整字段。

## 4. 转述边界

允许的信息链只有：

```text
亲历事实（0） → A 听到并持有（1） → B 听到 A 转述（2）
```

- `Hops >= 2` 再转述必须拒绝，原因码为 `hearsay_too_far`。
- 听者已经持有相同 `RootId` 时不新增认知，原因码为 `already_known`。
- 不能把认知传回 `RootOwner`，原因码为 `hearsay_to_origin`。
- speaker 只能转述自己持有的认知；试图转述其他居民私有认知，原因码为 `cannot_relay_others_belief`。
- 同一根认知不因 ID 是否包含 `@` 而决定跳数；`RootId`、`RootOwner`、`Hops` 是权威字段。
- 每次成功转述将 `RevealTrust` 减半，最低为 `0.1`；`True` 原样继承，不能通过转述把未知内容变成真值。
- 成功转述生成 `Source=told:<speaker>`、继承根字段并使 `Hops` 加一；文本明确包含实际转述链。

若选择中只有部分认知可转述，结果为 `Partial`，原因码为 `partial_hearsay`，呈现内容只列实际成功转出的认知。若零条可转述，结果必须为非 Accepted，并使用具体首个原因码或 `no_beliefs_selected`；不得增加关系、不得呈现“已经说了些什么”。规则拒绝的时间消耗沿用原 rules-8 语义。

## 5. 隐私、回放与验证

- 事件生成读取的是成功规则候选的实际变更，不读取完整世界真值、不解析模型叙述、不采信玩家自述。
- 玩家视图只能看到玩家可见场景；居民对话/自主任务视图只包含本人认知。不同居民的私有差分不得出现在彼此请求中。
- 事件认知参与世界快照 Hash/Diff、规则回执和严格回放；因此 stale、重复提交、拒绝分支不能产生幽灵认知。
- 验收证据保存在本机 `.local/four-mechanisms-rules9/social-chain/`，不把私有世界或模型原文写入本契约或 Git。

本契约对应的有限证据包括：二跳成功、第三跳拒绝、去重/防回传、Partial 与实际呈现、give/take/show 和本地岗哨目击者范围、旧快照补字段、每类上限、其他居民视图隐私、冻结 payload、严格回放，以及 14 例 rules-9 社会链有限真实批。它不宣称长期社会传播、三夜 GM 稳定性、M3 整体通过或真人体验通过。
