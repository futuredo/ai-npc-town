## 运行

默认离线：规划由离线基线完成，居民和 GM 也走离线规则。

```bash
dotnet run --project dotnet/Town.Research --configuration Release -- --plan --seeds=10
```

```bash
dotnet run --project dotnet/Town.Research --configuration Release -- --plan --holdout --seeds=3
```

M3 真实实验需要显式加 `--live`。即使联网，也只有**计划请求**会走 `gpt-6-luna`，居民和 GM 仍走离线规则，这样差异可以归因到规划者。联网时按 AGENTS.md 的研究授权执行：单并发、无自动重试，输出不超过 768 tokens，每次请求都记账。

## 指标与口径

- **首个计划可执行**：结构、引用通过，且默认选择在试运行中可依次执行。“团聚”单独记录，不并入可执行。
- **无效引用**：引用了玩家未知的事实、物件或规律，或不存在的对象，会被拦截并计数。`invalidCommitted` 统计含无效引用、却被确认执行的计划数，要求为 0。
- **三类失败**：
  - 前置条件：掷骰前被规则拒绝，世界不变；
  - 执行失败：掷骰失败、被巡逻发现或受惊逃走，后果已写入世界；
  - 世界已变：两步之间出现玩家可察觉、且影响计划的变化，剩余步骤作废。
- **重规划可执行率**：分类统计。研究报告另按世界真值标出“已无路可走”的重规划，例如雏龙已被商人带走、或者来不及在终局前赶到。这类情况与“可补救情形”分开计算。这一标注只用于分析，不进入模型输入。
- **回执一致**：
  - 成功的步骤，所有回执都是 committed 或 no_change；
  - 失败的步骤，至少有一份执行回执；
  - 作废的步骤，没有行动回执。
- **延迟**：每次规划调用端到端耗时的中位数和 P95。离线数值只反映本地规则开销，不代表模型等待时间。
