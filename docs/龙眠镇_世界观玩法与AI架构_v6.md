## 1. 一句话

> 三百年前，龙眠镇的骑士屠了一条龙，把它的头骨立在山岗上当战利品。三天前，大教堂墓穴里供奉的“石化龙蛋”孵化了。雏龙逃进了镇子，而它的母亲——苍穹之母——已经在雪峰上盘旋。**第三个黎明，她会降落。**
>
> 你是途经此地的**言契师**：你说出口的话会被古老的“织言机”听见并织进现实。整个镇子都想利用你；你要决定这条小龙、这座镇子和那份被遗忘的契约的命运。

题材关键词：风格化童话王国、龙、三日倒计时、谜案、阵营博弈、开放言语行动。

### 2.2 核心设定

- **织言机（The Loom）**：教堂地下的古老机关，能“听见”人的意图并让它在世界中成真——前提是符合世界的规律。它就是游戏里 AI 的**叙事外壳**：玩家看到的“织言镜”界面，就是在看织言机如何理解、判断和执行。
- **龙契**：三百年前，母龙并没有被杀死。被杀的是她的配偶；她与镇子立约：镇子守护她留下的蛋，她不再复仇。契约页后来被教会撕下藏起，镇民只记得“屠龙”的荣耀。
- **铁与余烬**：龙厌恶冷铁；龙辨认亲族靠“余烬气味”。这两条是全局可被玩家发现并利用的**规律**，语义判定会依据它们。

## 3. 核心玩法

### 3.1 循环（一局约 25—40 分钟）

```
三天 × 四个时段（晨/午/暮/夜）= 12 个时段
每个时段：自由走动 → 对人说 / 对世界做（开放输入）→ 消耗时间 →
夜晚：所有居民自主行动一轮（多智能体），GM 安排征兆
第三个黎明：母龙降临，按世界真实状态审判 → 多结局
```

玩家没有“按 E 选选项”的对话树。交互只有两种动词入口，都接受开放文本：

- **【言】对某人说**：盘问、说服、威胁、交易、许诺、撒谎。
- **【行】对世界做**：任何身体行动（“把熏鱼撒在船屋台阶上”“趁卫兵换岗溜进库房”“把契约页贴在广场告示板”）。

### 3.2 六类 AI 机制在本作中的落点

论文把 AI 原生机制分为 N1—N6。本作每一类都对应一个**离开 AI 就无法成立**的玩法：

| 机制 | 本作玩法 | 规则层产物（不是台词） |
| --- | --- | --- |
| N1 认知交互 | 盘问五名居民，拼出“谁搬走了蛋、雏龙在哪、契约是什么” | 回答必须引用该角色**自己的**认知条目；玩家获得的线索写入玩家认知库 |
| N2 社会影响 | 说服梅伦交出契约页、和维丝娜讨价还价、骗过奥斯里克 | 模型输出“立场变化提案+理由+引用的动机”，规则按角色价值观限幅，写入关系/承诺账本 |
| N3 生成叙事 / AI GM | “龙母之心”导演：根据张力曲线安排征兆（雪崩、乌鸦、龙吼、卫兵搜查） | GM 只能从有界事件语法中组合事件，并受节奏预算约束 |
| N4 语义判定 | 【行】的开放输入被理解为“动词+对象+方法”，按世界规律判定可行性/难度/后果 | 结构化行动提案 → 前置条件检查 → 种子化掷骰 → 世界差分 |
| N5 多智能体 | 夜间五名居民各自规划并执行行动；流言在居民间传播；行动可能互相冲突 | 每人一个行动提案，冲突由引擎统一结算，结果写入事件日志 |
| N6 生成式构造 | 在附魔工坊用手里的材料描述并“织造”新物件（例：“混着熏鱼烟和余烬灰的哨子”） | 模型产出物件定义：名称、外观、**有界效果标签**、消耗；规则核算成本后物件真实进入背包，可被后续判定使用 |

### 3.3 一个完整片段（设计样例）

1. 玩家对玛尔妲【言】：“最近厨房丢过东西吗？”→ N1：她引用认知 `marta_saw_pip_docks`，提到皮普和冒烟的毯子。
2. 玩家去码头，对皮普【言】：“我不是来抓它的，我是来帮它回家的。”→ N2：皮普信任 +，但规则限制“初次见面无法完全信任”，他只承认“有个朋友”。
3. 玩家【行】：“把从玛尔妲那买来的熏鱼放在船屋门口，退到栈桥尽头等。”→ N4：判定引用规律“雏龙爱吃熏鱼”，前置“持有熏鱼”通过，结果：小烬探出头，**世界状态**`whelp.visible=true`。
4. 夜晚 → N5：玛尔妲向维丝娜抱怨“码头那个孩子”，维丝娜获得线索；她雇的偷猎者第二天出现在码头。
5. GM（N3）判断张力不足，安排“雪峰传来龙吼”，所有居民恐惧上升，奥斯里克提前搜城。
6. 玩家在工坊【造】一个“余烬哨”（N6），在终局时用来让母龙辨认亲族。
7. 第三个黎明：母龙审判。结局不由旁白宣布，而由世界状态计算：雏龙是否安全、契约是否公开、谁伤害过它、玩家许诺是否兑现。

### 3.4 结局（由状态组合，不是固定分支）

- **归巢**：雏龙与母龙团聚，契约公开 → 镇子重获龙的庇护。
- **铁笼**：雏龙被关在王城 → 母龙焚城（可在最后时刻翻盘）。
- **远洋**：维丝娜得手 → 母龙追向海面，镇子幸存但失去庇护。
- **新约**：玩家促成镇民当众重立契约 → 隐藏结局。

## 4. AI 原生架构

### 4.1 设计原则

1. **AI 只提案，规则落地。** 模型永远不能直接改世界；所有输出都是结构化提案，规则引擎决定是否、如何执行。
2. **感知分区。** 每次调用只发送该角色的 `PerceptionView`（自己的认知、看得见的东西、自己的动机），绝不发送世界真值或他人私有认知。
3. **一切可见、可回放、可比较。** 每次调用生成一条 `AiTrace`，记录完整链路；研究录制帧可以离线执行回放（不包含 Unity 物理/动画），并可替换提供方（规则/录制/真实模型）做对比实验。
4. **默认零费用。** 默认提供方是离线的规则/录制提供方；真实模型须显式开启，并沿用现有预算账本（标准对话每轮 3 次、每日 20 次；本轮获授权的六机制研究不设总费用上限）。

### 4.2 统一管线（六类机制共用）

```
玩家/居民/GM 意图
   │
   ▼
① Context 组装   ── 感知分区：PerceptionView + 可用动词/物件/规律
   ▼
② Prompt 组装    ── 分段：角色卡 / 认知 / 规则摘要 / 输出 schema / 玩家输入（标记为数据）
   ▼
③ Provider 调用  ── Rule(离线) | Replay(录制) | OpenAI(gpt-6-luna, 预算闸门)
   ▼
④ 解析与校验     ── JSON schema → 引用归属 → 实体存在 → 动词白名单 → 数值限幅
   ▼
⑤ 规则裁决       ── 前置条件、种子化判定、冲突结算
   ▼
⑥ 世界提交       ── WorldDiff（版本号 + 旧局保护 + 去重）
   ▼
⑦ 回执与表现     ── 台词/动画/特效 + AiTrace → 织言镜
```

每一阶段都可能失败，失败原因有固定枚举（`schema_invalid`、`citation_not_owned`、`unknown_entity`、`verb_not_allowed`、`precondition_failed`、`budget_exhausted`、`stale_session` 等），失败也进入 trace 并对玩家给出可理解的反馈（“织言机没听懂”“这件事做不到，因为……”）。

### 4.3 关键数据结构（`Town.Core/Dragonsleep`，Unity 与 .NET 共用）

| 类型 | 用途 |
| --- | --- |
| `AiTaskKind` | Dialogue(N1/N2) / Adjudicate(N4) / AgentPlan(N5) / Direct(N3) / Craft(N6) |
| `PerceptionView` | 单角色可见信息快照，带每条认知 ID |
| `PromptPacket` | 分段提示词，记录每段字符数，便于研究“哪段上下文起作用” |
| `AiProposal` | 统一提案：`say` 台词、`cites` 引用、`intent` 动词+对象+方法、`stance` 立场变化、`craft` 物件定义、`event` GM 事件 |
| `Verdict` | 规则裁决：接受/部分/拒绝 + 原因 + 掷骰 |
| `WorldDiff` | 本次提交的世界改动列表 |
| `AiTrace` | 上述全部 + 提供方、耗时、token、估算费用、阶段时间戳 |

### 4.4 织言镜（游戏内 AI 可视化）

界面分三栏，可在游戏中随时展开：

- **左·线轴**：本局所有 AI 调用的时间线，按机制着色（N1—N6），失败的线是断的。
- **中·织机**：当前调用的七个阶段依次点亮；可展开看发送给模型的分段上下文、原始返回、每条校验结果。
- **右·落针**：规则裁决和世界差分，例如 `whelp.hunger 0.8→0.3`、`pip.trust +0.2（上限 +0.25）`。

研究导出：每局写 `AiTrace` JSONL 到 `.local/dragonsleep/traces/`，可统计有效率、拒绝类别、延迟、token、估算费用，并支持“同一局、换提供方重放”。
