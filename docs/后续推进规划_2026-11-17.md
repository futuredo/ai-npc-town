## 3｜架构问题（按严重度）

### A1 双提交路径，迁移停在一半（最高）
Kernel Begin/Prepare/Commit 与旧 `RunAsync → DsExecutor` 并存，去重、回执、回放语义两套；Unity 无严格回放入口。每个新功能都要先决定走哪条路。
**需要决策**：全量迁移（排期）或冻结内核边界（明确只覆盖三入口并写入契约），二选一，不要继续“顺手迁一点”。

### A2 `DragonsleepSession` 职责过载 + 版本组合膨胀
`DragonsleepSession.cs` 863 行，持有世界、门锁、Trace、规则事件、待确认造物、行动记忆、owner 调度、时段推进。`ActAsync` 以可选字符串参数传提示 / 感知版本并在运行时校验组合。版本维度：提示 v1/v2/v3 × 感知 v1/v2 × rules-6～9 × 是否事务。
**建议**：版本收拢为不可变 `DsRunProfile`；制定退役规则（旧规则版本仅保留黄金回放、不再运行时可选）；按职责拆出行动记忆、造物待槽、规则事件日志、时段推进。

### A3 研究代码按实验复制增长
`Town.Research` 4.6k 行，接近 Core 6.2k 行；`ActionKernelResearch.{Focus,FocusTransfer,Memory,Semantics,Transfer}`、`ActionV3ProductionResearch` 等每轮一个文件。
**建议**：通用 runner + JSON 套件定义（案例、种子、对照臂、预注册门槛、统计口径），新实验只写数据。

### A4 已登记技术债（里程碑交界处理）
感知与提案弱类型（`RunStepAsync(Dictionary<string,object>)`、冻结 JSON）；逻辑依赖中文文案（公开新闻搜城筛选、库存描述）；内容硬编码于 `DsContent.cs`。设计已在[感知迁移](感知视图类型化迁移建议.md)与[内容数据化](内容数据驱动建议.md)。

### A5 SDK 抽离：保持现判断
仅龙眠镇 + ToyHost，第二个真实宿主出现前不冻结公开 API。

### A6 工程杂项
`.local/` 约 15G，其中 `builds/` 约 12G；[项目进度](项目进度.md)为逐段追加流水，难以看清当前状态。

## 4｜方法论问题：样本量与门槛

同一 v3 候选 068 为 48/48、074 为 41/48。n=48、成功率 85%～90% 时 95% 置信区间约 ±10 个百分点，44/48 门槛落在噪声内；v2 vs v3 若真实差异 3～5 个百分点，需要每臂数百样本才能分辨。每 48 次请求费用约估算 USD 0.003，样本量不是成本瓶颈。

**建议口径**（需用户确认后写入治理文档）：
1. 预注册：套件、种子、样本量、主指标、门槛、停止条件在联网前落盘。
2. 样本量按预期效应量计算（功效 0.8、α=0.05），报告 Wilson 区间；版本比较用配对同题设计与配对检验（McNemar）。
3. 晋升门槛写成“下界 ≥ X”或“相对基线不劣于 δ”，不用单点计数。
4. 冻结集与调参集分开；不重抽、不补跑失败。
5. 关键探针单独门槛，不被总分掩盖。
