## 现行结构

```text
unity/
  Assets/Town.Core/Dragonsleep/       纯 C# 世界、规则、计划、回放
  Assets/Town.OpenAI/                线上提供方与费用 / 授权边界
  Assets/Town.Unity/                 输入、表现、HUD 与宿主适配
  Assets/Town.Editor/                场景生成、构建与本机工具
  Assets/Town.Tests.PlayMode/        真实游戏场景集成回归
  Assets/PieGame.AI.Kernel/          独立内核
  Assets/PieGame.AI.Unity/           生命周期桥与所有者线程调度

  Assets/Town.Content/              收纳约定与实际使用的 UI 资源，未实现内容加载器
  Assets/LocalThirdParty/           本机商业素材和派生主场景，不随 Git 分发
  Packages/、ProjectSettings/       工程依赖和受控设置
  Library/                         当前导入 / 编译热缓存，不是源码
dotnet/                            编译上述同一批核心源码，另含离线测试和研究宿主

.local/                            本机证据、唯一验证包、临时工具与工作产物
```

`dotnet/` 不是一份需要删除的重复游戏实现。`Town.Core`、`Town.OpenAI` 和 `PieGame.AI.Kernel` 的 csproj 用通配符直接编译 `unity/Assets` 源码。当前 PieGame 的两条 Kernel 权威入口、Session owner 调度和旧宿主执行器各有明确作用，不能按名称相似将其当作重复代码删除；边界见[工程骨架](工程骨架说明.md)。

## 审查后仍存在的架构边界

1. 主场景与商业派生内容被忽略，单独 Git 检出不能恢复完整画面；需保留合法来源和明确的本机恢复过程。
2. 内容大多仍在 C#，`Town.Content` 不是已经完成的数据驱动内容库；清目录不顺带实施数据迁移。
3. Plan 上层线程归属与造物确认授权仍有待办，不能通过删除旧宿主管线来假装完成 SDK 统一。
4. CI 目前主要覆盖 .NET；Python 工具、Unity、Player 验证各有独立入口。资源清理须检查引用并进行相应验证，不能只看 .NET 通过。

后续清理也应遵循：明确路径 → 核引用 / 来源 / 唯一内容 → 保留清单和必要重建依据 → 小范围执行 → 回归。不要使用覆盖整个 `.local/`、`Assets/` 或商业素材目录的递归删除命令。
