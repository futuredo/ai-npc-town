# 内容数据驱动建议（仅设计，未实施）

日期：2026-11-09。本轮不增加内容加载器，不移动 C# 内容，不调整玩法、规则数值或提示字节。

## 1. 分清内容与执行规则

- 首批候选：`DsContent.cs` 的角色、地点、物品、初始认知和规律定义，以及显示文本、显式排序、稳定 ID。
- 后续候选：离线提供方的确定性策略、导演事件定义、造物能力白名单、目标和结局配置。它们含行为，不能只贴成 JSON 就声称没有逻辑迁移。
- 暂留代码：前置校验、裁决/提交、随机算法、玩家确认、认知权限、导航到达、事务与过期检查。配置不得携带可任意执行的 C# 或扩权限脚本。
- `ContextBuilder` 的提示与投影不是普通 UI 文案；内容修改只要进入感知/提示，也构成模型输入变更。

## 2. 最小数据边界

建议先以引擎无关的版本化数据文件作为单一真源，Unity 只读入已验证结果；不要同时维护 ScriptableObject、JSON 和 C# 三份手工列表。是否采用 ScriptableObject 编辑器，只在确有编辑需求后决定，不让纯 C# 核心依赖 Unity。

每份内容包应有：包 ID、schema 版本、内容版本、支持的宿主规则版本、确定性内容指纹。角色/物品/地点引用稳定 ID，显示名可改但 ID 不随汉字改动；显示/决策顺序显式记录，不能用目录枚举或不稳定字典顺序推导。

可见初始知识和完整世界初值分层存储与投影。内容包是宿主本地资源，不得整包送给模型；每次仍从角色合法视角生成冻结感知。秘密、未观察地点和其他居民私有认知不因“已数据化”变成公共数据。

## 3. 加载时校验与失败方式

- 拒绝重复/空 ID、未知引用、非法枚举、NaN/Infinity、越界数值、超量条目和不兼容版本。
- 检查规律引用、角色地点/持物关系、初始知识引用及能力/材料白名单一致性；错误应能定位到具体记录。
- 校验通过后生成不可变运行内容，整包原子替换；失败不留下半个世界、不凭空用默认值“修复”。
- 同一局固定内容版本和指纹，不在模型请求中途热更新；编辑模式预览与正式局隔离。
- 不用配置路径自动读任意本地文件，不提供网络动态加载或自动下载。素材仍单独维护 `art/asset-manifest.json` 的来源和许可。

## 4. 迁移和验收顺序

1. 单独授权后，从当前 C# 原值导出只读样本，固定排序、默认值、浮点与全部字符串，不先改命名或补设计。
2. 对同一种子/场景分别初始化旧内容与加载内容，比较完整世界快照、合法角色感知、完整提示字节、可执行提案和整局轨迹；不只比较条目数量。
3. 加载器通过坏数据/缺引用/私有信息负例，全部离线统计、黄金、严格回放及 Unity 导入加载测试通过，才切换单一真源。旧路径只作为有期限验证夹具，不保留永久双实现。
4. 新内容导致模型可见信息或玩法变化时，另列版本与新旧对照；旧录制保留其内容指纹及读取条件，不修改旧黄金掩盖变化。

当前黄金的 14 起点主要覆盖计划/对话/居民计划，不能替代全部 GM/造物/行动投影样本。内容迁移前需补相应证据，不把当前编译和测试通过写成已完成数据化。

内容文件和加载规则归具体游戏宿主；未来 SDK 只提供版本/引用/指纹等通用契约，不能把本项目角色表定义为所有项目的通用内容格式。参见 [SDK 抽离建议](AI框架SDK抽离建议.md)。
