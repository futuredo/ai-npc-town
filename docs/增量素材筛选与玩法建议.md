**11/08 后续落局**：外盘已按十九组整理；完整场景/工作站、人物动作与 UI 已接进离线短局，当前看[资源利用清单](资源利用清单.md)、[局内接入](月光驿站局内接入.md)与[日志 020](开发日志/2026-11-08_020_现成场景与资源落局.md)。本文十七组/下载中是当时快照，不能当当前完整目录。

## 1. 先说结论

- **值得优先继续接入：Fantasy Horde Villagers 的四个人形样本和十段日常动作。** 少年、女性、男性、长袍人物来自同一套，适合先统一近景人物，而不是为了每个身份再找一套骨架。
- **环境暂时够用**：已有 KINGDOM 建筑/桌桶和 Fantasy Worlds 树石/道具，可以支撑一个小型魔法工坊。新下载的大城堡、雪堡不必成为前置。
- **Arashi 只作备选**：模型和 Humanoid 技术检查通过，但武士造型、战斗片段占比与主风格不同；不因为它动作多就把 Demo 改成战斗游戏。
- 本轮新增 **68 个源资源及依赖、23 个 FBX、读取到 56 个动画片段**。其中 10 段日常动作对 6 个角色做了 **60/60 组有效姿态变化采样**，不是把片段数量当作行为验收。
- 当前素材足以开始一段小范围互动接入；真正优先的缺口已经变成**拿放/交接、持物行走、接触与转身、光影反馈、中文界面和声音**，不是更多房子和怪物。

“可用”在本文指**有技术接入价值**。所有用户提供的商业下载包仍缺官方许可核实，保持 `license=null`、`import_verified=false`、`in_game_approved=false`；这些字段不因导入或采样成功而升级为正式交付/发布批准。

## 3. 已放进工程的新增内容

### 3.1 Fantasy Horde：优先人物与日常动作候选

目录：`unity/Assets/LocalThirdParty/Polygonmaker/Fantasy Horde Series/Fantasy Horde - Villagers/`。

选择入口为四位人物 `Child_1 / Female_1 / Male_1 / Monk_1`、一根 `Staff_curved` 和十个动作 FBX，连依赖共 **54 文件、导入转换前约 178.4 MiB**，不是整包导入。

| 动作类别 | 实际片段 | 边界 |
| --- | --- | --- |
| 原地行走 | `Anim_Old@walk_inplace` | 已采样骨骼运动；尚未与 NavMesh 速度/转向联调，不能保证无脚滑 |
| 待机与变化 | Old idle、Warrior idle、Warrior idlebreak | 可作少量自然停顿，不是无限随机表演库 |

五个有效 Humanoid Avatar 包括四人物与共享 `PolygonmakerRig`；动画 FBX 复用共享 Avatar，无需误改为每个动作都创建一副新骨架。

URP 处理保留四个原生兼容材质，另外四个 Built-in Cutout 和一个 Standard 材质转换。Cutout 保留基色/贴图/UV、裁剪阈值、法线与对应金属/光滑参数；没有把所有皮肤 Shader 强行替换。**`shader.isSupported=true` 不足以证明其属于当前管线**：本轮确实发现支持标记为真但没有 URP Pass 的旧 Shader，已按管线标签和实际引用处理。

### 3.2 Arashi：备选而非主角全替换

## 5. 素材适配后的世界与玩法建议

**建议保留“书中奇幻 + 借光过断鳞”，把首场景做成鳞岸的月光驿站/工坊，而不是普通商人运货。** 这是对 v5 的素材适配建议，不替代待确认方案，不声称已实现。

一栋小屋、一张工作桌、两条鳞岸步道、一个安全月台就够。远处露出巨龙轮廓、龙角月灯与空白海，近处真正能玩的魔法是有限月光、可摆放的棱镜/反片、会跟光的漂流灯。奇幻感由**能亲手试的规则与变化**决定，不靠一口气铺满城堡和怪物。

角色先从同一套 Horde 选少年、披袍者和领路人代理：少年想自己决定怎么过岸；保管月焰者要求保住一处照明；领路者愿冒险但要亲眼试过。服装只是临时视觉，**不把长袍直接等同邪教、不让铁匠职业重新支配主线**。鹿骨骑士、缝影女巫的特殊外形可以后续再做；第一片段以可辨轮廓、小饰片和光影效果表现能力，不先增加非人骨架采购。

快乐来自“我想了一个办法 → 居民提出自己的条件 → 我把灯/反片摆出来试 → 世界真的回应 → 我改进方案”，而非连续读六段聊天。保留两条路线与不同资源代价，试验前展示关键硬限制；合理的新解法不能因不在示例攻略里就被否决。失败应看得出是光没接通、承诺未满足或伙伴还没到，而不是旁白判负。

| AI 机制 | 可以在同一小场景验证什么 | 必须留下的真实结果（均待实现） |
| --- | --- | --- |
| 认知交互 | 询问为何漂流灯走失，展示一次真实试验，纠正传闻 | 角色自己的来源/认知变化，不读其他人秘密 |
| 社会影响 | 谈借棱镜、换岗、先保谁的照明 | 各方独立同意、持续条件、物品/岗位授权与撤回 |
| 语义判定 | 自提分批、借影、接续照明的新方法 | 解释方法与缺口，校验后实际执行，不只映射同一个旧按钮 |
| 多智能体 | 领路者去核查、保管者准备资源、少年自主选择跟随或拒绝 | 局部消息、真实到达/持物/任务竞争回执 |
| 生成式构造 | 描述一种引路灯，让模型组合有限功能部件 | 先预览、确认，再产生能照明/转向/停留的实体；不是图片改名充数 |
| 受限 AI GM | 根据谁过岸、哪里仍暗提出一次后续接续请求 | 依据公开事件生成合法目标，不凭空补能源、替居民同意或宣布成功 |

这里对构造选择了“功能实体”这一较窄实验，**不是论文排除图像/声音生成**。六类保留独立实验入口，短局只组合最好玩的两三类。现行在线接口仍是 `NpcPerceptionView` + `action=none`，新协议和视图需另行批准；整理素材不授权付费试验。
