更新：2026-11-06。性质：**技术探索 Demo 的体验假设，不是已实现功能或试玩结论。** 实施主线是[AI 原生引擎接入计划](AI原生互动验证计划.md)；[故事与玩法 v4](未竟之镇_故事与玩法_v4.md)提供奇幻世界与后续内容，不先制作完整首章。实际落地见[项目进度](../../项目进度.md)。

**11/08 实施补充**：Village 已重做第三人称直接控制与近场交互，见[日志 021](../../开发日志/2026-11-08_021_第三人称3C重做.md)。下面仍是体验目标；当前真正能做的是走近、开关光、确认人工候选和护送补救，不是开放造物/谈判已实现。

下一段最值得做成可玩核心的是**“亲手借一束光，和伙伴一起试出过路办法”**：在现成附魔台借/试/归还部件，用位置、方向与接续次序改变实际光路，再协商伙伴接受的条件；失光时自己到现场补救。趣味来自空间试验和人物条件彼此咬合，不是多打字、搬普通货物或只看 NPC 自动走。单芯能量、视线与归还代价须先让玩家看清；手动布置、部件借还和有参数小计划仍是下一段实现，不在本轮 3C 中冒报完成。

## 1. 好玩的核心是什么

> **在一个会响应想法的魔法试验场里，发现规律、发明东西、拉上有自己主意的伙伴，让自己想出的办法真的运转起来。**

项目首先是游戏内 AI 原生能力的技术验证 Demo，但玩家不该像在填写测试问卷。玩家体验“发明—试验—意外—调整”，研究者在背后观察六类机制各自的贡献、缺陷与代价。

| 层 | 玩家想要 | Demo 必须提供 |
| --- | --- | --- |
| 奇境与操作 | 想靠近看看、动手试这个 | 龙背/月灯的尺度、可移动的光影与灯具，不只旁白命名 |
| 发明与理解 | 我的办法不在菜单里，世界仍听懂 | 开放调查/协商/裁定、受限但有功能差异的造物 |
| 伙伴与意外 | 对方有自己的理由，局面会回应我 | 角色主动求证/协助/撤回，有因果的小后续而非强行反转 |
| 因果与掌控 | 我知道刚才发生了什么，还想改一次 | 状态可见、可试错、后果能解释，失败不只有拒绝台词 |

不靠系统数量、聊天轮数或沉重献祭情节制造深度。轻巧、古怪的魔法快乐先成立，再扩长故事。

## 2. 一段互动怎样才完整

**看见问题 → 观察/提问 → 提出办法或造物 → 必要协商与澄清 → 动手试验/伙伴行动 → 可见结果 → 根据新局面调整。**

每次重要干预都有目标、依据、简短方法摘要、实际执行与可继续引用的结果；非关键操作不反复弹确认。移动、摆放、试光、选对象、继续已确认计划用快捷操作，不要求每一步打字。

## 3. 首个短局：造一盏会带路的小月亮

**白龙将翻身，龙鳞步道开裂。把芬恩和一批漂流灯送到安全月台。** 造引路器是醒目邀请，不是唯一答案；改变光路、合作次序、接续点也应有实质作用。10—15 分钟只是未测节奏假设。

| 游玩节点 | 玩家经历 | 体验与技术证据 |
| --- | --- | --- |
| 看见与试一下 | 芬恩追着走偏的漂流灯，远处月灯随龙息晃动；玩家移动一处亮点/固定一段草稿 | 先有即时反馈、好奇和目标，不先读长篇世界观 |
| 调查规律 | 试光、对照传闻、追问角色没讲清的地方 | 观察/证词有来源，未知不泄露；新追问不是关键词猜谜 |
| 发明与协商 | 提出走法、借资源、约定条件，或描述引路器 | 方法与构型非唯一攻略，各方独立同意，拒绝有具体理由 |
| 动手试验 | 摆放/点亮/移动造物，走上真实通路，伙伴按自己的决定参与 | 材料、照明、路径、任务真实变化，至少一种构型可实际试用 |
| 意外与调整 | 伙伴求证/改计划；实际行动引出获准的小后续 | 有限自主和 GM 不替玩家解题，不无中生有惩罚正确办法 |
| 本局收束 | 到达者、遗留灯具、资源与承诺组成可见结果 | 先空间结果再因果页；有具体想重试的办法，不以长结尾补空玩法 |

一个局不必展示六类全套。开发者可独立开关六切片，组合局先取证据最好的 2—3 类作主机制；其余是同一场景里的实验入口，不是强制六站课程。

## 4. AI 与玩法同步，不互相拖延

- 六机制的具体输入、输出、状态与反例见[接入计划 §3](AI原生互动验证计划.md#3-六类机制具体落在哪里)。GM/构造属于本 Demo 的受限研究范围，不再以“以后扩展”无限后置。
- 先完成一个“玩家方法—角色决定—硬约束校验—空间执行—回执/记住”的闭环，再扩同一场景的其他能力，不预先搭万能代理引擎。
- 第一闭环就有最小状态、玩家反馈与录制；离线就绪后尽早申请少量真实探测，不等完整剧情、美术或所有切片做完。
- 当前接口仍 `action=none`。新决策、构造、事件与主持者视图需独立契约和审批；默认离线，本计划不构成调用或权限授权。
- 技术依赖性、同能力 B/C 记忆实验、不同组合的玩家体验分别验，不混为一个成功率。

## 5. 体验品质底线

1. **奇观可见、魔法可操作。** 光影/造物/空间至少有一种即时变化，不靠方块标签或长文描述冒充奇幻。
2. **语言和动作有节奏。** 不连续安排多轮只能输入和等待的谈话；短语也能表达方法，常用动作不必请求 AI。
3. **状态可读。** 材料、当前约定、谁尚未同意、什么已完成都能查；手记区分亲历/听说/猜测，不显示隐藏计划。
4. **代价提前可知。** 借走月焰会暗哪里、影路何时失效，不能失败后才加限制；高风险变更先预览。
5. **不同方法有实际差别。** 至少改变构型、光路、资源、任务或关系中的一项；不是同一开关配不同台词。
6. **自主不是混乱。** 角色行为有可见起因，主持不为精彩破坏既成事实，不强迫每局背叛/反转。
7. **不惩罚等待。** 模型等待与关键阅读/确认不扣行动窗口；延迟、取消与预算不足有反馈。
8. **结果不作假。** 真到达才算到达、真生成可用对象才算造物。离线、回放、真实 AI 明确标注。

## 6. 验证分工

| 层 | 最小证据 | 不可外推的结论 |
| --- | --- | --- |
| Core / 状态 | 权限/同意、资源、事件/配方校验，重复/取消/旧局、存档一致；必跑离线 `dotnet test dotnet/Town.sln --configuration Release` | 旧 100 项回归不证明新六机制实现 |
| Unity / 空间 | 真正到达、光影/构型/碰撞/行为、暂停/阻塞/恢复 | CLI 瞬移或改旗标不代表玩家完成试验 |
| 真实模型 | 六类分开测保留输入、正反例、理由/引用与实际回执 | 录制替身不证明模型能力，3 次请求不证明六类与整局 |
| 真人体验 | 无攻略操作、自己试法、因果解释、等待/枯燥/重试意愿 | 几位玩家的赞同不证明泛化或市场吸引力 |

规则合法但无趣、模型理解但执行失败、操作好玩但并非原生，都应分别报告。调用约束见[接入计划 §10](AI原生互动验证计划.md#10-接入与成本不因新目标自动放宽)。

## 7. 暂不扩展什么

不先做完整献灯首章、全部五场景/结局、开放世界、动作战斗、经济模拟、大量角色、无限新物理或全知 GM。六类先各有狭窄可用切片，不代表六套大型系统。基础框架仅按当前切片的真实瓶颈补齐。

v4 的人物关系与宏观危机继续保留，技术切片和短局有证据后再决定是否扩成长篇，不把先前写了完整故事当必须全部制作的理由。

## 8. 怎样判定它值得继续做

至少 3 位、争取 5 位未读方案的外部玩家作诊断目标，尚未开展。

| 时点 | 观察信号 | 没有时先修什么 |
| --- | --- | --- |
| 开场 | 主动移动光/试魔法，想靠近一个奇观，能说出当前目标 | 视觉揭示、即时反馈与目标，不是再加术语 |
| 试法 | 提出或改造一种方法，知道借了什么、缺什么 | 能力可读性、开放输入、资源与角色条件 |
| 结果 | 能解释造物/伙伴/路径真的怎样变了，想据此调整 | 执行、因果与失败反馈，不是只补台词 |
| 结束 | 有具体想再试的构型/路线/协作办法 | 方法的实质差异、节奏、自主性，不先堆奖励与剧情 |

记录打字次数、等待、首次卡点、求助、无聊时点、主动尝试及原话。两位玩家同一关键点卡住先修复再复测；若只觉得设定漂亮或 AI 会说话却没有做出任何事，短局未通过。六类技术都有效也不等于应该全部保留在游玩里。

## 9. 既有实现如何处理

v3 保留工程回归，不继续补完整旧路线；认知隔离、来源、导航/3C、代际与存档思路复用。新角色、造物、事件、能力与录制需要独立数据/版本迁移，不能批量改名冒充迁完。旧素材暂停采购，正式导入另记来源与许可证。

## 10. 下一次实现从哪里开始

实施按[接入计划 §8](AI原生互动验证计划.md#8-按什么顺序实施)的 D0—D4。D0/D1 只做月光工坊—断鳞步道的一项可操作光/影能力、一位角色的开放方案与条件约定，以及最小录制/执行/反馈。随后六类分别补切片，再用证据选择组合；不再以完成 v4 全章或只验证 N4/N5 作为项目终点。
