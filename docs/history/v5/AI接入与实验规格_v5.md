## 1. 问题与可检验假设

| 编号 | 问题 / 假设 | 有效证据 | 不能用作证明 |
| --- | --- | --- | --- |
| R1 接入 | 有限候选协议能把模型输出接为安全、持续的世界变化 | 候选→校验→提交→真实完成/失败→存档回放的同一事件链 | JSON 解析成功、模型说做完 |
| R2 机制增量 | 六类各提供不同的玩家能力或后续局面 | 独立实验、保留输入、多解评审、移除/替代导致的实质差别 | 六个标签、一段回复同时算六次验证 |
| R3 持续性 | 角色能在局部信息和旧约定下作出相关后续 | 求证/消息送达/履约的真实因果链，旧事实修正与来源记录 | 三个角色共享全知提示词、固定日程播放 |
| R4 体验 | 最佳少数组合能带来发明、试验、改造的快乐 | 新玩家主动试法、理解后果、具体重试打算，与等待/误解记录 | 设计者觉得有趣、测试通过数、语言流畅 |
| R5 代价 | 能识别哪些调用值得保留 | 请求职责、实际耗时/usage/估算费用、失败与替代方案 | 零成本宣称、只报顺利的一局 |

采用[论文解读](../../论文解读_AI原生游戏综述与路线图.md)中的原生依赖性作为实验工具，不宣称这是唯一普适定义。六类是分类，不是产品功能越齐越优秀。首版功能造物是对 N6 的项目选择；论文也允许直接构成玩法的图片、声音、文字等生成物。

## 2. 六类切片的具体职责

| 机制 | 输入 / 模型职责 | 候选结果 | 引擎真正落下什么 | 主要伪实现风险 |
| --- | --- | --- | --- | --- |
| N1 认知交互 | 当前角色已知事件、玩家问题/反证；理解关联、披露/澄清/修正 | 回答、引用、认知修正建议、不确定性 | 玩家听到的有来源说法；合法修正保留旧认知历史 | 按关键词放秘密、自动共享所有目击 |
| N2 社会影响 | 自己的目标、资源、任务、旧约定、玩家条件；决定接受/拒绝/反提 | 自己愿承担的行动、可观察条件与退出条件 | 每方独立同意、资源授予/预留、约定执行与履约 | 固定好感阈值、替别人同意 |
| N3 AI GM | 经批准的公开事件与允许事件家族；组织有因果的小后续 | 事件引用、目标、对象、前置、完成/取消条件 | 一个可执行/可取消附加目标，完成后产生事件 | 旁白换皮、倒改历史、免费解题 |
| N4 语义判定 | 角色可知的选中对象/能力描述、玩家方法；解释指代、缺口与语义标准 | 澄清或最多三步候选操作、参与者与标准 | 验证后的计划/任务；语义判定与实际完成分开 | 只匹配到一个旧按钮，或模型直接宣布物理成功 |
| N5 多智能体 | 单个角色的局部事件、目标、约定与任务状态；选择有限下一步 | 求证/消息/移动/提案/继续/停止之一及依据 | 真实送达消息、空间任务、冲突仲裁与回执 | 玩家逐步遥控、全知共享、每帧推理 |
| N6 生成式构造 | 可用组件/端口/功能原语、玩家描述与已知试验；形成构型 | 组件连接图、行为图、参数、材料引用 | 材料账、预览、确认后的可用实体与功能 | 固定二选一、换名换皮、任意脚本执行 |

同一互动允许涉及多类，但记录主职责与次职责。例如先讨论借棱镜，再请求配方，是两个有不同权限的决定；不能把一次长回复既当六种独立验证，又把内部多次调用算一次费用。

## 3. 模型、程序与玩家的权力边界

### 3.1 三种权威

- **模型**：在合法能力空间内理解新方法，作社会选择，提出条件、有限计划、构型和后续目标；不是只负责文风。
- **程序**：既成事实、位置/碰撞、资源守恒、任务可达性、权限、同意、原始来源、版本、事务与预算。硬校验不得预先重算全部社会答案。
- **玩家**：有代价/风险的自己行为要确认；可以取消自己的提案，但不能取消别人已发生的选择，也不能替别人同意。

模型可能相信错误，也可能提出不安全方案。程序拦截非法效果并返回具体缺口，不偷偷将它改写成成功。一个方案资源合法但角色拒绝，两者不矛盾；评审不能把所有拒绝算理解失败。

### 3.2 信息视图

| 请求身份 | 允许信息（未来契约） | 永不发送 |
| --- | --- | --- |
| 角色调查/协商/裁定/自主 | 本人的认知与来源、已感知对象、自己的目标/能力/任务/约定、必要玩家输入 | 世界真值表、别人私有目标/记忆、未观察位置、本地文件 |
| 工坊构造 | 拟批准的工坊能力目录、获准可用材料/端口、玩家选择与公开试验 | 全员秘密、任意代码工具、场景文件或目录内容 |
| 受限 GM | 拟批准的公开事件投影、公开未决目标、允许事件家族及可引用对象 | 全部居民私有状态、未发现真相、可随意写世界的工具 |

**现行在线权限只有当前角色 `NpcPerceptionView` 与必要玩家输入。** 工坊专用视图、GM 视图、新字段和动作候选均需单独审核；不能把新视图包在聊天字符串中规避。未获准时只用离线人工样本走执行测试，不调用新在线接口。

请求上下文是局部投影，不将完整设计文档当系统提示：例如“梅芙想要收回棱镜”属于她自己的目标，不应预先发送给芬恩。公开事件也需显式发布：私下协商不会自动成为 GM 可见的全局素材。

### 3.3 输出、引用与文本

- 候选使用有限枚举与类型化字段；自由文字只作短解释，不反序列化为任意类名/脚本。
- 引用必须属于本次允许的证据 ID，不能因字符串像真 ID 就写入知识。
- 区分事实观察、他人说法、模型推断与承诺。模型推断不会直接变成世界真值或亲历。
- 简短理由摘要可记录；不请求、不保存隐藏推理链。
- 当前词表型防泄露只能覆盖有限场景，不夸称可检测全部改写；专门测秘密诱导、否定句与正常表达误杀。

## 4. 最小接入管线与候选协议

以下是**待实现概念模型，不是已有类/API**。先接一个具体光路/约定闭环，再提取共用接缝，不新增一套万能代理平台。

```text
输入/事件 → 机制路由（无付费）→ 局部视图与能力快照
        → 请求预检/预算预留 → 模型候选
        → 结构/引用/代际/版本/权限校验
        → 澄清 / 拒绝 / 各方同意 / 玩家确认
        → 原子提交资源与约定 → 有界任务/构造执行
        → 到达/光路/行为回执 → 事件/记忆/存档/必要的下一决定
```

### 4.1 请求信封

在客户端本地保存：`requestId / sessionGeneration / stateVersion / mechanism / actorId / scenarioVersion / policyVersion / promptVersion / schemaVersion / model / mode / budgetReservation / viewHash`。

不要求模型重复整套信封，避免浪费输出。关联 ID 与幂等键由程序生成；重试规则仍为零。候选需绑定目标对象与期望状态，回复到达时再校验，不只看开始请求时合法。

### 4.2 候选公共字段

| 字段 | 约束与用途 |
| --- | --- |
| `decision` | `answer / clarify / decline / propose / consent / withdraw / continue / stop` 的相关子集；不是任意执行字符串 |
| `summary` | 玩家能读懂的方法/理由，目标 1—2 句；具体长度由压缩协议测试冻结 |
| `evidence` | 本视图可引用 ID 列表，有限条数 |
| `missing` | 需要澄清的一个关键对象/条件；无缺口可空 |
| 专用载荷 | 调查修正、约定、三步计划、角色动作、事件或对象图；每次只承担一个主要职责 |

给程序的结构和给玩家的长台词不应同时膨胀。首轮输出仍 384 tokens：先用短 ID 与紧凑字段验证；若连最小合法载荷都装不下，记协议失败，提出新预算/上限申请，不能悄悄扩大。

### 4.3 首版能力词汇

- 通用：观察已感知对象、到已知锚点、发送一条有来源的消息、提案、独立同意/拒绝、停止自己的任务。
- 物理：拾取/放置自己有权处理的轻物、旋转光学部件、安装/拆下、点亮/熄灭、沿已验证路线带队。
- 角色特有：芬恩带队、梅芙借棱镜与核验、瑟恩到一个岗位支援/借反光片。
- 构造：安装白名单组件，按端口连边，配置固定/跟随信标/锚点停留等有限行为。
- GM：引用公开已发生事件，为现有对象组合一个有条件的附加目标。

语言可以产生新的组合、次序、社会理由与可检查标准，但不能创造不存在的物理操作。不支持的能力应明确返回 `unsupported`，不能用漂亮文字偷偷降级为别的意思。

### 4.4 接入示例：成功、同意与完成不是同一个字段

以下是**离线协议草图，不是已实现 Schema 或实际模型回答**。玩家对瑟恩说：“先让你看过我试亮的结果，再到下路护送，结束后我把反光片还你。”

```json
{
  "decision": "propose",
  "summary": "我先看试亮；退路仍可走，我就到下路护送。",
  "evidence": ["obs_17"],
  "conditions": ["test_passed", "retreat_open"],
  "self_action": {"kind": "guard", "anchor": "L1"},
  "exit": "next_safe_boundary"
}
```

程序确认 `obs_17` 确属瑟恩已知，再核对岗位/任务和条件。这个回复仅表示他反提了自己的参与方式；它不自动借出反光片、不代表玩家已经接受，也不替芬恩同意。如果玩家接受、条件满足且瑟恩实际到位，才具备对应护送支援；对象真正进入 E 后才收到完成回执。

若 `obs_17` 不存在或属于别人私有观察，拒绝该引用而不是从真值表补证据；若试亮尚未发生，可以保留“待试验”的提案，不写成已经完成。字段名/ID/载荷长度需在 M2 离线测试后冻结，示例只说明责任分层。

## 5. 约定、任务、造物和事件怎样落地

### 5.1 约定（Agreement）

最少保存：ID、各参与者、各自同意记录、条件表达式、资源、地点/岗位、完成标准、到期/撤回边界、依据事件、状态与版本。

条件先只支持有限事件/谓词的 AND/OR 组合，限制深度和条数；如“试亮成功 AND 退路已验证”。“让他满意”可以由相关角色根据所见作一次语义判断，随后形成带依据的个人决定；不能伪装成程序客观布尔值，更不能读取内心作为世界事实。

谈成不立刻替所有人启动任务。参与者分别同意后才预留自己的资源；有一方拒绝，展示尚缺同意。首版可将可变资源锁定在已确认的小计划内，不签无限将来的承诺。

### 5.2 执行任务

状态至少区分：`proposed / awaiting_consent / ready / executing / completed / failed / cancelled`。调查答复不需要强塞进完整任务状态机。

发起通行前，校验：当前可达路线、光源/符文、容量、真实支援岗位、同意、资源与潮息窗口。预检失败不扣窗口；确认并提交本次尝试时才扣一个。技术性执行失败保留失败原因与恢复点，不多扣一次、不装完成。

到达以 Unity 实际到达/验证回调为证据，Core 只接收通过身份/代际/任务版本检查的回执。路径受阻、取消、光源撤离都有安全停止点与玩家反馈；不能继续沿用旧日程“时间到了就算到达”的捷径。

### 5.3 造物（Recipe → Instance）

对象图保存组件 ID/类型、端口/连边、有限几何参数、行为节点、材料引用与版本。初版建议最多 6 部件、8 条连接/控制边、3 个行为节点；拓扑与端口规则明确，光路不得循环增能。

流程：结构/材料/拓扑校验 → 空间预览 → 确认 → 一次性预留材料 → 创建受控实体 → 验证功能 → 提交对象与回执。创建失败清理本次未提交实体/预留，不回滚其他已经发生的世界事件。

光学与控制边分型：不把跟随目标当能量输入。数量/总能量/光程/摆放/碰撞均验证，不能凭名字“无限月亮”改变物理属性。拆装只回收实际使用的部件，借物所有权不变。

### 5.4 主持事件

候选包含：允许事件家族、引用公开事件、现有对象、目标、触发/完成/取消条件。不得直接包含“把任务设为完成”或给全员写认知。

目标成立后，经普通消息/任务系统让相关角色真正收到请求；角色仍独立决定。最多一个未完成的 GM 附加目标，避免无穷支线。某候选只有文案差异时如实归为表达，不算生成可玩事件。

## 6. 异步、调度与错误处理

### 6.1 事件驱动，不是在线无限循环

- 无模型路由先识别是否需要决定；移动/试亮/摆放/已确认计划不调用。
- 同一时点全局最多一个真实请求；不只每 client 并发一。每位角色最多一个待处理决定，重复点击返回等待，不收费排队。
- 新提案、消息真正送达、任务受阻、条件满足、履约/失约才触发决定。相同事件合并，不因每帧位置变化触发。
- 一条交互链最多两次自主后续决定，达到上限暂停并提示继续；单局总数还受授权请求余额控制。此数值是保护目标，不绕过全日预算。
- GM 只在阶段变化或一段真实行动完成后提案，不每句插话。决定去重键关联角色、触发事件与任务版本。
- 模型等待冻结行动窗口和危险推进，但 UI、取消、镜头与无风险预览仍可响应。恢复前说明刚才发生了什么。

### 6.2 校验顺序

结构与大小 → 本次引用 → 局代际/最新请求 → 相关状态版本 → 身份/权限 → 同意 → 对象/材料/能力 → 空间路径/光学 → 重复与冲突 → 确认/提交。

无关相机变化不必使回复作废；影响目标/资源的变化必须重新校验，必要时要求用户重新决定，不能自动重调模型收费。旧局包、已取消包和重复回执永远不能落地。

| 问题 | 玩家反馈与恢复 | 研究记录 |
| --- | --- | --- |
| 格式/截断 | 未生成可用提案，保留输入；无自动重试 | 原始失败、载荷大小、usage 有无 |
| 含糊方法 | 一个具体澄清问题，不先执行 | 澄清次数、需不需要模型 |
| 越权/不存在能力 | 指明不支持项，其他事实不改 | 原始候选与拦截分别计 |
| 资源已被占用 | 展示冲突持有者/相关计划的可见信息 | 版本冲突，不算模型已兑现 |
| 超时/取消 | 停止等待、不提交；次数/预留仍保留 | 不自动重试、不抹失败 |
| 导航/实体失败 | 停在安全点，撤销本次未提交资源，允许恢复 | 引擎失败与模型失败分开 |
| 预算/权限不足 | 暂停 AI 决定，可显式进入规则演示 | 不伪称仍是真实 AI |

## 7. 记录、回放、存档与隐私

记录最小事件链：请求信封/视图指纹、脱敏输入、候选、校验结论、同意/确认、资源事务、执行回执、认知来源变化、时间/usage/费用估算、最终状态指纹。

模式始终标注 `offline_fixture / recorded_replay / live`。回放消费已提交结果和回执，不重复调用、不重新抽一次模型答案；新继续互动默认离线/暂停，不能读档后自动恢复收费自主循环。

新存档必须覆盖：构型/实体 ID 与版本、材料所有权与预留、约定与各方同意、任务/位置/安全点、公开与私有事件、来源记忆、潮息窗口、机制配置、已消费输出与回执。**旧 v3.1 存档不能冒称自动兼容**；新场景与旧运行分入口，明确版本拒绝或编写显式迁移。先用短局完整记录，暂不为无限长历史做复杂快照系统。

密钥、认证头、预算文件不进入存档/资源包。原始记录可能含玩家输入和角色秘密，默认本地忽略目录；分享报告只导出必要脱敏片段，不把调试全知视图当玩家可见证据。

## 8. 六张机制实验卡

共同字段：场景/规则/协议版本、固定初态、信息视图、输入、预先登记的合法多解范围、非法效果、模式、对照、请求预算、实际状态/轨迹、评审结论与失败原因。

| 卡 | 正例目标 | 关键反例 | 可观察通过条件 | 关闭/替代对照 |
| --- | --- | --- | --- | --- |
| E1 / N1 | 用“刚才只有 A 亮”反问角色的双符文解释；相关角色确实见过该试验 | 要求说出别人的私约/未观察位置；伪造证据 ID | 引用有效，区分猜测/亲历，按反证修正解释；未知不泄漏 | 固定问答/近期截断，报告其实际信息范围 |
| E2 / N2 | 提出“先验证退路、过完第一批归还借物”的交换或另一组保留条件 | 替第三人同意、重复许诺同一棱镜、不可观察的秘密条件 | 具体条件影响接受/反提；独立同意后真实授予，履约/退出可追 | 固定交易菜单，不能偷偷给 AI 组额外材料 |
| E3 / N3 | 两个不同已发生结果各引出相关可执行后续，目标不相同 | 不存在的灯、倒改失约、生成免费新能力 | 后续引用真实公开事件；有对象/条件/完成或取消与状态差别 | 固定同一后续；若只台词差异判未成立 |
| E4 / N4 | 提示词与专用分支未出现的方法，包含新次序/空间关系/协作标准 | 含糊“让它过去”、不存在飞行、缺资源却宣布完成 | 相关理解/澄清/合理拒绝，合法时确实改变计划/执行；非同按钮 | 简单意图映射，不为 AI 组改物理规则 |
| E5 / N5 | 一人收到任务受阻消息，自主求证/联系另一人/到岗位 | 消息未送达却知道、两人抢同一岗位、事件自激循环 | 有局部信息→决定→真实动作→他人后续的链；至少一步非玩家遥控 | 固定日程/关闭后续，明确能力差异 |
| E6 / N6 | 同一组件目录产生至少两种功能不同的有效构型，再描述一个未给示例的变化 | 循环供能、超材料、越界、生成代码、换名不换功能 | 图/实体/材料一致，功能实测有差异，拆装/读档一致 | 固定配方按钮；不把美术变化当功能增量 |

这些例子是试验主题，不是预先写进模型的正确答案。至少保留六种语义不同的方法，分给设计/测试记录后不放入提示词或专用代码分支。构型例子与开放方法的验收集分离。

### 8.1 离线必测矩阵

每卡先做一个合法、一个应拒绝、一个澄清/冲突样本，最低 18 个候选样本；它们验证契约与执行，不统计为模型能力。另加公共反例：

1. 新局/读档后旧回复；取消后回包；同回执重复提交。
2. 未经同意、私有消息越权、提示注入、假引用。
3. 同资源两计划竞争、借物拆装复制、跨版本构型。
4. 光路失效/物理不到达/岗位未到，却请求完成。
5. 预算预留并发、账本错误、超时/失败仍计次，无隐式重试。
6. 回放/存读档后状态一致、0 网络、无密钥与私密日志入包。

### 8.2 真实请求分阶段，不虚报样本

| 阶段 | 数量目标 | 前置与结论边界 |
| --- | --- | --- |
| L0 离线 | 上述样本与空间测试，不收费 | 只能证明结构/权限/执行路径 |
| L1 第一闭环 | 最多 3 次：N1/N2/N4 各一个窄例或集中修一个问题 | 新接口获准且用户授权后；任何失败先停止该批。不是六类验证 |
| L2 补机制 | 最多 3 次：N3/N5/N6 各一个窄例 | 分批另授权；不能拿 L1 成功自动授权 |
| L3 反例探测 | 六类各一反例，分两个至多 3 次的小批 | 至少累计 12 次才有“一正一反/类”的最低探测，不证明可靠率 |
| L4 复测/保留方法 | 根据失败决定是否追加；若以上 12 例各重测一次，总计 24 次 | 需新批准；超过日 20 次，不能同日完成，不能清账本规避 |

六类各一隔离正例至少 6 请求；内部调用全部单计。多个机制合并一次输出可以研究组合，但不能替代六类独立证据。首轮 3 次只能做很窄的能力摸底。

## 9. 三种比较必须分开

### 9.1 原生依赖性 / 单机制贡献

同一初态、材料与空间，分别开关/用固定方案替代某机制；观察可支持的方法、构型、条件、主动后续与玩家体验的差别。记录替代改变的能力，不能用删掉法术、增加不公平限制来证明 AI 更强。

基线仍能分批救援不等于所有原生目标失败；但若 AI 仅令同一救援路线多几句对白，核心创造互动并未成立。报告应限定“哪些部分依赖模型”，而不是整个产品一律贴原生标签。

### 9.2 记忆 B/C 子实验

固定模型、玩法能力、物理规则、提示词职责、输出/调用预算、场景、输入序列；只换近期上下文与来源检索组织。不能让 B 不会分光、关识破，而 C 有新技能。A 是规则基线，不冒充另一种模型记忆组。

先用小样本发现需要记什么，再做 B/C；不让检索平台的复杂度抢在实际语义/履约问题前面。

### 9.3 机制组合与真人体验

先选 N2/N4/N6 等候选组合，与更简单配置比较。报告配置差异与角色能做什么；小样本只诊断，不伪装因果统计实验。

至少 3 位、争取 5 位新玩家，不先读设计文档；记录首次试光/首次计划、输入次数、主动修改、等待/卡点、求助、实际结果。结束问：

1. 你想做什么？世界哪里理解对了/错了？
2. 灯、路线或伙伴具体为什么发生变化？
3. 你是否想过不是提示里的办法？有没有试？
4. 哪里开始无聊或等待？
5. 如果再来一次，你具体会改什么？

两人同核心操作卡点先修复再找新玩家测。录制回放/规则模式可以测界面和操作，但必须标明，不能把反馈当实时 AI 体验。

## 10. 指标、人工评审与报告

| 层 | 指标 / 分母 |
| --- | --- |
| 理解 | 保留输入的相关解释/合理澄清/有依据拒绝，各占被评请求数；不能用服从率代替 |
| 认知 | 非法披露、假引用、来源误归因、过时采用/成功纠错，分别列机会数 |
| 机制 | 条件影响、可执行新目标、有效构型/实测功能差异、自主因果链，不混一个总成功率 |
| 执行 | 已提交任务完成/失败/取消、应到达却未到达、资源与回执不一致 |
| 安全工程 | 旧包污染、重复执行、越权执行、密钥入记录：观察样本中必须为 0；不声称全域证明 |
| 成本性能 | 真实请求数、等待、输入/缓存/输出 usage、估算费用；样本小先列每次与中位/范围，不虚报稳健 P95 |
| 体验 | 主动试法/改造、因果解释、具体重试意图、无聊/卡点与原话，不只问喜不喜欢 |

人工标准预先登记：语义上相关、引用合法、条件可实现、角色决定有理由、实际效果相符；允许多个合法答案。先由实现者逐例审阅，再尽量由未参与提示词编写的人复核争议样本；没有第二评审就写明。不能用同一模型自评作唯一答案。

研究报告固定包含：版本与模式、样本/分母、成功和失败原始片段、拦截与兜底、实际回执、对照差异、耗时费用、局限与下一实验。少量探测不声称统计显著、长期稳定、通用推理或市场吸引力；需可靠率估计时另定样本量/置信区间与预算。

## 11. 成本、授权与停止闸门

沿用[成本规范](../../OpenAI接入与成本规范.md)：默认 `gpt-6-luna`，输出每次最多 384 tokens，完整输入 JSON 最多 12 KiB，并发 1，单轮最多 3 次，无自动重试/换模型/付费搜索。每次预留 USD 0.002，单轮 USD 0.01，UTC 日最多 20 次 / USD 0.05。失败、超时和途中取消计次；不重置账本。

### 11.1 请求目标与预留，不等于实际账单

| 范围 | 请求数 | 预留上限 | 授权要求 |
| --- | --- | --- | --- |
| 一批窄探测 | ≤3 | USD 0.006 | 每批明确授权；现轮 USD 0.01 上限不变 |
| 六类各一正一反 | 至少 12 | USD 0.024 | 至少四批；不含任何额外澄清/角色决定 |
| 上述每例再一次 | 累计 24 | USD 0.048 | 至少跨两个 UTC 日，分批授权，不绕过日请求上限 |
| 一局真实组合 | **尚未知** | 不预报固定单局价格 | 从轨迹测出调用数再批准；若需 >3 次不能自动放行 |

这不是申请花完上述金额，更不是已有许可。按当前预留，20 次计 USD 0.04，请求数可能先于金额上限阻断；仍同时执行两种限制。

实际估算费用按返回 usage 和**运行前核对的价格**计算；无 usage 标未知，不能填零。现有成本文档价格是 11/04 记录，不自动当永久价格。预算预留不是组织级硬额度，也不能覆盖其他机器/工程。

若短局无法在当前每批 3 次边界内连续运行：先保持分段实验/录制体验，提交测得的完整调用轨迹、预计量与停止策略，再申请新的单局授权；不能开多个“三次批次”自动连跑来规避。无人值守持续代理默认不启用。

任何密钥/权限异常、旧局状态污染、重复收费执行、无效资源事务先停止；格式/截断/能力不足记录后修协议，不花钱自动抽到满意。确认设计与历史归档都不等于批准新动作协议或付费运行。
