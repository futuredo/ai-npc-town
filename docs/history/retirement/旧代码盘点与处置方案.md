## 1. 结论与证据范围

旧代码不是一组可以直接删除的孤立目录：v3 灰盒仍有场景、运行时、编辑器入口和存档回归；月光切片有独立运行闭环和回放。当前龙眠镇领域代码没有发现对旧领域命名空间的直接源码依赖，但外围仍有用量类型和 UI 主题的跨代复用。

检查了第一方 C#、`.asmdef` / `.csproj`、编辑器菜单、PlayMode 与 .NET 测试，以及本机 `Assets/` 下 `.unity` / `.prefab` / `.asset` 的脚本 GUID 引用，包括被忽略的 `LocalThirdParty` 场景。按类型名搜索得到的 `Session`、`Ending`、`NpcPerceptionView` 等同名结果已人工区分，不能把命中同名当成真实依赖。原始搜索清单留在 `.local/refactor-baseline/stage5/legacy-reference-inventory.json`，它是候选索引，不是编译器依赖图。

“未发现引用”只表示本次源码和本机文本资产扫描未发现；不覆盖仓外调用方、缺失商业资产、二进制资产、反射构造或未来重新生成的场景。没有以此授权删除任何内容。

## 5. 三种候选方案

| 方案 | 代码与程序集 | 场景 / 资产影响 | 测试影响 | 存档 / 回放影响 |
| --- | --- | --- | --- | --- |
| A. 独立 `Town.Legacy` | v3 与月光分别保持内部闭环，可用 `Town.Legacy`、`Town.Legacy.Unity`、`.Editor` 分层，而不是一个混合引擎/纯 C# 大包；同步建 .NET 工程、移除原通配编译重叠 | 原 MonoBehaviour 名称/字段/meta 必须保留；程序集身份变动仍需检查加载与所有序列化类型，不承诺仅留 GUID 就必然无风险；月光主题先确定共享资产归属 | 更新显式引用并分别运行全部旧/新 .NET 与 PlayMode；检测重复编译、依赖环、动态添加组件；旧 OpenAI 契约须保留或独立适配 | 不改 JSON 成员、枚举数值、规则/场景 ID、校验算法与存储路径；用已有存档字节和录制逐一读回。类型命名空间可能影响 DataContract 身份，须保持并验证；不自动升级旧档 |
| B. 整体归档 | 把完整旧运行闭环和配套工具作为只读历史快照移出当前编译；不只是搬几个 Core 文件 | 同时退出四个构建条目，旧菜单停止供当前工程使用；商业资产只记录清单不打包分发；先解除用量类型和主题依赖 | 旧测试迁到可单独运行的历史工程，不得删除测试再声称新工程通过率未降；明确归档后验证环境与可复现条件 | 当前版本将不再提供旧档运行入口，保留独立历史读取器/工程和版本说明；不把旧档误当龙眠镇档，不删除玩家本机文件 |
| C. 保持不动 | 代码仍在现有程序集，文档标明年代/阅读边界；当前 SDK 研究只针对独立契约，不带走整个 Core | 场景、GUID、动态组件、构建条目与主题路径均不动 | 继续全量 .NET 和现行 PlayMode；旧回归成本保留 | 现有旧档、月光录制和龙眠镇严格回放入口都不变，无迁移承诺新增 |

**当前建议选 C 作为本轮交付状态。** 若还需要持续演示 v3/月光，后续单独批准 A；若确认永久退役，再选 B。A/B 都不是本轮隐含后续动作：先固定旧档/各场景加载证据，列路径清单，消除外围跨代依赖，再执行。

旧存档边界明确分开：`TownSave` 是 schema `1` / `unfinished-town-v3.1`，保存到 `Application.persistentDataPath/unfinished-town/chapter7.json` 并有备份；`MoonReplay` 使用 `moonlight-slice-1`；龙眠镇使用 `dragonsleep-replay-v1` / 当前 `dragonsleep-rules-6`。三者不是可自动互换的版本序列。
