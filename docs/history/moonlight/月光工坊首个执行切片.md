# 月光工坊：首个候选执行切片

> 历史文档（2026-11-09 整理）：对应旧方案、原型或删除前盘点，不再作为现行操作说明。用户已授权退役旧原型及其专属验证；不再执行文中的旧玩法复验与待确认步骤。当前设计见 [龙眠镇 v6](../../龙眠镇_世界观玩法与AI架构_v6.md)，实现见 [工程骨架](../../工程骨架说明.md)。正文中的源码路径、测试数量与“当前”均指原记录时点。

更新：2026-11-07。状态：**离线执行框架已落地；尚未接入真实语义模型，也不是完整 v5 短局。**

## 1. 本轮推进的核心

研究目标不是让角色多说几句，而是验证 AI 提出的办法能否进入游戏规则和执行层。本切片先把可证伪的基础接缝做实：

```text
玩家方法文本 + 请求代际/版本
→ 候选来源（当前仅显式人工样本）
→ 结构、引用、能力、角色同意、资源校验
→ 等待玩家确认
→ 预留月焰
→ Unity 实际验光、寻路、连续位置采样
→ 完成 / 停止 / 失败回执
→ 录制与无网络回放
```

它服务于后续 **N4 语义判定 + N2 社会协商**，但现在只有固定的两种方法和一位角色，不能把执行测试当成开放语义或社会推理已经成功。

## 2. 如何运行

打开 `unity/Assets/Scenes/Moonlight_Workshop.unity`，进入 Play。新场景与 `Town_Graybox`、商业素材预览完全分开，不替换旧存档。

1. 写下想试的方法；文本会记录，但当前**不会解析该文本**。
2. 显式选择“跟随引路”“双束符文”“澄清”或“拒绝”人工样本，再送入候选校验。
3. 检查角色条件。只有玩家确认，才预留两份月焰并开始执行；角色答应不是已经到达。
4. 跟随引路走下路；双束符文先验证两条无遮挡光路，稳定两秒后走上路。
5. 切断月光或放下遮光屏，观察验光/移动变化；可以暂停、撤回或重开。
6. 内存书签录制候选及实际采样，回放后保持暂停；继续时重新验现场光路。**不是新增磁盘存档槽。**

小月亮当前由执行器自动放在角色前方，是引路代理，不是已实现的玩家造物、自由摆放工具或 N6。场景使用自制几何与 URP 材质，人物是技术代理，界面仍为开发用 IMGUI。

## 3. 代码职责

| 文件 | 职责 |
| --- | --- |
| `Town.Core/Moonlight/MoonContract.cs` | 独立请求、候选、有限方法、角色同意、人工样本来源接口 |
| `Town.Core/Moonlight/MoonWorkshop.cs` | 请求归属/版本校验、确认、月焰占用、连续位置与供光条件、回执 |
| `Town.Core/Moonlight/MoonReplay.cs` | 独立 `moonlight-slice-1` 录制；最多 10000 指令/2 MiB；回放不调用候选来源 |
| `Town.Unity/Moonlight/MoonWorkshopGame.cs` | NavMesh 实际执行、射线遮挡、稳定供光、界面与内存书签 |
| `Town.Editor/MoonWorkshopSceneBuilder.cs` | 显式生成隔离场景，拒绝覆盖已有场景；不在开工程时运行 |

以上路径相对 `unity/Assets/`。Core 仍被 .NET 链接复用，不引入新运行库。旧 `TownRuntime`、`ILLMClient` 与 `TownSave` 不被替换，也不假装兼容新场景。

### 必须保留的边界

- 候选无法自己写 `completed`、瞬移、增加能源，或替另一个人同意；当前只验证芬恩自己的条件。
- 同一请求仅处理一次；取消、跨局、同代际另一实例、过期回复都不能占用当前请求。
- “可通行”以现场射线和导航为依据。连续位置限速及顺序路点检查是技术约束，**不是防作弊系统或完整几何证明**。
- 回放 SHA-256 用于损坏检测，不是身份签名；界面书签不包含完整场景编辑历史。遮光屏属于现场条件，回放后重新检测。
- 尚无多角色资源竞争、任意构型、动态能力目录、独立自主计划或 GM。不能把这套窄状态机包装成六机制通用平台。
- 没有修改现行在线 `NpcPerceptionView` / `action=none` 权限，没有新增真实模型适配或隐式联网入口。

## 4. 证据该证明什么

Core 测试覆盖两方法差异、角色同意与玩家确认分离、越权引用/超资源/未知能力、过期/取消/重复、连续姿态、供光条件、途中录制回放。

Unity 测试检查真实经过上下路线、碰撞遮光时不出发、恢复光后等待稳定、切光停止、重开代际与位置，以及途中书签恢复后继续实际到达；旧六项导航/存档/URP 测试继续回归。实际结果记录在[日志 019](../../开发日志/2026-11-07_019_月光工坊执行闭环.md)，不把测试数量解释成模型准确率或好玩率。

首轮测试发现压扁的圆柱仍有默认胶囊碰撞体，导航面高出可见地面约 1.23 米；导致下路停滞和重开位置错误。已替换为静态网格碰撞并重烘本切片导航，不放宽断言、不重建旧灰盒。

## 5. 下一步最小推进点

1. 在当前执行接缝上扩展**有参数、顺序和条件差异的小计划**，而非继续增加聊天菜单；先用保留候选与反例验证执行器能区分实质不同的方法。
2. 定义一位角色的最小感知/能力契约和异步候选接口，保留澄清、拒绝、反提与局代际校验；在线信息和动作权限须单独明确批准。
3. 获准后尽早做最多三次窄真实模型探测，验证能否给出合法且有差别的方案；失败保留原始候选和拦截结果，不悄悄切回人工样本冒充 AI。
4. 单角色闭环可信后再加入第二位角色的独立条件/撤回，随后分别做 N5、N3、N6 窄实验；不等完整剧情或全部素材下载。

GitHub 调研只用于选择接缝与实验模式，见[实现参考](AI原生框架实现参考.md)。没有安装大而全的 Agent 框架或导入第三方源码。
