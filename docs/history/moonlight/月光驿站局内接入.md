## 1. 运行入口

首选打开 `Assets/LocalThirdParty/Gameplay/Moonlight_Village.unity` 后 Play。它是 KINGDOM 完整室外 `DemoExterior` 的玩法副本，原资源场景不覆盖。玩法在原生地形世界位置约 `(310, 6.5, 470)` 附近运行，保留原作者周围环境，不是把整套地图缩成远景摆件。

如果要隔离环境干扰，打开 `Assets/LocalThirdParty/Gameplay/Moonlight_Rescue.unity`。如果要验证不带商业资产的执行内核，打开 `Assets/Scenes/Moonlight_Workshop.unity`。旧 `Town_Graybox` 继续作为原规则回归，不是当前故事主线。

`LocalThirdParty` 被 Git 忽略，须本机已导入资源。显式菜单 `Town/Moonlight/Build Local Rescue Chapter`、`Build Native Village Demo` 用于首次组装；拒绝覆盖已有目标，不能把重建当作安全刷新按钮。原生场景副本移除缺失厂商脚本、停用原展示相机/旧粒子，使用项目自己的执行、镜头、UI 和局部导航；没有安装原包里的第一人称控制器或未知插件。

## 2. 一局怎样玩

**开场**：白龙即将翻身，芬恩不愿被固定成灯芯。先借一轮小月亮，让他和三盏漂流灯离开危险鳞岸。完整献灯故事暂不展开；这段先保证可理解的目标、可观察的办法和实际后果。

1. 用 WASD 操控读者走近芬恩，按 E 打开任务纸页，选“下路跟随小月亮”或“上路两束光照住符文”。输入框会记录方法文字，**当前文字不决定候选**，界面明确标记人工候选和零网络请求。
2. 听芬恩的条件：持续供光，失光就停。提出/同意不是执行；玩家必须再确认占用两份月焰。
3. 确认后收起面板，自己走动、跟随观察芬恩和三灯实际行进。引路法要求近域光和无遮挡；分光法要求两枚符文射线畅通并稳定试亮两秒。NavMesh 实际经过中点和终点，不按倒计时宣告到达。
4. 近场光源可按 E 切换；面板仍保留切光/放屏实验控件。交谈阅读时暂停护送与玩家移动，Esc 关闭后恢复原暂停状态，不为看条件付出失败代价。中断应留下具体补救方向，而不是把还没记录的合法位移追溯判成失败。
5. 每盏灯独立记录真实到达；芬恩到达不能代替三盏灯获救。全员抵达自动收束；也可二次确认提前结束，按实际结果给出完整/部分/未完成结果，不凭空判定所有人死亡。
6. 结尾后重开可比较另一方法。途中重开也需要二次确认，避免误触抹掉进度。

**当前 Village 已重做第三人称 3C**：全屏透视、WASD 镜头相对移动、Shift 快走、按住右键环绕、滚轮调距离、Home 复位。默认只有紧凑任务与附近交互提示，不再常驻大面板。人物有实体碰撞/重力，动画按实际位移响应；镜头碰障即时收近、退远缓动，近身隐藏自己的网格。E 要求距离、朝向与可达视线，不能隔墙打开芬恩面板。

旧 `Moonlight_Rescue` / `Moonlight_Workshop` 仍为观察实验入口，不因 Village 改动而改变操作。第三人称安装菜单 `Town/Moonlight/Upgrade Village Third Person Controls` 只操作 Village 副本，拒绝重复安装；未来首次生成 Village 时自动安装。详见[日志 021](../../开发日志/2026-11-08_021_第三人称3C重做.md)。

## 3. 哪些代码真正控制结果

| 层 | 新增/调整 | 职责 |
| --- | --- | --- |
| Core | `MoonRescueChapter` | 准备/护送/收束，三灯逐个到达、芬恩实际完成、结果与故事事件；无网络、无 Unity 依赖 |
| Core 执行接缝 | `MoonWorkshop`、`MoonCandidate`、`MoonReplay` | 继续使用已有归属/版本/引用/同意/资源校验、确认与实际采样；不由文本直接改世界 |
| Unity 世界映射 | `MoonWorkshopGame.worldOrigin`、`RoutePosition` | Core 保持局部米制坐标，Unity 映射到现成场景实际世界坐标与坡面；旧技术场景 origin=0 不变 |
| Unity 护送 | `MoonRescueGame` | 三个实际 NavMeshAgent、供光/遮挡、逐路点到达后回报 Core；三灯不是三个 LLM |
| 人物动作 | `MoonActorAnimation` | 有效 Humanoid Avatar，PlayableGraph 待机/行走混合；NPC 按导航速度、玩家按实际位移响应，关闭 Root Motion 对规则的影响 |
| 玩家 | `MoonPlayerController` | CharacterController 碰撞、重力、加减速、转向、卡帧有界分段、失焦停走、新局复位；不接管芬恩导航 |
| 近场交互 | `MoonPlayerInteraction`、`MoonInteractionPoint` | 距离/朝向/视线筛选；芬恩/工作站讨论与光源切换，面板阻止误操作 |
| 界面 | `MoonRescueHud`、`MoonRuntimeTheme.tss` | 已购纸页/标题/按钮图用于交互面板；Village 默认收起，阅读保护暂停状态，保留阶段/补救/双确认 |
| 镜头 | `MoonThirdPersonCamera` | Village 全屏透视跟随、环绕/缩放/碰撞/近身网格处理；`MoonSceneCamera` 仅保留旧观察入口 |
| 组装 | `MoonRescueSceneBuilder`、`MoonVillageSceneBuilder`、`MoonThreeCSetup` | 在独立副本复用人物/整组工作站/完整场景；第三人称有显式升级入口，保原场景和旧测试入口 |
| 素材工具 | `index_unity_packages.py`、`select_unity_assets.py` | 全包目录、依赖闭包、场景显式授权开关、已存在 GUID 复用、防止覆盖已转换材质、排除厂商运行代码 |

**关键边界**：Core 连续采样仍会拒绝无光位移、超速/瞬移和越权候选；Unity 切光前先结清旧供光区间内已发生的姿态，再改变光状态并停 Agent。这是修采样时序，不是放宽移动/到达半径来掩盖错误。复杂动态障碍、全几何防作弊、联网同步不是已完成的能力。

## 4. 现成场景和材质怎样适配

- KINGDOM 室外场景及依赖批次：1,737 个新文件，237 个已存在资源复用；AFS 完整工作站批次：106 个新文件，34 个复用。加前置物件/UI 共 **1,900 个新文件**，不是 1,900 个独立可交互物件。
- 找到 KINGDOM 原包内的官方 `Click Me - Castle URP.unitypackage`，选取本次所需 151 材质、80 个 Shader/Graph/子图/include；导入前按 GUID/路径核对并备份已有文件。没有把官方整包项目设置、场景或 C# 覆盖进工程。
- 部分叶片/树干图需要在子图就绪后重新导入，保留原风动/混合材质，而不是全部变成白色 Lit。两份缺失水效果仅做透明 Lit 兼容，旧内置粒子在副本停用；**水波/瀑布泡沫的原有效果未恢复，不报成完整视觉移植**。天空继续使用合法的 `Skybox/Cubemap`，不是所有非 UniversalPipeline 标签都应替换。
- AFS 前批 11 材质、整组工作站新增 17 材质分批适配 URP；外盘原包不修改。原始与导入后哈希分别登记。
- 原生地形局部烘焙独立 `VillageNavMesh.asset`；逐段检查两路线完整，不搬技术台平台盖住地面、不让角色凭台词跨不可达地形。

## 5. 验证证据与尚未完成

证据分别保存在 `.local/asset-final-pass-20261107/` 的导入/场景审计、`.NET` 输出、PlayMode 结果和截图中；汇总见[日志 020](../../开发日志/2026-11-08_020_现成场景与资源落局.md)。自动界面流程以 UI Toolkit 的 `NavigationSubmitEvent` 触发实际按钮，不直接跳过界面调用护送方法；它仍不等于真人鼠标/键盘手感验收。

3C 重做后的最新全量结果为 **115/115 Core、19/19 PlayMode**，新增三项针对移动/动画、实体与镜头碰撞、近场交互/面板/新局恢复的测试。运行时确认全屏透视 FOV 55、跟随距离 5.5 米且出生点无遮挡、玩家着地/有效人形/关闭根运动、默认面板关闭；近场打开后移动被阻止。完整结果与两张含 HUD 截图在 `.local/3c-rebuild-20261108/`，不把技术截图当人工画质验收。

已实现的是：现成资源整合、条件确认与执行、三灯目标、人物基本动作、阶段 HUD、可补救中断、按实际到达结尾。**尚未实现或尚未验收**：

- 任意输入的模型理解/协商、独立多角色自主、GM、新构型生成；当前只有两种显式人工候选，不能称六类 AI 全部成功。
- 附魔台里每件物品的独立点击/拿放/借还与资源转移；书和晶体仍有纯视觉用途。
- 新短局完整磁盘存档。旧技术切片的内存书签只覆盖单角色执行，不包含本章灯群/结尾；旧小镇存档不自动兼容新局。
- 音效/音乐/完整交接动作、脚接地/穿插、环境性能档位、各种分辨率/字体平台、人工逐项画质和新玩家乐趣。
- 商业资源的订单/EULA 与分发许可核实；本机演示和技术可用不等于获准公开打包发布。

下一步应围绕**现有工作站的一次真实试亮/归还操作，和一位角色的异步、有参数条件的小计划**扩展，不再先扩大地图和素材数量。新在线候选协议仍须单独批准；默认不读密钥、不发模型请求、不更改 `action=none` 与预算约束。
