## 1. 分层与入口

```text
Town.Unity（场景、NavMesh、3C、交互面板）    Town.Sandbox / NUnit
                       \                   /
                         TownRuntime
                         ├─ World / Knowledge：事实与分角色认知
                         ├─ Rules / Tasks / Social：传播、日程、搬运、维修、承诺与拜师
                         ├─ StoryRules：一次性剧情、书签、石板与最后一页
                         ├─ Brain / Memory：认知快照、对话校验、近期对话
                         ├─ Journal：有界审计日志
                         └─ TownCommand / TownSave：类型化命令、确定性重建与校验

Town.OpenAI → Town.Core：独立且显式的验证入口，不被 Town.Unity 引用
```

`Town.Core` 不依赖 UnityEngine，源码位于 `unity/Assets/Town.Core/`，由 .NET 工程链接复用。默认 `RuleDialogueClient`，不会打开工程就接网。`ILLMClient` 可注入测试替身，但不代表已完成游戏内模型与预算闸门的集成。

当前旧运行内容内部 `amu/ahe/xiaochuan`、`OathBell`、`bench_progress` 等兼容 ID 不变，仍显示布伦、梅芙、芬恩与拱门。v4 新角色与魔法不能只改名复用旧任务；必须定义内容迁移、能力/阶段/语义状态和新存档版本，现有 ID 与硬编码三居民不是长期扩展方案。

## 2. 一局的状态与命令

- `TownRuntime` 管局代际、逐分钟推进、玩家地点、对话等待与取消；大步快进也逐分钟跑规则，不跳过时刻。
- `WorldState.Commit` 记录世界版本；`KnowledgeStore.Learn` 保留来源、时间和被纠正的历史。两者仍有原型可变对象，尚不是编译期强隔离。
- `TownCommand` 是 Unity 玩家动作的统一入口：调查、拾取、出示、归还、传话、协助、承诺、道歉、守钟人与读页。规则裁决前置条件，不执行模型生成的任意命令。
- NPC 闲聊按日程相遇传播，玩家在同处可以偷听。同一原始来源不能因转述变成多个源头；墨钟封存 18:00 的读数和显化结果。
- 芬恩亲手还锤接管日程；维修耗时 60 游戏分钟；信任影响秘密与协助，传话和归还影响拜师。
- `StoryRules` 消费一次性剧情节点，独立保存剧情历史；只负责叙事与引导，不向 NPC 认知广播秘密。最后一页判词在落墨时封存，钟后的补说不改写作者判词。
- `Journal` 每局最多 256 条；每个居民近期对话最多 20 轮。剧情历史和存档重建记录不依赖审计队列，不能把审计日志当完整回放。

## 3. 导航、3C 与接近交互

`TownNavigation` 包装 NavMeshAgent，负责采样目标、完整路径检查、移动/到达/不可达/阻塞状态、暂停与复位。阻塞检测最多重算一次，持续阻塞停止并提示，不无限重试。玩家和居民共用它。

`PlayerClickMover` 支持点击寻路、镜头相对 WASD、Shift 加速与朝向；移动受 NavMesh 约束。点击面板不穿透到场景，鼠标停在面板上仍可 WASD。暂停、输入阻塞或对话等待时停走。

`TownCameraRig` 提供平滑跟随、右键环绕、俯仰/距离限制、滚轮缩放、Home 复位及碰撞收近。它是当前斜俯视玩法的可运行底座，不是完整角色动画/碰撞反馈系统。

地点依据玩家**实际坐标**进入 3 米范围后回报，不因点击目标直接到达。居民交互另外要求 Core 同地点、居民不在路上、表现距离不超过 5 米。`E` 提供默认交互，具体话题仍在面板中选择。

**重要边界：** Core 日程/搬运按游戏时间抵达，NavMesh 是表现适配，并非所有任务都由物理到达回调驱动。当前用物理距离挡住隔空交互；若正式地图变大、路被阻断或动态改动，必须继续做行程耗时校准与任务到达/失败闭环，不能声称已解决动态障碍下的全部行为兑现。

## 4. 单章本地存档

### 保存的内容

`TownSave` 保存版本、类型化操作序列、已经获得的对话结果、核心状态指纹、玩家及三位居民的表现坐标/朝向。采用确定性重建，而不是把可变世界对象直接反序列化后拼装：

1. `CreateSave` 拒绝对话等待中的半回合，以及用旧委托式开发命令产生的不可追踪操作。
2. 保存前试重建并比对状态指纹，发现直接绕过 Runtime 的开发改动则拒绝保存。
3. `TownSaveCodec` 检查版本、命令、地点、居民、坐标、对话及配额；SHA-256 检测文件损坏。
4. `TownSaveStore` 同目录临时文件、刷盘、原子替换；保留上一份 `.bak`。主文件坏了尝试备份，两份都坏则拒绝。
5. 读档先重建并验证 Core、检查角色和 NavMesh 坐标，再替换本局；局代际递增、恢复后暂停，避免玩家还没看清就错过时间。

**读档永远使用录制结果重放，不接收外部模型客户端；恢复后的新对话默认离线。** 不重复付费、不把旧请求写回新局，也不保存密钥或预算文件。

### 限制

- `Schema=1`、规则版本 `unfinished-town-v3.1`；未知版本明确拒绝，暂无迁移。
- 单章累计推进最多 1440 游戏分钟、最多 20000 步、编码文件最多 2 MiB；不是无限长开放世界存档。保存会完整试重建，后续长篇需评估耗时与快照分段。
- 单槽、本机明文；无加密、防作弊、云同步、自动存档、多槽或结局图鉴。SHA 不是身份签名。
- 状态指纹覆盖世界、认知、传播、关系、任务、近期对话和剧情；并非通用所有对象序列化或恶意篡改防护。
- Unity 坐标预检能拒绝当前不可达存档；极端场景对象在定位过程中失效的表现层回滚尚需加强。

## 5. 模型边界与研究接口

11/06 用户进一步明确 AI 原生目标：模型要参与方法裁定、社会决定与自主计划，不只是解析到旧命令。11/07 已有独立离线候选/角色条件/确认/执行接缝，11/08 已接短局；**候选仍是人工样本，不是已完成的模型语义接口**，不能直接复用现有 `action=none` 执行。引擎保留硬规则与执行权；新增完整语义状态需要新的存档协议和回执，旧确定性存档不自动覆盖它们。

## 7. URP 渲染底座

- Unity `6000.3.23f1`，URP `17.3.0`。Graphics 默认与全部 6 个质量档绑定 `Assets/Settings/Rendering/Town_URP.asset`，使用同目录 `Town_URP_Renderer.asset`。目前同一 Forward 配置：HDR、4× MSAA、渲染比例 1、主光阴影 2048、阴影距离 60、SRP Batcher；未做高低设备分档性能调优。
- `UrpProjectSetup.Configure` 是显式菜单 `Town/Rendering/Configure URP`，不会开工程自动重写设置；复用已有管线资产，不重建场景/NavMesh。URP Global Settings 与默认 Volume Profile 由 Unity 配套生成并保留。
- `Town/Rendering/Upgrade Built-in Materials` 使用官方升级器转换 Standard/Autodesk，另处理 `2Side` 的双面与 `roughness → 1-roughness` 通道打包。兼容的 Shader Graph、TriForge 混合/植被 Shader 保留，不统一强换 Lit。以后导入新素材仍须单独审计与备份，不在后台自动转换。
- `GrayboxSceneBuilder` / `LocalAssetReview` 新材质使用 URP。`EditorCameraCapture` 使用 `SingleCameraRequest`，保存前后恢复相机/RenderTexture 状态并释放临时资源；`SceneSnapshot` 与素材预览共用它。
- 11/07 的 336 主材质是当时迁移分母，保留历史。11/08 新资源另行适配，原生玩法副本 201 种实际引用材质审计无错误/不支持，不能拿旧分母冒充全新资源验收。官方 KINGDOM URP 图保留；两水效果降级、旧粒子停用，人工视觉/性能/发布未验。商业资源在被忽略的 `LocalThirdParty/`，许可不因技术检查改变。
- Unity 序列化空字符串默认包含冒号后的空格，`.gitattributes` 仅对 `.asset` / `.mat` 放宽行尾空格检查，不改写编辑器资源格式；手写代码、JSON、Markdown 仍按默认检查。

## 8. 新月光工坊：独立离线执行接缝

`Town.Core.Moonlight` 不修改旧 `TownRuntime`：`MoonRequest` 固定离线角色观察，`MoonCandidate` 只提出澄清/拒绝/方法与条件，`MoonWorkshop` 检查归属、版本、引用、有限能力、同意和能源，玩家确认后进入执行；`MoonWorkshopGame` 用 NavMesh/光路射线和连续姿态反馈，只有实际经过路点才产生完成回执。

`MoonReplay` 独立版本 `moonlight-slice-1`，记录合法命令、候选及引擎采样；最多 10000 指令、2 MiB，回放不访问候选来源、不联网。Unity 书签目前只在内存中保存，恢复后暂停；场景遮挡重新检测。它不是旧 `TownSave` 的新磁盘槽，也不自动迁移旧存档。

本切片采用**显式人工候选**，不把玩家文本映射成旧按钮后冒充理解，更不声称已有真实开放协商。两种固定方法仅验证执行下游；多方约定、参数化小计划、模型异步接入、N3/N5/N6 都未完成。详见[切片说明](moonlight/月光工坊首个执行切片.md)；在线 `action=none`、信息与预算规范未改变。

## 9. 现成场景里的短局与执行适配

- `MoonRescueChapter` 是独立 Core：准备/护送/收束、三灯唯一到达记录、芬恩完成和实际结果。`MoonRescueGame` 接三个真实 Agent，逐个经过中点/终点才回报；一个角色到达不能代替灯群获救。
- `MoonWorkshopGame.worldOrigin` / `RoutePosition` 将局部米制坐标映射至现成场景并采样坡面。`MoonVillageSceneBuilder` 复制 KINGDOM 完整室外场景，保原布局，烘焙独立局部 `VillageNavMesh.asset`，不复制技术台地面覆盖原地形。
- 切光/放屏前 `FlushObservedPose` 结清上一段合法供光区间的真实位移，再切状态并停 Agent，避免把已发生的合法动作追溯判为无光移动。Core 的速度、无光位移和到达条件不放宽。
- `MoonActorAnimation` 用 Humanoid 与 PlayableGraph 混待机/行走，Root Motion 关闭；`MoonRescueHud` 用已购 PNG 和 UI Toolkit 展示阶段/条件/补救/结尾，途中收束与重开双确认。旧观察入口保留；Village 的新第三人称见下一节。
- 新场景复用完整 AFS 工作站，但书、晶体、器皿目前不全是交互对象。梅芙/瑟恩仅待机视觉，非三 AI。当前新短局没有完整磁盘存档，旧 `MoonReplay` 不含灯群/章节结果。
- 导入工具默认不导源场景，显式 `--allow-scenes` 才纳入；`--reuse` 保已有 GUID 对应的已转换资源，未知冲突拒绝。厂商运行脚本/插件不进入执行链。完整源码包、转换贴图和商业玩法副本不随 Git 分发。

详见[局内接入](moonlight/月光驿站局内接入.md)及[资源利用清单](../资源利用清单.md)。

## 10. Village 第三人称 3C

- `MoonPlayerController` 使用 CharacterController，WASD 相机相对方向、加减速/转向/重力；卡帧采用有界小步，不整帧丢输入。玩家不接管芬恩任务，实际水平位移驱动 `MoonActorAnimation`，顶墙不按输入虚跑。当前仅待机/行走与有限快走，不冒充跑步/脚部 IK。
- `MoonThirdPersonCamera` 全屏透视 FOV 55、跟随目标高度 1.25 米、环绕/缩放/俯仰限制；SphereCast 碰障即时收近、离障缓动退远，近身隐藏自身渲染。右键捕获光标，松开/失焦/面板/停用归还原光标状态。角色视觉层 28 不参与镜头/视线遮挡，实体仍与环境碰撞。
- `MoonPlayerInteraction` / `MoonInteractionPoint` 按距离、朝向和视线筛选对象。目标自己的工作站碰撞允许命中，不误当隔墙；其他墙体仍挡交互。当前只接芬恩/工作站讨论与光源切换，不声明所有场景道具可用。
- `MoonRescueHud.immersive` 仅 Village 开启：默认紧凑目标和 E 提示，交谈时展开已购皮肤面板，保护护送暂停及玩家输入，关闭恢复原暂停状态。新局直接清面板状态，不把旧局暂停带入新局。
- `MoonThreeCSetup` 有显式升级菜单，保存前拒绝脏的目标场景/重复安装；`MoonVillageSceneBuilder` 首次生成时复用安装流程。仅改本地玩法副本，不覆商业原场景、旧小镇或两个观察切片。

首轮相机恢复测试暴露出生点紧靠真实灯柱；通过场景采样更换出生点，不忽略障碍或放宽测试距离。最终 19/19 PlayMode；详见[日志 021](../开发日志/2026-11-08_021_第三人称3C重做.md)。常规碰撞测试不证明任意初始嵌墙、复杂阶梯、低帧性能、各设备/手柄或真人手感全部合格。
