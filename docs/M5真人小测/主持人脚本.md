# 主持人脚本（仅主持人可见）

目标：观察第一次接触者在 5 分钟内如何理解、行动、等待和恢复。**我们测试游戏，不测试参与者；完成归巢不是本次真人小测的新通过门槛。**

招募 1–2 人，每人独立一局，避免旁观前一位。招募时只说“一个奇幻小镇原型的短时可用性观察”，不讲 P、取舍、确认、卫兵路线或结局。不要求参与者事先阅读资料；若已接触过本项目，在记录中标注，不能当作首次发现样本。

## 0｜主持人开场前检查（不要念给参与者）

- 使用 [README](README.md) 指定且已验证的新包，默认离线，开场页等待；不能提前打开计划面板、生成草稿或执行自动化脚本。
- 一份空白[观察记录表](观察记录表.md)、秒表、匿名编号准备好；机型 / 分辨率 / 包标识先记好。
- 首次启动耗时另计：从启动应用到开场“启程”可操作；注明是否本机首次 / 冷热状态未知。先前做过技术验证，因此本轮真人启动不冒称该设备首次冷启动。
- 不向参与者展示观察指标、自动化步骤或本页未标“朗读”的部分。不把开发人员已知的模型、路线和快捷键先教一遍。

## 1｜说明与同意（朗读；不计入 5 分钟）

> 谢谢你帮我们试一个还在开发中的奇幻小镇游戏。我们想知道游戏本身哪里清楚、哪里让人困惑，不是在考你，做不到或失败都对我们有帮助。
>
> 这次游戏部分是 5 分钟，之后我会问几个问题。你可以随时暂停、跳过问题或结束，不需要解释原因。我们会用匿名编号记操作和感受，不记你的姓名；请不要在游戏里输入真实姓名、联系方式或其他私人信息。这次使用本机离线版本，不向真实模型发送你的输入。
>
> 我们希望记文字观察笔记，你是否同意？截图、录屏、录音分别需要你另外同意；不同意录制也可以继续。资料只用于本项目体验改进，由【保管人】保管，仅【访问人员】可看，计划在【删除日期】删除。如果你希望撤回记录，请通过【联系渠道】告诉我们你的匿名编号。

逐项询问并填写同意栏；方括号项目必须提前由组织者填写。未约定保管人、访问范围和删除日期时不录音 / 录屏；未经同意不调用云转写或上传原始资料。是否参与与是否录制分开确认。不同意任何记录则结束观察，不留下可识别资料。

## 2｜5 分钟任务（仅朗读这段）

> 你来到龙眠镇，希望把小雏龙小烬安全送回母亲身边。请按自己的理解尝试推进这件事，做你愿意做的选择。你有 5 分钟，不要求一定完成。
>
> 如果愿意，可以说出你现在想做什么、预期会发生什么；也可以安静玩。游戏里怎么做请先自己探索，我暂时不会教操作。你认为任务结束后也可以继续查看结果。准备好了我们就开始。

读完且开场可交互后，口述“现在开始”，秒表记 `t=00:00`，由参与者自己决定是否点击“启程”。**不可在任务里追加“按 P”“先规划”“失败后重确认”“看回执”或任何最优路线。**

## 3｜00:00–05:00：不提示规则

主持人不主动解释控件或纠正想法，不代点、不指屏幕、不用表情暗示成功；观察者不在参与者视野里展示观察表。计时不因迷路、游戏等待、失败或理解错误暂停。

| 情况 | 可用中性话术 | 不可说 / 不可做 |
| --- | --- | --- |
| “我要按哪里 / 下一步做什么？” | “请先按你的理解试试；我们想知道游戏现在告诉了你什么。” | “看看右下角 / 按 P / 先确认一下。” |
| “我做对了吗？” | “这里没有考你的正确答案，你可以按自己的判断继续。” | “对了 / 快了 / 这样就能过。” |
| 主动说不懂、卡住 | “我记下了。你可以继续探索，也可以决定停在这里。” | 给解法、换一条路、替他生成计划或主动提示重开 |
| 自发描述预期或感受 | “谢谢，我记下了。” | 解释其错误、反问“所以你知道草稿没执行吧？” |
| 长时间沉默或无动作 | 保持观察；记录停顿及画面 | 用“还有 X 分钟”催操作、定时救援或认定其已失败 |
| 到 5 分钟 | “5 分钟到了，请先停在这里。谢谢，我们接下来聊聊刚才的体验。” | 为追到结局续时、修改起点、重抽种子 |

可应参与者请求重读**原任务全文**，不得补充机制。每次任何中性发言也记时间与原话，便于区分自主行为和主持影响。若参与者完全未发现 P，这就是有效发现，不在 5 分钟内补教。

## 4｜何时可以介入

只在下列情形介入，不以“等了多久 / 进度太慢”为救援条件：

1. **自愿停止 / 不适**：参与者要求暂停、撤回或出现不适，立即停计时与录制，优先照顾人；不催其完成。
2. **隐私或安全**：开始输入可识别个人信息、意外露出私人窗口或存在安全风险时，停止录制并提醒不要输入隐私；按同意约定处理片段，不复制私人内容到记录表。
3. **明确的系统 / 设备故障**：崩溃、系统弹窗、键鼠断开等。仅处理桌面焦点 / 设备层问题，不改变游戏状态、不传送 / 注入资源 / 解释游戏逻辑；记录介入前时间、症状、操作和中断时长。不确定是游戏等待还是故障时先记录“不确定”，不能擅自关掉请求刷结果。

技术中断可暂停秒表，但标出墙钟总时长及实际游玩时长。无法保留状态则终止该局为“技术中断，未完成观察”；任何重启另立 `R1` 补充局，不能覆盖原局或当作首次体验。机制讲解若发生，记录准确时间 / 内容，后续相关行为标“有帮助”，不能计为自主发现。

## 5｜停表、访谈与收尾

1. 记 `05:00`（或提前停止时刻）的实际画面、任务状态和参与者判断；冻结时间线及五项清单的“未遇到”，不为填满清单制造抓捕、失败或跨夜。
2. 按[赛后访谈](赛后访谈.md)提问。计划 / 失败没有自然出现时使用其中“不适用”的问法，不能先演示再追记“已经理解”。
3. 在同意范围内保存匿名原话与必要证据，检查没有姓名 / 通知 / 账号等；结束录制，告知可撤回渠道。游戏本机轨迹可能含自由输入，按原始私密资料管理，不提交 Git。
4. 访谈之后如用户另行安排辅助演示，可展示未遇到的情形；单独记任务、提示、时间和结果，不计入本次 5 分钟自主短局，也不倒填原五项为“通过”。
5. 不向下一位透露前一位的路线、失误或结果。每位重启到普通开场；不删除历史存档 / 回放。
