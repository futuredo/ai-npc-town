# AI 框架 SDK 抽离建议（仅设计）

日期：2026-11-09。本轮只完成行为不变重构和拆分建议，**没有创建或发布 SDK**。

## 1. 要复用的到底是什么

可复用的是一条有证据、有限权限的 AI 互动闭环：

```text
宿主裁剪合法感知 → 冻结输入 → 模型/离线/录制提供方 → 结构与引用校验
→ 玩家确认（需要时）→ 宿主规则裁决 → 原子提交 → 回执 → 失败/重规划/回放
```

SDK 不应要求其它项目接受龙、居民、四日时钟或本项目库存结构；也不是把 `DsWorld` 改名为 `UniversalWorld`。宿主必须仍拥有世界真值、合法能力、玩法规则及最终写权限。

六机制共享请求生命周期，但不强行共享世界模型：认知/传话的可见性与关系归宿主；GM 的事件白名单归宿主；自由行动的裁决归宿主；居民自主行为的感知和能力归宿主；造物的材料/能力验证及确认归宿主。SDK 提供共同安全边界、流程与可观察证据，不替宿主判定“哪种魔法合理”。

## 2. 建议模块与依赖方向

以下为候选职责，不是本轮已存在的包名或稳定 API。

| 模块 | 应拥有 | 不应拥有 |
| --- | --- | --- |
| `AI.Contracts` | 请求身份、会话代际、协议版本、冻结感知包、引用集合、提供方输入/输出、失败分类、回执契约 | Unity 类型、世界对象、人物 ID、API 密钥、本项目中文提示 |
| `AI.Runtime` | 有界请求生命周期、取消/超时、过期检查、确认令牌、已提交去重、调用宿主校验/提交的编排 | 自行修改世界、自动接受模型新能力、隐式无限重试 |
| `AI.Providers.OpenAI` | HTTP 适配、响应解析、注入的模型与预算策略、可测试传输边界 | 自行读项目根目录密钥、默认收费、兜底切换高价模型、龙眠镇规则 |
| `AI.Evaluation` | 轨迹协议、提示/输入指纹、录制提供方、严格回放与对照统计工具 | 默认外发完整世界快照、混淆严格回放与仅执行回放 |
| `AI.Unity` | 生命周期与主线程桥接、取消销毁对象的请求、可选调试呈现 | 依赖龙眠镇场景/商业 UI 资产、替代宿主物理/导航到达判断 |
| `Host.Dragonsleep` | 现行世界/规则/内容、合法视角构造、提示/Schema、离线规划器、行动与造物能力、结局与 Unity 表现 | 将本项目语义写回通用核心 |

依赖方向：Contracts 不依赖宿主；Runtime / 提供方 / Evaluation 各依赖 Contracts，不彼此形成环；Unity 桥接依赖 Contracts / Runtime；宿主在组合入口注入这些实现。先从现有 .NET 离线入口验证，不先发布一堆相互依赖的空包。

从现有代码借鉴但不要直接整类搬走：

- `IAiProvider`、`AiTrace`、`DsExecutionReceipt` 有可提取的契约，但当前携带 `AiTaskKind`、龙眠镇快照/计划等语义，须先隔离。
- `DsExecutor` 的候选隔离、状态哈希复核和提交回执可提取为编排能力；真正前置、掷骰含义与后果留宿主。
- `DsPlanRun` 可抽出确认/步骤/作废/失败生命周期；`act/wait` 的词表、截止规则、归巢目标和 `BaselinePlanner` 不是 SDK 通用策略。
- `DsReplay` 的版本/提示指纹检查值得保留；世界快照序列化器由宿主提供，不能让通用回放器理解 `DsWorld`。
- 现行在线提供方和 `OpenAiPolicy` 借用旧 `Brain.TokenUsage`，先分离中性用量契约；不得因此把整套旧认知系统带入 SDK。

## 3. 必须明确的宿主接口责任

不用一个万能 `IWorld` 暴露整个真值。先按真实调用点定义最小职责，再由第二个宿主检验：

1. **感知构造**：宿主按当前角色/任务构造允许发送的冻结包，包含可引用 ID；冻结后不持有世界引用。SDK 不能验证所有游戏知识语义，必须有宿主隐私负例。
2. **结构/能力/引用校验**：提供方数据是不可信输入；由任务契约与宿主能力白名单共同验证，叙述文本不授予能力。
3. **试运行与提交**：宿主返回隔离候选及提交凭据；凭据绑定会话、请求、已校验提案、预期状态版本/摘要。真正提交必须原子检查，世界已变则拒绝，不只依赖 UI 按钮禁用。
4. **确认**：确认绑定具体候选和版本；新局、读档、改稿、世界变化后不能复用旧确认。造物/多步计划与普通对话的策略分别声明。
5. **回执**：记录实际执行、失败码、合法展示文本、前后状态证据；模型声称“做完”不能替代宿主回执。完整真值证据留本地，公开日志另裁剪。
6. **推进与重规划**：宿主控制时间、导航、物理到达、居民轮次和结束条件；SDK 不自行循环直到模型满意。重规划仅接收当前合法感知和可显示失败，不接收试运行的异地真值。

这些是提取前应验证的契约要求，不声称当前游戏已经实现所有跨宿主保障。

## 4. 版本与兼容性

至少区分：SDK API/包版本、宿主规则版本、模型输入输出协议版本、录制格式版本；内容数据另带版本/指纹。不得用一个 `rules-6` 同时代表全部。

严格回放固定提供方原始输出、提示字节指纹、宿主规则/内容版本、初始状态和随机源状态。SDK 升级只要投影/排序/空值变化，也可能破坏严格回放；必须有样本证据，不能自动升级或重录覆盖旧证据。仅执行回放不验证旧提示时，应明确标注不同模式。

现行 `DsPlan` 类型化不是公开 SDK 二进制兼容承诺；公开 API 冻结应晚于第二个宿主验证。

## 5. 建议实施顺序与退出条件

1. **写契约和兼容测试，不搬目录**：以现行黄金、严格回放、过期/重复提交/确认失效/取消/坏引用负例固定边界；为未覆盖任务补字节与隐私样本。
2. **提最小纯 C# 闭环**：先让离线提供方、一个任务、宿主裁决与回执脱离 Unity 跑通；保持龙眠镇适配层和旧入口可验证，不并行维护两套规则真源。
3. **第二个规则明显不同的宿主**：建议独立的非奇幻维修/调度小案例，使用不同动作、资源、时间及失败规则，不复用龙眠镇 ID/四日结局。两宿主不修改通用核心就能各自完成确认、提交、失败适配和回放，才证明有复用价值；复制一份龙眠镇不算。
4. **再决定 Unity 包和提供方包的发布**：Unity 适配单独验证对象销毁/主线程/Domain Reload；打包只含自有代码及许可允许的依赖，不含商业素材、本地数据、密钥或预算账本。

每步有独立回归和回退入口；若第二宿主必须不断给核心加人物/物品/剧情特例，停止扩 API，重新划分宿主责任，而不是堆兼容开关。

默认所有样例和测试离线，联网能力显式注入且需宿主授权。预算、模型、最大输入输出、并发和重试都由宿主策略决定，不能继承本项目研究授权为 SDK 默认权限。本建议不授权真实模型实验、依赖安装或包发布。
